[T1.9] The gate result is a **commit status**, not a check run: `GitHubPublisher.post_status` is the only call of the statuses API (state allow-list `pending|success|failure|error`, description cut to 140 characters, context `pruefstand/gate` unless given) and `set_check` is a thin wrapper that maps `(status, no_baseline, infra_error)` through the interfaces §10 table. For `no_baseline` the caller passes the `eval_fingerprint` as `summary` (description `no baseline for <fp>; run baseline-promote`). `GitHubPublisher` only talks to an `https://` API, validates `repo` (`owner/name`), `sha` (hex) and the token (printable ASCII, no white space), never follows redirects, retries 5xx and transport errors 3 times, raises `PublishError` (a `PruefstandError` holding endpoint and status code only, never a response body or the token) and hides the token from `repr`.
