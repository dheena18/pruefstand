[T7.1c, follow-up of T7.1a S4 after D1288; found in the review of #251] `apply.py` creates its worktree at `index.base_sha` and applies every patch there. The N01 patch regenerated for D1288 applies only to the current tree, not at the old `base_sha` (8186931).

**Fix.**
- `base_sha` moves to #251's merge commit (`aac3edf`), in `index.yaml` and the generated README. Every patch is regenerated where needed and checked to apply there.
- `benchmarks/tests/test_base_sha.py` checks out `base_sha` in a temporary worktree and runs `git apply --check` on every patch, so CI catches this class of break.
- **CI gap:** the CI `test` job's checkout is shallow, so it lacks `base_sha` and the test skips there. A fetch of `base_sha` in that job (owner path `.github/**`) makes the check run in CI too. Until then it runs on every full clone (VM, local).

**Where `base_sha` is pinned:** `benchmarks/mutations/index.yaml` and the generated `benchmarks/mutations/README.md`. Elsewhere it is only named:
- `apply.py` reads it;
- `prompts/T7.1a`, `T7.1b` and `T7.2` refer to "the `base_sha`" in prose;
- N04's patch carries a recorded `git_sha` inside its cassette data, which is part of the recording, not a pin.
