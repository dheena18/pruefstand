[T6.3 S4 offline, before the weekly runs] How `experiments/noise/cause_switches.py` runs and checks the five tier-2 cause-switch scenarios.

**Scenario configs.** `experiments/noise/configs/scenario_<name>.yaml` are generated from `pruefstand.yaml` by `--write-configs`, and a test keeps them equal. Each one:
- keeps everything else, including `hard_fail` and `min_clusters: 30`;
- narrows `gate.metrics` to the target metric's own rule;
- narrows `gated_slices` to `[overall]` (m = 1).

**Runs.** Both runs of a scenario are fresh `pruefstand run --tier nightly` runs, because they belong to the weekly `nightly.yml` job.
- The four deterministic scenarios use `--split core` with `PRUEFSTAND_JUDGE_MODE=skipped`.
- `refusal_policy` uses `--split full --stratum refusal` with the judge, without `--block`, and never with a stored baseline (AI12-10, P4.3).

**MDE pre-check.** The scenario MDE is `minimum_detectable_effect(se, alpha, delta, m=1)`.
- Before the switch run exists, `se` is taken from the baseline alone: the size-weighted spread of its cluster means (as in D1275) times sqrt(2), over sqrt(k). This is the paired difference of two runs with uncorrelated cluster errors, an upper bound when the two runs share every case.
- The planned drops are planning values, set before any run: `context_recall` 0.10, `citation_recall` 0.20, `language_match` 0.50, `refusal_correct` 0.30. The run slice records the measured drops next to them and replaces a planned value only through a superseding decision.
- `errors` is an absolute check and has no MDE.

**Check.** A scenario passes when all of these hold:
- the production gate (`MetricRegistry.full()` directions, seed from the config) names the expected `likely_cause`;
- the switch run has no `infra_error`;
- the switch run is complete, except for `errors`, whose `error_rate` absolute check must not pass.
