[T3.1a] `deploy-cluster-bin.sh` talks to the cluster with plain ssh, so it runs as the service user; the owner runs `make gpu-deploy-bin`, which copies `infra/gpu` and `infra/cluster` to a world-readable temp dir and runs `sudo -u pruefstand <tmp>/gpu/deploy-cluster-bin.sh`. A user other than `pruefstand` (or `--bin-dev`) writes `pruefstand-bin-dev/`. No `put` op was added to the wrapper: that would let the owner run arbitrary scripts with the cluster key. Confused-deputy guard (review M3): `make gpu-deploy-bin` and `make gpu-install-wrapper` run a `git archive origin/main` export, and the scripts themselves refuse a tree that differs from `origin/main` (`lib/git_verify.sh`); the installer never overwrites a file it did not create without `--replace` (diff first). `health.sh` exit 14 uses `status.sh` (`bin-integrity`, `bin-sums`) compared with `deploy-cluster-bin.sh --print-sums`, again without a new op.
