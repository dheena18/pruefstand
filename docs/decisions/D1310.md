[T8.4 slice 4, Opus review of #241] The Try-it e2e (`scripts/demo/try_e2e.sh`) runs in its own compose project `pruefstand-demo-e2e` (own qdrant, llm, embed, index, volumes), not in the production project `pruefstand-demo`: its EXIT-trap `down --remove-orphans -v` can then never stop the public demo or delete its `qdrant_data` index; `E2E_PROJECT=pruefstand-demo` is refused. Because two projects cannot create overlapping networks, `demo-net` takes its subnet from `DEMO_NET_SUBNET` (default `10.232.0.0/24`, the production value); the script exports `10.234.0.0/24` (refuses `10.232.0.0/24`), checked free against the repo's subnets (10.231 proxy-egress, 10.232 demo-net, 10.233 demo-egress; gate-net has none fixed) and the VM's routes. The in-container reset uses `python -c` (urllib) because the rag-demo image has no `curl`. The e2e stack is 4 vCPU / 7 GB on its own, so it is not run next to the public demo unless the VM budget allows (D1309). ui-spec §14.2 updated. **Follow-up for the T0.7 firewall task:** `infra/vm/pruefstand-firewall.sh` drops and route-checks only 10.232.0.0/24 and 10.233.0.0/24; the e2e `demo-net` 10.234.0.0/24 (internal, so no egress rule is needed) should also be in its route-clash check (no T0.7a row exists in `tasks/TASKS.md` yet, so this decision is the record).
