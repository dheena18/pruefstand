[T6.2a S4b, issue #164] `llm-proxy` reserve slots (`GET /health` beyond the cap) are served only to trusted peers, default loopback (`127.0.0.1`, `::1`: the container healthcheck and `docker exec` by the orchestrator); an untrusted peer at the cap is closed unread. Each untrusted peer address may hold at most 16 of the 32 connections (`per_peer_connections`), so one client on `gate-net` cannot take every slot. The #164 repro (40 reconnecting tricklers, cap 4) is a test: the trusted `/health` must answer at least 14 of 15 tries (before: about 5 %). Availability only; a run still cannot pass through it Constraint: the orchestrator reads `/health` with `docker exec` inside the container (loopback) or from a configured trusted address; a host-originated request arrives from the `gate-net` gateway address and is untrusted. A failed thread start releases the slot and the peer count (test); refused connections never leak a peer count (test).
