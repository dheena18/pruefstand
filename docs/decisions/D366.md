[T1.8, scope notes] (a) Target-cache entries are JSON `{mode, latency_ms, response}`; an entry of the other mode is a miss, errors are never cached, a failing cache write only logs. (b) Retrieve-mode records compute `context_recall`, `ndcg_at_k`, `tenant_leak` and the record metrics; every other answer metric is `not_applicable` (reason `retrieve_mode` or `not_in_judged_subset`). After a `/v1/retrieve` 404 fallback the case is scored as an answer case. (c) Judged values without a call carry `details.reason`: `category`, `not_in_judged_subset`, `retrieve_mode`, `no_judges`, `hard_fail`, `judge_quota`, `judge_cap`; only the last two count in `judge_skipped`. (d) `counts`: `ok` / `error` / `cached` / `retrieve` / `retrieve_fallback` count cases; `not_applicable` counts metric values; new `metric_truncated` (deterministic) next to `judge_truncated` counts values whose `details.truncated` is true (also logged). (e) Deterministic metrics run synchronously on the event loop, one case at a time, so their shared wall-clock regex budget is not eaten by concurrency. (f) `judged_cases` counts cases where a judge call was made (success or `LLMError`); `judge_degraded` = `judge_error / judged_cases > 0.05`
