[T6.1, security] Reading a baseline hashes and parses the same in-memory bytes (no re-open by name after hashing): `read_bounded` (regular file, no symlink, size cap), `manifest.json` SHA-256 (and, for the git store, the SHA-256 pinned in `index.json`), then the zstd frame is inflated with a hard cap (decompression bomb), `run.json` `artifact_sha256` is checked, and only then the JSONL is parsed. `results.parquet` is hashed but never parsed. Fingerprints, refs and run ids come from data and must match `[A-Za-z0-9][A-Za-z0-9_-]{0,63}` (refs: the seven fixed names); `<root>/<fp>`, `<ref>`, `history` and `history/<run_id>` must be real directories (symlinks refused). `_run_files.read_results` now shares `parse_results` / `require_hashes` with the baseline reader (messages unchanged)
