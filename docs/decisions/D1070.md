[T6.2a S4b, review of #137, CRITICAL fix] `llm-proxy` reads request bodies the way Ollama's Go decoder will: Go matches field names case-insensitively and the last duplicate wins, so `{"model": "<gen>", "MODEL": "<judge>"}` reached the judge, a later `"Options"` skipped the `num_ctx` rewrite and `"Keep_Alive"`/Kelvin-sign variants skipped the `keep_alive` strip. Now (`llm_proxy_json.py`): `object_pairs_hook` rejects any object, at any depth, with two keys equal after NFKC + Unicode casefold (exact duplicates included); `parse_constant` rejects NaN/Infinity; the top level may hold only exact ASCII keys per route (chat: `model`, `messages`, `stream`, `format`, `tools`, `think`, `options`, `keep_alive`; embed: `model`, `input`, `truncate`, `dimensions`, `options`, `keep_alive`), any other key → 403 "field not allowed"; `keep_alive` is then dropped and `options` rebuilt from exact keys; the forwarded body is ASCII-only JSON (`ensure_ascii`, `allow_nan=False`), so a lone surrogate is escaped, never an encode error
