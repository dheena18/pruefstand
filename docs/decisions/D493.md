[T3.4, dependencies, tokenizer] New rag-demo dependencies: `typer` (the `rag-demo` console script, MIT, already in the lock), `jsonschema` (moved from the optional `index` extra: the CLI validates every corpus line, MIT, already in the lock) and `tokenizers>=0.21` (Hugging Face, Apache-2.0, already in the lock via litellm; D241). `truncated_chunks` counts passages above `max_input_tokens` with the model's `tokenizer.json` (`index/tokens.py`; without a file a word-and-punctuation lower bound). The catalogue entry `ollama/bge-m3` now carries `tokenizer: {source: hf:BAAI/bge-m3/tokenizer.json, sha256: 21106b6d...dd08}` (the existing optional catalogue field, AI13-05); `python -m rag_demo.index.fetch_tokenizer` downloads it and verifies the digest; the Dockerfile bakes it into `/app/tokenizers/bge-m3.json` (`RAG_EMBED_TOKENIZER`), `make fetch-tokenizer` fetches it for the VM. `rag-demo index --encoder ollama` refuses to run without `RAG_EMBED_TOKENIZER` so the stored count is real.
