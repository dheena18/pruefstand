[T4.7a, review artefacts] All review files are in `<work_dir>/<name>-<version>/review/` (git-ignored): `sample.jsonl`, `items.jsonl` (one `ReviewItem` per reviewed case, appended as they arrive: the resume record), `spotcheck_sample.jsonl`, `spotcheck_decisions.jsonl`. Commands (`make review-model | review-spotcheck | review-app | review-summary | review-apply`, `BUILD=<dataset config>`, `mk/dataset.mk`) call `tools/review_app/cli.py`; `review-model` prints `reviewed=<n>` and the error rate per stratum, `review-summary` the rates, the owner's flag rates and the trust verdict. `apply` rewrites the dataset directory (stale split files removed), keeps `created_at` and validates the result. `apply` writes the new dataset beside the old one, validates it and swaps (a failure keeps the old one; `build_dataset`'s `validate` stage does the same); a second `apply` of the same review is refused. On a real directory (not `datasets/fixtures`) the SPEC quotas are problems, so rejects that push a count below a quota make `apply` fail: the intended flow on the real build is reject -> regenerate (`--only <prompt>`) -> rebuild -> review again -> apply (D752: re-selecting smoke belongs to that rebuild, T4.7b). The Streamlit app binds to 127.0.0.1 (on the VM: `ssh -L 8501:127.0.0.1:8501 <vm>`).
