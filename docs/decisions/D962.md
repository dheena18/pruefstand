[T5.2b, judge cut detection; owner check 2026-11-09] The judge input was checked after the call only with `prompt_eval_count >= num_ctx - num_predict`. Measured on the A40 server (Ollama 0.32.13, gemma3:12b, num_ctx 12288): a prompt over the window is cut silently and reported as a constant 6147 (num_ctx / 2 + 3), far below the window, so that check never fired. `judges.tokens.cut_signature` now gives the band `[num_ctx / 2, num_ctx / 2 + 16]`, and `Judge._check_not_cut` raises `JudgeInputTruncated` (candidate-side, worst-filled, counted `judge_truncated`) for a report in it, besides the old rule. Cost: a genuine prompt whose REPORTED count is 6144 to 6160 tokens is read as cut (17-token band; Ollama's prompt cache lowers the reported count by the cached prefix, which moves the band without widening it; a byte-identical cut prompt repeated may report a tiny count and be missed, but pruefstand's own LLM cache serves repeats with the original usage). The pre-call estimate (conservative, about 2.2x over the real count on German prose) stays the first guard; the exact Gemma tokenizer remains a follow-up and would make this check an exact comparison.
