[T6.2a S7, review of the post-run probe in #170, refines D1082] `gate_orchestrator.post_run.post_run_infra_error` maps the probe after the run as follows. Tunnel unit inactive → `tunnel_lost`; `health.sh` exit 11 and 12 → `ollama_down`; 13 and 15 → `model_reload`; 16 → `data_root_unavailable`. Exit 10 (free VRAM below the minimum, e.g. another cluster user) and 14 (cluster bin dir differs from the checkout) do **not** discard a finished run: WARN log, the run's result stands. Any other exit (1, 2, 64: the script itself failed) → kind `executor` (infra error, re-dispatch). Known limit: with the tunnel unit active, exit 11 is always `ollama_down` (the probe cannot tell a dead forward from a dead server). Every probe command runs with a subprocess timeout (`POST_RUN_TIMEOUT_S` = 120 s, `subprocess_runner`); a timeout raises `subprocess.TimeoutExpired`, which `run_with_retry` treats as an infra error of kind `executor` (D1080). `health.sh` exits with the first code of 16 11 12 14 13 15 10, so exit 14 can hide a model change: in the WARN-only branch (10, 14) a `resident:` digest-differs or `placement:` FAIL row still makes the run `model_reload`. `subprocess_runner` starts the probe in its own session (`start_new_session=True`) and on timeout kills that whole process group (`os.killpg`, never a pattern kill), so `ssh`, `curl` and `gpu_health.py` children of `health.sh` do not survive it. On timeout the group first gets SIGTERM (so `health.sh`'s `trap 'rm -rf $tmp' EXIT` runs), then after 2 s SIGKILL; every wait after the timeout is bounded (2 s grace, 5 s drain, then the pipe is closed), so a process that left the group and holds stdout cannot block the runner. Note: the `resident:` "differs from the catalogue" check in the WARN-only branch rarely matters, because `health.sh` reports 11 (not resident) before 14; it stays, and a test pins that a "not resident" row with exit 14 stays a warning while a digest row maps to `model_reload`.
