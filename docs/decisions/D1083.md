[T6.2a S7, review of the post-run probe in #170, refines D1082] `gate_orchestrator.post_run.post_run_infra_error` maps the probe after the run as follows. Tunnel unit inactive → `tunnel_lost`; `health.sh` exit 11 and 12 → `ollama_down`; 13 and 15 → `model_reload`; 16 → `data_root_unavailable`. Exit 10 (free VRAM below the minimum, e.g. another cluster user) and 14 (cluster bin dir differs from the checkout) do **not** discard a finished run: WARN log, the run's result stands. Any other exit (1, 2, 64: the script itself failed) → kind `executor` (infra error, re-dispatch). Known limit: with the tunnel unit active, exit 11 is always `ollama_down` (the probe cannot tell a dead forward from a dead server). Every probe command runs with a subprocess timeout (`POST_RUN_TIMEOUT_S` = 120 s, `subprocess_runner`); a timeout raises `subprocess.TimeoutExpired`, which `run_with_retry` treats as an infra error of kind `executor` (D1080).
