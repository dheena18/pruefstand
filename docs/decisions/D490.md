[T3.4, collection naming and alias] The default collection is the index fingerprint `chunks__<corpus_version>__<analyzer_hash8>__<embed_slug>` (`index/naming.py`; slugs keep `[a-z0-9-]`, `analyzer_hash8` = first 8 hex of sha256 over the T3.3 analyzer fingerprint, so a changed `compound_split`, stemmer, lexicon or hash scheme gives a new collection); the alias `chunks_active` is switched in **one** atomic `POST /collections/aliases` (delete + create) only after every point is written and the metadata is final. `--collection <name>` overrides the name (PR jobs: `pr_<N>_<shortsha>` with `--no-alias`, which never touches any alias); `--drop <name>` deletes a collection and refuses the one `chunks_active` points to. The app still serves `RAG_COLLECTION` (default `slice_v2`, D461); pointing it at `chunks_active` is a deployment setting, the Qdrant path accepts alias names
