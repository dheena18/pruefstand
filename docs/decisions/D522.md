[T5.1, retries and quota] `RetryPolicy` defaults: 3 retries, 1 s base doubling to 30 s, 25 % seeded jitter, `Retry-After` honoured, `Retry-After` > 60 s = daily limit. External-provider 429 after the retries -> `QuotaExhausted`, model exhausted for the run (no network call afterwards, cache hits still served); local-provider 429 stays a transient `LLMError`. A configured fallback backend is policy-checked and marked `fallback=True`. `RateLimitedError(LLMError)` carries `retry_after_s` (headers are read from the exception chain, LiteLLM drops them on its own wrapper)
