[T2.3a, T2.4a, T2.5a] Hardening follow-ups. **OLDP loaders:** every `Problem` is stored cut to 200 characters and in `ascii()` form (`ProblemLog.append`); all files of one directory pass share one examined-row budget `OldpLimits.max_rows` (`RowBudget`, bad lines count) and `OldpLimits.max_files` (1000) caps the files opened (`too_many_files`); a parquet batch that cannot be converted (date outside the Python range, missing time zone) is converted row by row and the bad row is one `bad_record` with source `<file>:<row>` (JSON-line problems name `<file>:<line>` too); parquet row groups are read one row per batch unless every wanted column (matched by its top-level name, so nested columns count) has no dictionary page and only encodings whose footer size bounds the decoded size (PLAIN, RLE, BIT_PACKED, DELTA_BINARY_PACKED, DELTA_LENGTH_BYTE_ARRAY, BYTE_STREAM_SPLIT; a dictionary value or a DELTA_BYTE_ARRAY prefix counts once in the footer but decodes once per row), other groups in batches of up to 64 rows and about 1 MiB of footer size; the footer is written by whoever made the file, so as the hard backstop every parquet file is read in a child process (`ingest/records_child.py`) whose address space may grow by `OldpLimits.max_parquet_memory_bytes` (default 512 MiB, 0 = in process) beyond its start (one malloc arena, system allocator, one Arrow thread, BLAS threads set to 1: reader start costs about 0.3 CPU-s instead of 7.5 on a 160-vCPU machine; started with `python -I`; the soft limit is clamped to an existing finite hard `RLIMIT_AS`, a read error that is the limit biting (`Failed to launch worker thread`, ENOMEM / EAGAIN, `Cannot allocate memory`) is a `memory_limit`, not a `bad_file` (found on the hosted runner), and a limit that cannot be set is logged as `parquet_reader_unlimited`, not silent), and an unknown bomb type ends as one counted `memory_limit` problem for that file (CLI exit 1, no effect on the machine); any NEW bomb type is a follow-up, not a blocker; measured peak RSS with the four bomb shapes (dictionary, nested dictionary, DELTA_BYTE_ARRAY, 12 x 20 MB): reader child 90 to 213 MiB, calling process about 90 to 112 MiB; `write_corpus` publishes the directory with `0o777 & ~umask`; row numbers stay file-aligned after a dropped row group; `bad_date` now also covers integers, `NaN`, bools and `2020-01-01garbage` (only an ISO date with an optional time is a date); `load_citation_graph` snapshots `problems.total` so a reused `ProblemLog` does not turn an empty graph into an error. The readers moved to `ingest/records_model.py` and `ingest/records_read.py` (300-line limit; `ingest.records` re-exports). `core/data/law_aliases.yaml` gains ZPO, VwGO, SGG and EStG (national); this changes what `extract_citations` finds, so `citation_precision`, `citation_recall`, `citation_f1` and `citation_grounded` are now `version = "2"` and baselines made under version 1 are not comparable (the perturbations `typos` and `citation_style`, which use the alias table, are bumped to version 2 in the T4.4a PR, D891) (the tier-1 `live-baseline` is re-created by the next main run). **EUR-Lex:** the heading probe reads at most 64 characters per paragraph (`_HEADING_CHARS`), so nested `<p><span><p>` costs linear time. **Ingest:** `verify_corpus(directory, plan=None)` re-applies the writer's rules (`corpus_files.check_chunk_rules`: licence, banned source), checks the sort order and hashes while parsing in one pass (a changed byte is still reported before a bad line); `plan` (`--plan corpus.yaml` in `scripts/validate_corpus.py`) checks declared tenants and sources whose rules name only the source (`ingest/corpus_plan.py`, the rest is not visible on a chunk); `write_corpus` stages in `.<version>.<random>.partial` (concurrent ingests no longer share a staging directory; the loser of the final rename compares with the winner's bytes); `load_pins` reads through `load_model` (no aliases, no duplicate keys, 1 MB cap). The `_extra_documents` pin of T4.6 was already done (`attack.sources()`); `corpus/slice_v1` fails `validate_corpus.py` by design (documented, pinned by a test); per-source licence files stay a documented publication blocker (DATA_LICENSES.md, T8.4/T8.5).
