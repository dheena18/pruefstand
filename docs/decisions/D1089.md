[T6.2a S4, executor stack] `infra/gate-executor/compose.executor.yml` (project `pruefstand-exec`) holds the three trusted services of a job. **qdrant**: the root compose's pinned image (a test keeps them equal), read-write key `QDRANT_API_KEY` and read-only key `QDRANT_READ_ONLY_API_KEY` from `runner.env` (both required; the candidate gets only the read-only one, D1098, so no JWT RBAC), storage `$PRUEFSTAND_HOME/qdrant` on the VM disk (never the data root), loopback ports with the executor defaults `${QDRANT_HTTP_PORT:-6333}`/`${QDRANT_GRPC_PORT:-6334}`; on `gate-net` (candidate) and a plain bridge `pruefstand-exec-host`, needed only because Docker publishes no port of a container that is on internal networks only. **rerank-cpu**: the T3.1a image built from `infra/gpu/rerank`, only on `gate-net`, no host port, weights from the external volume `pruefstand-rerank-models` mounted read-only with `HF_HUB_OFFLINE=1` (the owner fills it once with egress, runbook §0 step 7). **llm-proxy** unchanged. Only llm-proxy is on `proxy-egress`; only qdrant publishes ports; every service has a healthcheck and `no-new-privileges`. Owner-merge: it changes what runs on the executor VM.
