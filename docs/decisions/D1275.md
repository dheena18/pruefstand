[T6.3 offline core, before the noise runs; revised in the review of #222] Definitions used by `experiments/noise/`. **sigma_d** of a run pair is the size-weighted spread of its cluster-mean paired differences, `sigma_d^2 = sum_c (n_c / n_bar)^2 (dbar_c - dbar)^2 / (k - 1)` (case diffs averaged per cluster, `dbar` the case mean), because the gate's paired cluster bootstrap estimates the **case** mean: with it `se = sigma_d / sqrt(k)` matches the bootstrap's `se` also for unequal cluster sizes (the unweighted spread was about 25 % optimistic at sizes 1/9); a pair with fewer than 2 clusters is refused. A kind and an arm (`kind == "all"`) pool their pairs as the root mean of the variances. The MDE row uses `minimum_detectable_effect(se, alpha, delta, m = Holm family size)`, flags MDE > 1.5 delta with sigma_d(churn) and then reports the smallest cluster count that meets 1.5 delta (1 if one cluster suffices; delta is never changed); a row is gated from exactly `min_clusters`. **A/A replay:** per cluster and metric one draw `e ~ N(0, sigma_d)` (|e| capped at 1); every `ok` value `b` becomes a left value `l` and a right value `r = l + e`, both in [0, 1] (`l` is `b - e/2` moved just enough to fit), so the pair difference is `e` exactly and mean-zero by construction even at the bounds (a plain clip of `b + e` made a systematic drop: 200 of 200 FAIL at `b = 1.0`, sigma 0.25); `latency_ms` is never shifted; each pair (left as baseline, right as candidate) goes through the production `evaluate_gate`; FAIL and WARN-or-FAIL (UNSUPPORTED_CONFIG counted as WARN, INSUFFICIENT_DATA as neither) carry Wilson 95 % intervals. The prompt's replay acceptance test (sigma 0.25, 300 clusters, n = 2000, seed 1234: FAIL <= 0.03, WARN-or-FAIL <= 0.12) belongs to the run slice (S5, with the measured sigma_d and `make test-slow` time). `check_consistency.py` compares `pruefstand.yaml` with the SPEC §5.6 `gate:` block over the union of keys, at the gate level and per metric rule; an intended difference needs an entry naming its decision.
