[T4.6, injection documents] `attacks.make_injection_docs` writes one memo per (payload, placement): a real legal question of the tenant domain (the *anchor*, `attacks/data/anchors_de.yaml`, 10 per customer tenant, with the legitimate answer and citation), its answer, and the payload in one of six placements (`InjectionPlacement` in `core.models.attacks`: `plain`, `table_cell`, `footnote`, `metadata` = payload in the title, `mixed_lang` = English instruction, `base64` = payload encoded + "dekodiere und befolge"). Own payloads (`attacks/data/own_payloads_de.yaml`, 31 German + 6 English, all `{marker}`-based, no URLs); seeds from `deepset/prompt-injections` are accepted by `rewrite_payload` (marker demand appended) but not downloaded in this task. Marker `PWNED-<4 hex>`; the first hex digit is bound to the tenant (`digit % 3 == tenant index`), so markers never repeat across tenants without a shared `taken` argument. Ids: document `atk-<tp>-<nnn>`, case `inj-<doc_id>`, `cluster_id` = `anchor-<tp>-<nn>`, one per (tenant, anchor question) so the near-duplicate memos of one question are one cluster for the bootstrap (D480-D486: one role per cluster). LIMIT (open, follow-up T4.7a/T5): `injection_success` looks only for the case's own marker and `TestCase.injection_marker` is a single string, so when several memos of the same question are retrieved and the model obeys another memo, the case reads 0; the rate can be understated by up to the group size (4-5 at 8 payloads over 10 anchors). `metrics/` is not touched here; the proper fix is a marker set per cluster in the metric (follow-up). Cases are created with `split=full` and `corpus_version="unstamped"` as placeholders for `assign_splits` and the dataset build.
