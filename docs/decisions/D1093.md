[T6.2b, private executor workflows] `gate-executor.yml`, `baseline-promote.yml`, `nightly.yml` and `backup.yml` live in `infra/gate-executor/workflows/` and reach the private repo only through `scripts/sync_executor.sh`. `scripts/workflow_private.py` checks them: exactly these four files; SHA pins with a version comment; top-level `permissions: {}`; triggers only `schedule`/`workflow_dispatch`; cron minutes off 0/15/30/45; `concurrency.group` `${{ github.workflow }}-${{ inputs.pr || inputs.sha }}` for `gate-executor.yml` and `${{ github.workflow }}` for the others, never cancelling; every job has `timeout-minutes` and `runs-on` with `a40`, except the hosted, secret-free `guard` of `nightly.yml`; `gate-executor.yml` has only `workflow_dispatch` with a required `pr`; `nightly.yml` has exactly the two crons and the jobs `guard` (passes `github.event.schedule` to `night-guard --schedule`, outputs `run`, `deadline`) and `nightly` (`needs: guard`, `if: needs.guard.outputs.run == 'true'`, runs `gate-orchestrator nightly --deadline` with the guard's deadline); no step calls `flock`, `switch-mode.sh`, `health.sh` or `fetch-model.sh`; no `gh workflow run baseline-promote`; `upload-artifact` with `retention-days: 14`; no `run-gate`. Deviation from the prompt's wording: the deadline and the `pr` input reach `run:` through `env:` (`"$DEADLINE"`, `"$PR"`, the PR number re-checked as digits), never as `${{ }}` inside a script, so zizmor's template-injection audit stays clean. Jobs that write the private branches `executor-state` or `baselines` hold `contents: write` of the private `GITHUB_TOKEN`; the public repo is reached only with a `pruefstand-bot` token minted per job (`statuses: write`; the dispatch also `pull-requests: read`, `contents: read`). Review #214 additions (`scripts/workflow_private_hardening.py`, one mutant test each): no `${{` inside any `run:`; job permissions exactly `{contents: read}` for the hosted `guard` and only `contents` (`read`/`write`) elsewhere; every checkout `persist-credentials: false`; no `secrets.*` in a `run:` and no `env:` token variable (from `secrets.*`, `github.token` or a token output) expanded as `$NAME` in a `run:`; A40 jobs `runs-on` exactly `[self-hosted, linux, a40]`. `scripts/sync_executor.sh` refuses (exit 2) a tag whose workflows call a `gate-orchestrator` subcommand that the tag's `gate_orchestrator/cli.py` does not register (`add_parser("<name>"`), so the merge order is: the CLI slice (D1095) first, then these workflows. `inputs.sha` stays in the `gate-executor.yml` concurrency group as the prompt's final form for T7.2 (actionlint reports it as undefined until then); an actionlint config naming the `a40` label belongs to the private-repo template.
