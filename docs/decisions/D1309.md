[T8.4 S6b, owner-merge, Opus review of #240] `infra/deploy/demo/compose.yml`: every demo service sits only on the internal network `demo-net` (no egress); the production `rag-demo` publishes no host port (T8.5's cloudflared reaches `rag-demo:8000` over `demo-net`, the smoke uses `docker compose exec`), so the internet-facing app has no internet or LAN egress (ADR-0012, P2.2). Only the test instance `rag-demo-e2e` (profile `e2e`, nightly) also joins the plain bridge `e2e-edge`, because Docker cannot publish a port from an internal network; it listens on 127.0.0.1 only. Built images (`rag-demo`, `rag-demo-e2e`, `index`) carry no `image:` tag (the build base is digest-pinned in the Dockerfile); `index` has a healthcheck; the app containers drop all capabilities and have a read-only root with `/tmp` tmpfs. Limits: qdrant 0.5 vCPU / 1 GB, llm 2 / 4, embed 1 / 1, rag-demo 0.5 / 1 = 4 vCPU / 7 GB (ADR-0012: 4 / 8); with the e2e instance 4.5 / 8. `scripts/tests/test_demo_compose.py` asserts all of it. ui-spec, docker.md and ADR-0012 updated; the former loopback port 8090 of the public rag-demo is gone.
