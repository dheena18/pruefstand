[T6.2a, shared index] Every gate attempt (dispatch, main promotion, nightly) first checks the executor Qdrant for the alias `chunks_active` (`GET /aliases` with the read-write `QDRANT_API_KEY` on `QDRANT_URL`, default `http://127.0.0.1:6333`). If it exists nothing is done (idempotent; the check is one HTTP call). If it is missing, the orchestrator builds it once, under the GPU lock it already holds, with the trusted main's `rag-demo index --corpus $PRUEFSTAND_DATA_ROOT/corpus/$PRUEFSTAND_CORPUS_VERSION --encoder ollama` (which switches the alias only for a complete collection) and checks the alias again. The corpus version cannot be derived from anything the orchestrator reads, so it is a `runner.env` key set by the owner (`docs/ops/secrets.md`); without it, or without that directory, the attempt stops with the infra error `index_missing: ... set PRUEFSTAND_CORPUS_VERSION ...` before any proxy or candidate starts. Other failures are `index_unavailable` (Qdrant unreachable or key refused) and `index_failed` (non-zero exit or alias still missing). Rebuilding after a corpus change stays an owner step (drop the alias or index a new collection). Review #259: the build embeds through the tunnel: `rag.gpu.yaml` names `LLM_PROXY_URL` as its embed endpoint (D1081), and on the host that name must be the tunnel (`OLLAMA_GPU0_URL`, like the owner's `make index`), never `llm-proxy:11500` (which resolves only on `gate-net` and is not up yet); without `OLLAMA_GPU0_URL` nothing is built (`index_unavailable`). `PRUEFSTAND_CORPUS_VERSION` must be a plain directory name directly under `<data root>/corpus/` (not `.`, `..` or a path); an odd `/aliases` answer is `index_unavailable` too, so it stays on the infra retry path.
