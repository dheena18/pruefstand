[T6.2a, owner decision on the D1068 open point] Every tier-2 rag-demo profile (`apps/rag-demo/configs/rag.gpu.yaml` and all `configs/bugs/gpu/*.yaml`) names `endpoint_env: LLM_PROXY_URL` for the generator **and** the embedding model, so the PR's own profile already points at `llm-proxy` and the executor never has to hand a candidate an `OLLAMA_GPU*_URL`. The candidate-environment rule stays strict (no `OLLAMA_GPU0_URL`/`OLLAMA_GPU1_URL` in the candidate env, T6.2a `test_candidate.py`); the alternative (setting `OLLAMA_GPU0_URL=http://llm-proxy:11500` for the candidate and relaxing that test) was rejected. On the dev stack, which has no `llm-proxy`, `infra/gpu/compose.rag-demo.yml` and `make index` (`mk/rag-demo.mk`) set `LLM_PROXY_URL` to the tunnel (`$OLLAMA_GPU0_URL`, default `http://127.0.0.1:11434`); rag-demo still sends the bearer key, which Ollama ignores. A test asserts that no tier-2 profile mentions `OLLAMA_GPU` and both endpoints read `LLM_PROXY_URL`.
