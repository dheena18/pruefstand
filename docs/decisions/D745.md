[T4.5, review fixes] (1) `register`: the preposition rule matches `Sie` case-sensitively; a sentence with lowercase `sie`, `sich`, `ihnen` or `ihr...` is never rule-converted but goes to the model (rule-only drafts skip the equivalence check, so they must be certain). (2) `gender`: for nouns whose singular equals the plural the rule fires only when the nearest determiner within three words is a plural one, a numeral, or there is none; singular determiners include `vom/zum/beim/im/am`, `dein*/Ihr*/euer*`, `der/den/dem/des`; anything else goes to the model. (3) Policy in code: `perturb_case_async` marks every case whose tenant is not `shared_public` as private (`Item.private` in the batch passes); all its calls (rewrite, equivalence, second model) carry the prompt id prefix `datagen.private_docs.`, so the T5.1 data guard refuses every external provider with or without a canary registry (`--no-canaries` does not weaken it) and only the local model answers; a private item is then dropped as `no_independent_validator` (the local rewriter has the judge's family). No dataset split is private, so the tenant is the only criterion. `core.errors.DataGuardViolation(PolicyViolation)` (raised by the data guard; additive) lets the rewriter fall back to the local model only on that refusal, other `PolicyViolation`s surface. (4) `--pass both` uses `item_rng` like the batch passes; item ids are `q` + content hash (inserting a question re-requests nothing); `validate_pass` stores verdicts in `verdicts.jsonl` as it goes (key = draft key + validator identity) and ends with the outcomes so far on `QuotaExhausted`; `static_check` also requires the same law abbreviations (BGB vs HGB). (5) Prompt texts live in versioned files: `register_{du,sie}_de_v1`, `gender_{star,colon,partizip,pair}_de_v1`, `perturb_equivalence_{name}_de_v1`.
