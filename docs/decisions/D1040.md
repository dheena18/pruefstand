[T4.7b S6, offline part] `hf://<user>/<name>@<rev>` resolution (SPEC §5.6). `pipeline/datasets_hf.py` calls `huggingface_hub.snapshot_download(repo_type="dataset", revision=<rev>, local_dir=.cache/pruefstand/datasets/<user>__<name>/<rev>/raw)`, merges the per-licence configs (`<config>/<split>.jsonl`) into `.../merged/<split>.jsonl` and hands that directory to the unchanged local loader (full row validation, count check against the manifest). The HF layout written by `export_hf` had no manifest, so a snapshot could not be turned back into a directory: `build_hf_layout` now also writes `dataset_manifest.json` to the repo root with `splits`, `blocks` and `judged_subset` recounted from the exported rows (held-out/private cases are not exported; a fully filtered split is dropped, which `validate` then reports as a missing required split) (interfaces §14 note; a repo exported before this change must be re-exported, the loader says so). A version-like revision (`v1`, `1.0.0`) is cached once resolved, `main` or a branch is fetched on every call; the token is only read by `huggingface_hub` from `HF_TOKEN`, never by Prüfstand. `pruefstand validate dataset hf://...` uses the same resolver (its path argument is now a string). Replaces the T1.10 `ConfigError` for `hf://`; the file helpers moved to `pipeline/dataset_files.py` (file-size limit), unchanged.
