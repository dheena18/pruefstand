[T6.2b S8, executor-health] `executor-health.yml` (hourly at :43 + dispatch, hosted, one job `check-heartbeat` with exactly `contents: read, issues: write`, no secrets; enforced by `scripts/workflow_executor_health.py` in the workflow guard and an `OTHER_WRITE` entry for `issues: write`) fetches `heartbeat.json` from raw.githubusercontent.com (branch `heartbeat` of `dheena18/pruefstand-dashboard-data`, anonymous; a failed fetch counts as an empty file = executor down) and applies the actions of `scripts/ci/check_heartbeat.py`, a pure function of `now`, the heartbeat and the open issue labels. A heartbeat without a valid timezone-aware `ts` yields only `executor-down` (it says nothing about backups or nightlies). While `executor-down` holds (unknown, empty, failed-fetch or stale heartbeat, or a health field false > 2 h) **no issue is closed**: such a state is no evidence of recovery (review #198). Heartbeat text reaches public issues only sanitised: `release_tag` must match `^[A-Za-z0-9._-]{1,64}$` (the same class as the workflow's marker grep) or becomes `invalid-tag`; status text keeps only `[A-Za-z0-9 ._:-]`, at most 80 chars, as inline code (no mentions, links or markup). An `open` for a label whose issue already exists becomes a comment; `nightly-skipped` closes only on `last_nightly_status == "ok"`; the drift note carries the marker `drift-no-release:<release_tag>` and is posted once per tag (markers are read from the bodies and comments of the last 50 `nightly-skipped` issues). Labels are created on first use (`gh label create --force`). Follow-up (review #198 minors): a partial heartbeat (a health field missing or not a bool) closes nothing either, and `backup-stale` / `nightly-failed` close only when their own field is present and well-formed (missing = unknown); the drift note is an `open` (new issue) when its `nightly-skipped` issue is closed in the same run, and the workflow treats `comment` without an open issue like `open`, so actions in one run never depend on each other.
