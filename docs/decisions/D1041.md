[T4.7b S4, offline part] `scripts/closed_book.py --model <id> --split core [--retag] [--dataset DIR]`: each answerable case is asked of the generator without retrieval by one direct `/api/chat` call (catalogue options, `temperature` forced to 0, `think: false`, prompt `scripts/prompts/generator.closed_book.closed_book_de_v1.txt`; needs `PRUEFSTAND_LOCK_HELD=1`, exit 2 without it). Tag `closed_book:<model id>` iff a citation extracted from the answer matches a gold citation (`citations_match`) AND the answer holds >= 80 % of the reference answer's content words. Content words: reference citations removed by a regex, casefolded, numbers and words of >= 4 letters, a small German/English stopword list dropped (`nicht`/`kein*` stay content words, and a case is never tagged unless answer and reference carry the same negation words (`nicht`, `nichts`, `nie`, `niemals`, `niemand*`, `nirgends`, `weder`, `kein*` folded to one form), a dropped negation keeps recall high), a light suffix strip (`Kalendermonats` = `Kalendermonat`); deterministic, no judge, informational, never gates. The tag of the run's model is recomputed (set or removed); tags of other models stay unless `--retag`. Only the split file is rewritten (every 10 cases and on a failed call, atomically via a temp file + fsync + rename in `write_split_file`; stale tags of the model are cleared first and `<split>.jsonl.partial` marks an unfinished run; a rerun asks everything again) (sorted by id), the manifest is unchanged. Unit tests run on real German reference answers; the GPU run (`tagged=k/300`) waits for the real build.
