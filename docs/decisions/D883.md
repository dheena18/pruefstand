[T1.10a, note on D407] `TargetCassette(name, info_overrides=...)` replaces fields of the replayed `/v1/info` (for example `corpus_version`, `git_sha`) so a test can ask for another corpus or identity; an override is a test input, never a recorded fact. Cassette headers now end with `(git <sha>)`, the `git_sha` the recorded target reports in `/v1/info` (`unknown` when missing or unsafe); existing cassettes are not edited by hand and get the header at their next `make cassettes-target`. The live CLI test is marked `e2e` as well as `live` (VM-only, needs `scripts/live/two_targets.sh`).
