[lead helper scripts, 2026-11-15, owner request] The lead's push/resolve helpers live in the repo as `scripts/lead/` (`draft_push.sh`, `draft_update.sh`, `resolve_merge.sh`, `install_wrappers.sh`, `lib.sh`, `merge_union.py`), tested in `scripts/lead/tests/` with real git repos and a fake `gh`/`git`/`uv`; nothing agents rely on lives only in `/tmp` or a home directory. Because the wrappers run `origin/main`'s copy with the lead's rights, `scripts/lead/**` is an owner-merge path (D1210). Tools (`gh`, `git`) are resolved once and refused under `$HOME`; PATH is then fixed. `draft_*` run `ruff check` + `ruff format --check`, refuse (exit 2) a commit message, PR body, PR title or the message of any commit a push would send (`HEAD --not --remotes=origin`, side branches included, re-checked before every push, so a second run cannot push a commit whose message got a footer) with a `Claude-Session:` line or a `Generated with/by Claude Code` footer (case and spacing tolerant), stage only tracked changes plus explicit `--add <path>` (other untracked files, files over 1 MB and secret-looking names are refused; the checks run on a copy of the index, so a refusal leaves the index untouched), push exactly `refs/heads/<branch>:refs/heads/<branch>` (never forced; branch names with a leading `+`/`-` or refspec characters are refused) and open the PR as a draft against `main`. `resolve_merge.sh` merges `origin/main` with `--no-commit`, requires a merge already in progress to be of `origin/main` (or an ancestor), keeps both sides in the append-only files (`docs/decisions.md` ONLY while main still has the single table, i.e. before PR #160: once `origin/main` has `docs/decisions/`, a conflict on the page or a `| D<n> |` row added to it stops with `NEEDS MANUAL` naming `build_decisions_index.py --rebase-pending`; TASKS, ...; any conflict under `docs/decisions/**` needs a human), stops on other conflicts, on a duplicate D-number and on conflict markers a merge would add, never commits those, writes progress to `<git-dir>/lead-resolve-merge.state` (a rerun resumes through `MERGE_HEAD`; resolved files are written atomically and an append-only file left unmerged without markers counts as finished only if it still holds every line of both index sides, and any file lacking an ours/theirs pair (modify/delete) needs a human; the commit takes the index only, unstaged edits to files of the merge are refused and unrelated edits are never swept in), runs pytest in its own process group bounded by `LEAD_TEST_TIMEOUT` (`TEST_TIMEOUT`; Ctrl-C/TERM of the script kills that group; a per-worktree `flock` inherited by pytest refuses a second run while an orphan lives) and has `--dry-run` (local `origin/main`, no fetch). `install_wrappers.sh` writes `~/.local/bin/lead-draft-push|lead-draft-update|lead-resolve-merge`, which fetch and fast-forward the main checkout and exec its copy (a worktree of a stale branch lacks `scripts/lead/`). `scripts/check_self_matching_pgrep.py` (target `self-matching-pgrep` in `mk/checks.mk`, a prerequisite of `file-size`, so `make check` and the CI `file-size` job run it) flags `pgrep -f`/`pkill -f` (signal names such as `-HUP` are not options; `--` ends options; `\`-continued lines are joined) in shell, zsh, Makefile/`mk`, systemd `.service`, Dockerfile, workflow and composite-action `run:` blocks and in Python `subprocess`/`os.system` command strings (including `ssh host 'pkill -f x'` strings and heredocs) unless the pattern uses the bracket trick (`[x]yz`), `-x`, `-P`, `-F` or a PID file, or the line carries `# selfmatch-ok: <reason>`; no offender existed when it was added.
