[T6.2b S1b, `gate-router.yml`] The public router posts `pruefstand/gate` with a `pruefstand-bot` installation token (`actions/create-github-app-token` v3.3.0 pinned, `permission-statuses: write`, secrets `BOT_APP_ID`/`BOT_APP_KEY` of environment `gate-router` only): no gated path → success "not gated (no gated paths changed)"; a PR by `pruefstand-release[bot]` from a `release-please--*` branch whose every file is release-exempt and every changed patch line matches that file's line rule → success "not gated (release version bump)"; anything else → `pending` "gated: awaiting tier-2 dispatch" (CLAUDE.md §7, interfaces §10, R13 P1.1; the T6.2b Context sentence "no status" is the older wording), but a non-pending `pruefstand/gate` already on the head (the executor's result after a `reopened`) is never overwritten. Release rules (ci-cd.md §5): `version = "…"` in any `pyproject.toml`; entry lines of `.release-please-manifest.json`; the `image:` line of `action/action.yml`; any line of `CHANGELOG.md`; in `uv.lock` only `version = "…"` lines whose preceding `name = "…"` (context or changed) is `pruefstand` or `rag-demo`; a file without a patch (binary, too large) is never exempt. The rules and the gated-path regex (from `gated_paths.txt`) are generated by `scripts/ci/gate_router_regex.py`, inlined as `env` values, and the workflow's script mirrors the Python `classify`; tests compare the inlined values with the generator and run the workflow script under Node against the same cases. zizmor's `dangerous-triggers` finding on `pull_request_target` is ignored inline with its reason (the documented single exception, X2.2).
