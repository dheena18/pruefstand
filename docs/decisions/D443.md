[T6.1] Promotion is two-phase: the new baseline is staged as `<ref>.<hex>.partial` (fsync), swapped in with `os.rename` while the old one is kept as `<ref>.<hex>.old`, `history/<run_id>` is renamed in, and only then (git store) the one-file index commit is pushed (3 attempts, fresh clone each); a failure at any step rolls the data root back to the previous baseline, a success deletes the `.old` copy. A `get` that finds `<ref>.<hex>.old` without `<ref>` raises (interrupted promotion), never `None`. `put` itself refuses incomplete or flagged runs (`BaselineRefused`, a `StoreError` the CLI maps to exit 1) and stores `main` only for `block is None`, `nightly-b<k>`/`release-b<k>` only for `block == k`; `JUDGE_TRUNCATED_SHARE = 0.05` duplicates the gate's constant (`store` cannot import `pipeline`; a test keeps them equal). The push token is read from `PRUEFSTAND_BASELINES_TOKEN` (name configurable) and reaches git only through `GIT_ASKPASS`
