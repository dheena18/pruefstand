[T3.6, prompt budget, AI13-05 / D307] Tier 2 only: budget = `num_ctx` − `num_predict` from the config (`generator.options.num_ctx` equals the catalogue value, `generation.max_tokens` is `num_predict`); the prompt is counted with the **generator's** `tokenizer.json` (`RAG_GENERATOR_TOKENIZER`, baked into the image from the catalogue pin, never the `bge-m3` one), wrapped like the Qwen chat template (ChatML markers, empty think block for `think: false`). Over budget the lowest-ranked chunks are dropped (ids logged, texts never); they come back with `used_in_prompt: false`. After each native response `/v1/health.stats.prompt_overflow` grows when `prompt_eval_count ≥ budget` or differs from the local count by more than 2 %; without a tokenizer only the budget check runs and a startup warning says so. Caveat for the lead: Ollama reports only the tokens it evaluated, so a reused prompt-cache prefix lowers `prompt_eval_count`; calibrate on the first GPU run before treating the counter as more than informational
