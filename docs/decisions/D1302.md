[T1.13c, non-retryable generator timeout] After its own generator read or write timeout rag-demo no longer answers the generic 503 that the runner retries: it answers HTTP 504 with the body `{"detail": {"code": "generator_timeout", "message": "generator timed out"}}` (`GenerationTimeoutError` in rag-demo). `HttpTargetAdapter` maps exactly that status plus code to `TargetError(transient=False)`; every other 5xx, including a 504 from a proxy or with another code, stays transient. Reason: the tier-2 generator serialises requests, so a retried timeout only queues a duplicate generation behind the first (D624, D1065). Contract tests on both sides: `apps/rag-demo/tests/unit/test_api_generation.py` pins the body, `packages/pruefstand/tests/unit/adapters/test_http_generator_timeout.py` pins the adapter mapping. Other generator failures (unreachable, 5xx) stay 503.
