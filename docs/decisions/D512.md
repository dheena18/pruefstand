[T3.5, post-condition guard] After rerank and cut, a hit whose tenant is not in `allowed_tenants` raises `TenantIsolationError` (a `RetrievalError`, so the API answers 503 `backend unavailable`) and logs the chunk ids at ERROR, never the text. The guard is skipped while `tenant_filter: post_topk` or `shared_public_merge: unfiltered` is active (those switches must produce real leaks) and can be switched off with `guard=False` for the isolation tests, which prove the filter alone. The leak bug paths run before the reranker; with `post_topk` the first stage is cut at `top_k` as before
