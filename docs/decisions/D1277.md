[T6.3 S1 offline, before the noise runs] How `experiments/noise/noop.py` builds the runs of a noise arm.
- **Plan:** every arm plan starts with a reference run of the unchanged `rag.gpu.yaml` (index 0, the pair partner), then has `--repeats` variant runs.
- **No-op and churn modes:** each run gets `generation.seed = seed + i` (X3.5). The seed is part of the rag-demo config hash and so of the target fingerprint, so "target cache off" holds by construction while the judge cache stays on.
- **No-op only:** every run rebuilds its index into its own collection `noise_<mode>_<kind>_<i>`. `rebuild` also rebuilds the image (`docker build --no-cache`) for the variant runs.
- **`reorder`:** permutes the mapping keys at every level with a seeded generator. Lists keep their order, because their order is meaning; `rag.gpu.yaml` has none today. A test checks that the rag-demo `config_hash` is unchanged.
- **Churn kinds:**
  - `prompt_synonym` is mutation N04: its patch brings `answer_de_v3.txt`, applied in the candidate worktree.
  - `quant_swap` takes N09's `rag_overrides` and is refused while N09 is pending in `benchmarks/mutations/index.yaml` (nothing is pulled, ADR-0019).
  - `temp03` sets `generation.temperature: 0.3`.
- **Repeats mode:** the unchanged config with fixed seeds. `--cache-mode off` switches the target and judge caches off; this is the floor.
- **`run_noise.py`:** writes `runs/noise/<arm>/plan.json` and one `rag.<label>.yaml` per run. Executing the runs on the tier-2 stack under `pruefstand-lock` uses T6.2b's stack runner and is added with the run slice.
