[T3.1d] `git_verify` (owner path): the fetch names its refspec (`+refs/heads/main:refs/remotes/origin/main`), so a remapped `remote.origin.fetch` cannot move `origin/main` when the owner runs the check; a configured `url.<base>.insteadOf` is refused (checked before the root branch too, and now also by the `gpu-deploy-bin` / `gpu-install-wrapper` make targets before they `git fetch <URL> main`). NOT guaranteed: the root path never fetches (it requires a `FETCH_HEAD` from the last 10 minutes made by the owner and compares the existing `origin/main`, so the named refspec does not apply there), `remote.origin.url` is not checked, and the make targets follow `url.*.insteadOf` only as far as the new check refuses it (other URL rewrites such as `pushInsteadOf` do not affect a fetch). The wrapper's `stat %D` decode is the function `lock_key` with the glibc masks `0xfffff000` / `0xffffff00` (a minor above 255 and majors above 4095 no longer leak into each other); hex `10002c` is major 0, minor 300 and is unit-tested.
