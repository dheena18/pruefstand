[T3.6, prompt files] A prompt file may carry directive lines: `### layout:numbered` selects the v2 user layout, `### rule:<name>` starts a block that runs to the next directive. `answer_de_v2.txt` has the blocks `cite`, `refuse`, `injection_guard`, `language`; `answer_no_citations_de_v2.txt` and `answer_no_refusal_de_v2.txt` are v2 minus exactly one block (M5, M6); the `injection_guard` block is rendered only while the switch `injection_guard` is `on` (M7); directives never reach the model. v2 layout = `<dokumente>` around `[<n>] <citation_key or doc_id> — <text>` (with the guard on each hit stays inside T1.13's `<dokument id quelle>` block, instruction-like lines dropped), no tenant id, no `Dokumente:` header. v1 files render byte for byte as before (the recorded cassette still matches). `rag.gpu.yaml` and `configs/bugs/gpu/*` switch to v2, so every tier-2 `config_hash` changes once (the tier-1 hashes do not). A planted instruction is inside the delimiters unchanged with the guard off; with the guard on the T1.13 filter still drops the line (the guard owns that behaviour)
