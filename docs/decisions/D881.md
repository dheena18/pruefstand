[T6.1a (7), ADR-0004] Who guarantees that a gate-FAILed run is not promoted: `pruefstand baseline promote` itself (the single entry), not the T6.2b workflow. For `main` and `nightly-b<k>` the run's `gate.json` is REQUIRED (absent: exit 1, "run `pruefstand gate` first", not waivable); the release anchors `release-b<k>` are never gated and may lack it. A `gate.json` that is unreadable (symlink, directory, I/O), invalid or of another run is an integrity error (exit 3, never waived). Status FAIL, or ANY `find_hard_fails` finding recomputed from the verified run with the config's `gate.hard_fail` (rule `hard_fail` = a leak, `hard_fail_unverifiable` = a leak check that could not run) is refused (exit 1, store unchanged); a release anchor is therefore checked for hard-fail findings only, not for a gate verdict. The only override is the owner's explicit `--allow-failed-gate` (by hand, runbook section 3a); no workflow passes it (guard test required in T6.2b). Trust model unchanged (only adds refusals); flagged for the owner because it adds a CLI flag.
