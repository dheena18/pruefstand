[T4.6, refusal] `attacks.refusal.make_own_unanswerable(indexed, rng)` takes per tenant the citation keys it can retrieve (own + `shared_public`) and emits all near-miss templates (`missing_section`: a provision beyond the end of the law; `repealed`: a repealed act; `unstated`: an amount or period the provision does not state) plus at most as many off-topic questions, so near misses are >= 50 % per tenant (12 + 6 each). A `missing_section`/`repealed` template naming an indexed citation raises `DatasetError`. Tags: `near_miss`, `kind:<kind>`, `cite:<citation>`. `unstated` templates name an indexed provision by design, so "names a section absent from the tenant's chunks" holds for the first two kinds only (deviation from the prompt's test sentence). `unanswerable_from_germanrag` turns rows with a blank answer into `calibration_only` cases with `license_config="germanrag_derived"` (CC BY-SA 4.0, DATA_LICENSES section 2; `export_hf` does not enforce `calibration_only`, so the licence config must be right) and raises `DatasetError` when a non-empty input yields no row (column mapping check, T5.3). The optional `laws=` argument checks that a `missing_section` template cites a law of the tenant corpus and a `repealed` one does not. Partly answered templates were replaced (BGB 616 Hochzeit, VVG 14 Abs. 2 Abschlag, VVG a. F.).
