[T7.3 S2 offline, implements D1272] `experiments/rq1/run_grid.py` builds every RQ1 grid cell from main's `apps/rag-demo/configs/rag.gpu.yaml`.

**Deriving the `bge_m3` arm.** The arm's `embed` section is replaced, as a whole, by the base file's `embed` section, which reaches bge-m3 through `LLM_PROXY_URL` with the candidate key. So the grid hashes cover the derived section, and the committed placeholder in `grid.yaml` is never run. The `e5_large_instruct` arm stays as spelled out in `grid.yaml`.

**Checks on every cell.** Each cell is `rag.gpu.yaml` plus its overrides. It is:
- refused unless its embed endpoint variable is on the allow-list `LLM_PROXY_URL` (bge-m3 through llm-proxy) or `EMBED_URL` (the VM CPU TEI service of the e5 arm), so a tunnel variable or any new name is refused;
- parsed with rag-demo's own `parse_config` against `infra/gpu/models.yaml`;
- stored at `runs/rq1/<rag-demo config_hash>/rag.yaml`, which is the run directory key named by S2.

Two cells with the same rag-demo config hash are refused. `runs/rq1/grid.json` lists, per cell:
- name and grid hash;
- rag-demo config hash;
- embedder and its endpoint variable;
- retrieval, chunking and compound split.

**Out of scope here.** The index builds and the `rq1` requests (`plan.py`) run on the tier-2 stack runner of T6.2b and come with the run slice.

**Run-slice note (review of #238).** The e5 arm's `EMBED_URL` TEI service is not part of `infra/gate-executor/compose.executor.yml`. A candidate on `gate-net` therefore cannot reach it today. The run slice must add the e5 TEI service on `gate-net`, CPU only and offline like `rerank-cpu`, or run the e5 cells outside the gated path. This is an owner-path change (`infra/gate-executor/**`).
