[T6.2a, owner request for M4 prep] Two host scripts for the runner's env file `/home/pruefstand/runner.env` (`docs/ops/secrets.md`), both run by the owner as user `pruefstand` with the script on stdin (`sudo -u pruefstand bash -s -- /home/pruefstand/runner.env < infra/gate-executor/host/<script>`), so `pruefstand` needs no access to the owner's checkout and no agent ever reads the file. `runner-env-names.sh` prints only variable names (`NAME`, `NAME (empty)`), never a value: a name is printed only for a line that starts an assignment (`NAME=` or `export NAME=` at the line start) outside any open quoted value; a quote scanner (the same code in both scripts, checked by a test) follows `"..."` with `\\"` escapes, `'...'` and trailing-backslash continuations, so no continuation line of a multi-line value is ever printed; any other line is reported by number only (review of #195). `runner-env-keys.sh` appends `PRUEFSTAND_NONCE_KEY` and `PRUEFSTAND_CANDIDATE_API_KEY` when missing, each `openssl rand -hex 32` as `secrets.md` says, written straight from `openssl` into the file (never into a variable, an argument or the terminal); it never changes an existing line, is idempotent, creates a missing file with mode 0600 and refuses (exit 2, file unchanged) a symlink, a file owned by another user or not writable, a mode other than 600, or a key present with an empty, blank or empty-quoted (`""`, `''`) value; only assignment lines count, so a key-like line inside a quoted value is ignored. Both scripts turn tracing off. Tests use fake files under a temp dir only. Scanner rules (second review of #195), as for a systemd EnvironmentFile: a value is quoted only when it starts with `"`, `'` or `$'` (ANSI-C; `"..."` and `$'...'` honour backslash escapes) and may span lines, adjacent quoted parts continue it, text after the closing quote is ignored; any other value is unquoted, ends at the line end (quotes inside are literal), drops a trailing comment that starts at whitespace + `#` (a value that is only a comment counts as empty) and continues on the next line after a trailing backslash. Lines longer than 8192 bytes are refused (exit 2) instead of scanned.
