[security fix F1, `baseline promote`] `gate.json` must be bound to the baseline it promotes over: its `eval_fingerprint` equals the run's (else exit 3); for `main` / `nightly-b<k>` its `baseline_run_id` is not the candidate (a self-gate always passes) and equals the run stored now for (fingerprint, ref), else exit 1, never waived; `no_baseline` is accepted only for the first promote of (fingerprint, ref); a later `no_baseline` report is unbound (exit 1, never waived); status INSUFFICIENT_DATA and UNSUPPORTED_CONFIG against the stored baseline are refused like FAIL (`--allow-failed-gate` waives them); WARN stays promotable. The store re-checks the expected baseline under an exclusive `flock` on `<data root>/.promote.lock` (local store) and inside the index change function on every fresh index (git store), so two concurrent promotes (also two first promotes) store exactly one; the loser is refused (exit 1) and the git store rolls the data root back. Gap (follow-up): the gate policy hash is not bound to gate.json. Recording an override in the stored entry (review F8): D1123.
