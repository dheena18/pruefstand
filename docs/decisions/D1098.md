[T6.2a dispatch, review #224] (1) **Qdrant keys:** the candidate gets only the executor Qdrant's **read-only** key: `QDRANT_READ_ONLY_API_KEY` from `runner.env` is passed into the candidate as `QDRANT_API_KEY` (by name, never on the command line), and the orchestrator's read-write `QDRANT_API_KEY` is removed from the `docker run` client env, so a candidate cannot wipe or poison `chunks_active` for later main and nightly runs. The executor Qdrant must set `QDRANT__SERVICE__READ_ONLY_API_KEY` (the executor-stack PR, D1089). (2) **Trusted main per job:** `host/gate-orchestrator` never moves the shared `$PRUEFSTAND_MAIN_DIR`; under a short `flock` on a file in its `.git` it fetches `origin/main`, resolves the SHA once and adds a detached worktree under `$RUNNER_TEMP`, runs `uv run --project <worktree>`, and removes the worktree at exit, so a schedule starting during a 90-min dispatch cannot change that dispatch's package or `health.sh`. (3) **Failures with a status:** a missing or unreadable `gate.json`/`run.json` is the infra error `gate_failed: …` (posted, retried once), and an image status without a `sha256:` digest is refused up front as `error` "image verification failed: image status has no digest" (never pulled, never retried).
