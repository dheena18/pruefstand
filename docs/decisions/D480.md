[T4.1, assignment order and drops] `assign_splits` draws whole clusters in a fixed order so no split is starved: `robust_pr`, `rq1`, `smoke`, `core`, `full` (refusal stratum, then three blocks), then the judged subset of `core`; every random choice is one seeded permutation of the id-sorted candidates. Whatever no stage takes is *dropped and counted*: `assign_splits_report` returns `SplitReport(cases, dropped, n_perturbed)` (`assign_splits` returns `cases` only); `assignment_summary(cases, seed)` gives the manifest fields `blocks` / `judged_subset` / `assignment_seed`. A cluster whose unperturbed cases have more than one role (answerable / unanswerable / injection / probe) is not placed (builders keep roles apart), and a cluster that lands in `smoke` or `core` keeps its unperturbed cases only (variants dropped), so `core` is exactly 220 + 50 + 30 and perturbed cases stay in `perturbed_all` (X3.6).
