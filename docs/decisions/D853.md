[CI, gitleaks scope; OWNER DECISION 2026-11-09] On `pull_request` the `gitleaks` job scans only the PR commit range (`base.sha..head.sha`, passed through `env`, not interpolated into the script); on push to `main` and the weekly run it scans the full history as before. Reason: a synthetic secret-looking test string on any other branch failed the `scan` check of every PR (4 occurrences, PRs #59/#67/#70/#77). No allowlist is widened, and the aggregate `scan` stays the required check.
