[T6.1, interface] `push_dashboard_data(src, repo, *, token_env, extra, remote=None)` and `push_heartbeat(repo, payload, *, token_env, remote=None)` gain the optional keyword `remote` (git URL or local path replacing `https://github.com/<repo>.git`; used by the tests with a bare repository; with it the size check is skipped). `src` is the flat export directory: top-level files go to `runs/<run_id>/`, its `cases/` subdirectory to `cases/<run_id>/`. The rewrite (`runs/index.json` rows with the `RunIndexEntry` fields copied from `run.json` / `gate.json`, newest 200 runs, `cases/` + `report.html` for the newest 20 by `created_at` then run id, `manifest.json`) follows D300; a run directory without a valid `run.json` is deleted. The 1 GB check uses the GitHub REST API through `httpx` (`size` in KB, token as a header) instead of `gh api`, fails closed above 1 GB and open when the size is unavailable. The heartbeat payload must be at most 64 snake_case fields with string values of at most 1000 characters
