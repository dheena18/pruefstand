[T3.4b, rag-demo fixed-token sub-chunking, owner-approved 2026-11-16] `RagConfig.chunking` (`ChunkingCfg`, default `per_section`) replaces the "chunking strategy" comment of interfaces §16. `fixed_tokens` (size 64-4096) cuts each corpus chunk into pieces of at most `size` tokens of the embedded text (citation key included in the budget, no overlap), at the last sentence end in the second half of the window, else hard. Sentence ends skip German legal abbreviations (Abs., S., Nr., Art., Buchst., i.V.m., ggf., z.B., bzw., vgl., etc., u.a., d.h., sog., Rn., Var., lit., Hs., Alt., ...) and ordinals/list markers; a hard cut never ends on an abbreviation or "§". The stored and retrieved piece `text` is the body only, the citation key is prepended at embedding time (`index_text`), so `evidence_recall` can never match on the prefix (tested). A chunk that fits keeps its `chunk_id`, longer ones get `<chunk_id>#p<n>`; doc ids, tenant and `corpus_version` are unchanged so gold doc ids hold. The default leaves `config_hash` of every committed config unchanged (`chunking` is dropped from the hashed dump while it equals the default); a non-default value changes it. The collection metadata records `chunking`, a non-default chunking adds `__ft<size>` to the collection name, and a retriever refuses an index built with another chunking (an index without the key counts as `per_section`). Token counts use the embedding model's `tokenizer.json` when configured (`RAG_EMBED_TOKENIZER`), else the word-and-punctuation lower bound, so tier-1 pieces can be longer in real tokens than `size`.
