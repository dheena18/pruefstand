[T6.2a S4b, `llm-proxy` option details] Within the interfaces §1.5 policy: a sampling key (`temperature`, `top_p`, `num_predict`) that the tag's catalogue entry gives **no** `option_bounds` for keeps the catalogue default (the client value is ignored, e.g. `bge-m3` has no bounds); `seed` passes when it is an integer (no bounds needed); a non-numeric or boolean value is out of bounds (403). The route must match the tag's role (`/api/chat` generator tags, `/api/embed` embed tags). `GET /health` needs no key (counters only, reachable only from `gate-net`); `PUT`/`DELETE`/`HEAD` and any query string → 403. A body without `Content-Length` or above 4 MiB → 403 unread (no chunked bodies). Upstream timeout 900 s (generation on the 27B generator; the runner rule D624 keeps client timeouts above 300 s). Stdlib only (no new dependency); the policy lives in `llm_proxy_policy.py` (pure, unique module name per D232) next to `llm_proxy.py`
