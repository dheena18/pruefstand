[T7.1c, owner-merge; completes D1290] The CI `test` job in `ci.yml` fetches the mutation `base_sha` before `make coverage`:
- the command is `git fetch --no-tags --depth=1 origin <base_sha>`;
- the SHA is read from `benchmarks/mutations/index.yaml` with `sed`, so it cannot drift;
- only that one commit is fetched, not `fetch-depth: 0` for the whole history;
- no new action and no pin are added, and `persist-credentials: false` stays (an anonymous fetch from the public repo);
- it takes seconds, inside the job's 25-minute limit (D1308).

`test_base_sha.py` now **fails** when `base_sha` is missing and `CI=true`, and skips only in a local shallow clone. So the "every patch applies at `base_sha`" rule is enforced on every PR.
