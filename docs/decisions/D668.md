[T8.2b, cases] The build embeds only page 1 of the default view of shard 0 (and its length and failing count), not the whole shard, in the static HTML and the `<Suspense>` fallback; the client fetches shard 0, then shards 1+ in parallel, and the build-time copy counts as part 1 until the runtime copy arrives. `?failing` is absent for the default ("Failing only" when a failing case exists, else all), `0` or `1` otherwise. The detail panel and the static case page are one `CaseDetail`; the baseline answer is looked up in the baseline run's shards in order (client: on demand; static page: at build) and `Baseline not exported` covers a null, unexported or shard-less baseline. Below 1024 px the panel replaces the list and the heading takes focus.
