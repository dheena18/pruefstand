[T3.5, retrieval package] `rag_demo/retrieve.py` is deleted; `rag_demo/retrieval/` holds `filters` (`allowed_tenants`, `tenant_filter`), `query_builder` (`build_query`, pure, returns a frozen `QdrantQuery`), `bugs` (the seeded M8/M9 code paths, unchanged behaviour), `store` (`QdrantStore`), `corpus_meta` (`CorpusMeta`), `rerank`, `retriever` (`QdrantRetriever`) and `testing` (`assert_tenant_scoped`, reused by T3.7 and T7.1a). The tenant filter is built once, in `filters.tenant_filter`; `build_query` is the only builder the retriever calls for the main query. With `tenant_filter: inside` every prefetch **and** the top-level query carry the filter (defence in depth); `assert_tenant_scoped` accepts the object or the recorded wire body and fails on a missing, partial, `should`, shared-public-only or extra unfiltered leg. `allowed_tenants` raises `ValueError` for a malformed tenant (lower-case slug, <= 64) and, when given `known`, for any tenant outside it; the API keeps checking membership against the collection metadata (422)
