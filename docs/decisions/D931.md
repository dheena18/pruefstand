[T5.4, pass rule outcome states] The pass rule (D146) yields `passed`, `failed` or `pending` per judge and metric: `failed` when any evaluated criterion fails (kappa, hard-negative specificity, Wilson lower bound or discrimination per edit type), `pending` when every evaluated criterion holds but a required gating set (here `legal_hard`, T5.3 PR 2) is not built. `pending` is never a pass: `calibration_status.yaml` then has `passed: false` (judged metrics informational, W3.8) and `status: pending`. The rule refuses `dev` items and the selection helper refuses `test` items (AI13-12). `calibration_status.yaml` keeps the `epoch` key (= `judge_epoch`, read by `pipeline.fingerprints`) and adds `status`, `refusal_judged.reasons`, `prompt_versions`, `prompt_versions_tried` and a `judges:` block (serving, per-metric outcome, `drift_threshold`, `a0`, `flip_rate_upper`). The first calibration writes `epoch: 1`, so `eval_fingerprint` changes once (no baseline exists yet for tier 2).
