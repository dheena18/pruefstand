[T1.12, Action image] `action/Dockerfile` follows the T0.3 template and needs the **repository root** as build context (it installs `pruefstand` from the workspace); GitHub builds a `uses: ./action` step with `action/` as context, so that form works only after T9.1b publishes the image and `action.yml` points at it. Until then `action-selftest.yml` builds the image from the root and runs it with `docker run --network host --user "$(id -u):$(id -g)"` (uid 10001 cannot write the runner-owned workspace; CLAUDE.md section 8 keeps the non-root user). `action/entrypoint.py` reads `INPUT_*`, calls the CLI through an injectable `invoke` (subprocess with argument lists in production; the unit tests run the real CLI in-process under respx with the T1.10 recordings), exits with the gate exit code and rejects an empty `baseline-run`, a missing file or an unknown `tier` with exit 2. The unit test asserts the title `## Prüfstand tier 1: ✅ PASS` (the renderer titles every `stack=live` run so), not the prompt's older `## Prüfstand: ✅ PASS`
