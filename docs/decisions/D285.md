[port set superseded by D325 (ADR-0018): rules name only `172.17.0.1:11434`] [R12 integration 3, amends N4.2] Packets from a container to the host address `172.17.0.1` are delivered locally and traverse `INPUT`, not `FORWARD`/`DOCKER-USER`. `pruefstand-firewall.service` therefore installs the accept-from-`10.231.0.0/24` / drop pair for `172.17.0.1:11434/11435` in **both** Docker's `DOCKER-USER` chain (container-to-container and egress) and a dedicated chain `PRUEFSTAND-INPUT` jumped to from `INPUT`; it flushes only `PRUEFSTAND-INPUT`, inserts into `DOCKER-USER` only when `iptables -C` misses the rule, and never flushes or reloads the ruleset (`nftables.service` stays disabled). `vm_check firewall` checks both chains and the behavioural probe
