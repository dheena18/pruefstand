[T8.3, C-SHARD-ERROR mechanism, UI11-18] Probe result (Playwright 1.49.1 at the time, Chromium, 2026-11-10, `e2e/offline-probe` run once and deleted): a request intercepted by `page.route` BEFORE `context.setOffline(true)` and continued AFTER it fails (both delayed shards of the `D-MANY` run turned into two `C-SHARD-ERROR` alerts, no shard stayed loading). So the **primary** mechanism is used: shards 1+ delayed (`e2e/delay.ts`), `setOffline(true)`, release, shard error asserted, `setOffline(false)`, Retry, shard loaded (`states.populated.spec.ts`). Without the delay the test fails at its first wait (the held requests never appear), which is the negative control
