[T6.2a S4b, issue #150, extends D252] `llm-proxy` enforces a 4th setting besides the allow-list, `num_ctx` and `keep_alive`: every `POST /api/chat` is forwarded with `"think": false` (absent, `true`, `"high"`, `null` or any other value is rewritten), so CLAUDE.md §5 / D95 (thinking always off) holds on the gate whatever the candidate config says. **Rewrite, not 403**, like `num_ctx`: a candidate that sends `think: true` (or omits it) still gets a valid, comparable run instead of an error-rate failure that would blame the config wiring rather than the app behaviour, and it matches how the proxy already normalises load-time fields. `/api/embed` is unchanged (`think` stays a 403 key there) Note (L1): Ollama's `ResolveThinking` replaces `think: false` for models whose metadata says thinking cannot be turned off (gpt-oss / Harmony), so such a tag must never be a generator: `build_policy` refuses a generator whose `family`/`ollama_family` is `gpt-oss`/`gptoss` (test), and the catalogue must not list one with role generator.
