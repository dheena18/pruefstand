[T6.2a S9, review #202: runner unit privileges and hooks] `pruefstand-runner.service` sets **no** `NoNewPrivileges=` and none of the directives that imply it (systemd.exec(5): `SystemCallFilter=`, `RestrictSUIDSGID=`, `PrivateDevices=`, `ProtectKernel*=`, `MemoryDenyWriteExecute=`, `LockPersonality=`, `DynamicUser=`, ...): the preflight repairs a dropped tunnel in the job with `sudo -n systemctl restart pruefstand-tunnel` (the one sudoers rule, D200/D227), and sudo refuses under no_new_privs, so with it the D226 repair-and-retry could never succeed. Chosen over moving the restart out of the job (e.g. a polkit rule or a root timer) because it keeps the reviewed sudoers design and the in-job repair the retry rule relies on; the protection lost is small, since `pruefstand` is in group `docker` (root-equivalent) and candidate code runs only in the sandboxed container. `test_host_privileges.py` keeps the unit, the sudoers rule and `preflight.RESTART` consistent. Also: `job_cleanup.sh` runs with `set -f`, reads collection names line by line (never globbed) and wipes `GITHUB_WORKSPACE` only when it is a canonical directory below a runner `_work/` dir (no `.`/`..`, no symlink: `realpath` must equal it); the hooks run from a stable clone `/home/pruefstand/pruefstand-gate` of the private repo, never from a job workspace (runbook §0 step 6).
