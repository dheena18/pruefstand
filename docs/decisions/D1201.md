[GitHub Models replacement, code; owner decision 2026-11-15 via the lead] One backend switch for public-text datagen: `PRUEFSTAND_DATAGEN_BACKEND` = `vm` (default) \| `github` (`PruefstandSettings.datagen_backend`, typed, not a secret). `vm` = the VM CPU model of D1200, id `openai_compatible_local/ministral-3-14b-instruct-2512` (8B pin also allowed), reached at its own `PRUEFSTAND_DATAGEN_BASE_URL` (default `http://127.0.0.1:18091/v1`, loopback http only; never the judge URL) and checked once before any call through `/v1/models` (`pruefstand.dataset.vm_datagen.check_vm_served`; llama-server echoes the requested name, so the answer's `model` proves nothing), so a batch never lands on another server and nothing is cached under the pin from another model. Review round: the VM client sends one request at a time (`effective_concurrency`), with a 900 s timeout and NO transport retries (a resend would bypass the request budget); a `github/` model without a token is refused with "GitHub Models is retired (2026-07-30, D1202)". `github` keeps the old ids for old ledgers. Users: `scripts/generate_qa.py` (T4.2, `--model` default from the switch, GitHub token only for `github/` ids), the T4.2 live recording test, the T4.5 recording test (`PRUEFSTAND_PERTURB_REWRITE_MODEL` may be the VM pin; the token is needed only for a `github/` rewrite model), `record_cassettes.sh --dataset/--perturb`, and `indomain_cli generate` (T3.1b). Guard rules: `check_datagen_model` accepts exactly the pinned VM ids among local models (anything else local stays refused) and still refuses `qwen`/`gemma`; `datagen_policy(provider)` allows one provider; LLMPolicy is unchanged. Data rules (ADR-0019, D328-D332 checked): the model is local, so policy would allow private text, but this decision uses it for PUBLIC text only (generate_qa still skips private and attack chunks); private docs and canaries stay on the local judge `gemma3:12b` (D330) until the owner decides otherwise. Findings of D1200 folded in: `indomain_gen` asks the VM model with `response_format` json_schema (`GEN_SCHEMA`, evidence span 20..400 characters; fence-tolerant parsing kept for builds that ignore it; to be confirmed on the live server after the VM reboot), and `indomain_cli generate --retries N` (default 2, `indomain_retry.py`) regenerates an invalid item up to N more times (attempt 0 greedy, temperature 0 seed 42; a retry samples at temperature 0.7 seed 42 + k, because a greedy retry returned the identical answer live); every attempt is one call against `--max-calls`, cached under `<id>#retry<k>-t0.7-s<42+k>` (attempt 0 keeps the plain `<id>` key, with no temperature or seed in it, so old caches stay valid; changing the attempt-0 temperature or seed later needs a new prompt version or a key change), counted in the summary line (calls, retries, exhausted items); `generation`/`assemble` take the first valid attempt. Gaps (follow-up): no second-family checker is reachable without GitHub Models (`indomain_cli check` for `assemble`, `generate_qa --cross-check`); an Ollama path for `ollama/gemma3:12b` is the candidate.
