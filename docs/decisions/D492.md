[T3.4, encoders] `rag_demo/dense.py` is deleted; `TeiDenseEncoder` (tier 1) and the new `OllamaDenseEncoder` (tier 2) live in `rag_demo/index/encoders.py`: batch 32 (was 16), timeout, 3 attempts with 0.5 s / 1 s backoff on connection errors, timeouts and HTTP 408/425/429/5xx, no retry on other 4xx, then `EncoderError` (subclass of `EmbeddingError`, so the API still maps it to 503). Ollama: native `POST <url>/api/embed` only, body `{model: <bare tag>, input, truncate: true, options}`, never `keep_alive`; `options` = the catalogue entry's `options` exactly (`wiring.catalogue_options`, integer keys sent as integers) so Ollama does not reload the model, and `options.num_ctx` must equal `embed.max_input_tokens` (`ConfigError` otherwise). Vectors are checked (count, dimension, non-zero) and normalised to unit length. The bearer header (D216) is read once at construction and never appears in logs or errors; Qdrant errors strip `QDRANT_API_KEY` from the shown body. `PendingOllamaEncoder` (D455) is removed: tier-2 queries now embed with `OllamaDenseEncoder`
