[T6.2b S3a, baseline promotion order] `gate_orchestrator/promote.py` (pure) builds the commands of `baseline-promote.yml` and reads the exit codes: `main` and `nightly-b<k>` run `pruefstand gate --candidate <run> --from-store --ref <ref>` first and then `pruefstand baseline promote --run <run> --ref <ref>` (promote refuses a run without a bound `gate.json`, D881); a release run (`release-b0..b2`) is never gated and goes straight to promote (D321). Promote exit 0 = promoted; 1 = refused (FAIL, hard fail, a concurrent promote): reported in the job summary and heartbeat and recorded as processed, so the run is not retried on every poll; 3 = integrity error: recorded and the owner is alerted; any other code is transient and retried on the next poll. The owner's override of a failed gate stays a manual step (runbook 3a): a test fails if that flag appears in any file under `infra/gate-executor/**` or `.github/workflows/**`.
