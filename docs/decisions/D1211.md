[Decision log layout, owner request] **One file per decision.** Why: every PR appended a row at the end of the one big table in `docs/decisions.md`, so any two open PRs conflicted there (a recurring merge conflict across the parallel agents). Layout: `docs/decisions/D<n>.md` holds one decision (front matter `id`, `section`, optional `supersedes`, `adr` as JSON strings, then the text verbatim); the 683 rows that existed were migrated loss-free (multiset of `(id, text, extra columns)` and every rebuilt row line identical to the old line, checked by `decisions_migrate.roundtrip_problems`; no duplicate id existed). `docs/decisions.md` is now a short hand-written page (rules, section provenance, the 63 task rows from before decision numbers, pinned versions, open questions). The single sorted log is **generated, not committed**: `scripts/build_decisions_index.py` writes `docs/decisions-log.md` (git-ignored), the mkdocs hook `on_pre_build` in `scripts/mkdocs_hooks.py` builds it for `make docs`, and `--stdout` prints it for pasting at session start; a committed index would conflict again whenever two PRs add rows. Guards (`scripts/tests/test_decisions_unique.py`, `build_decisions_index.py --check`, also run by `make docs`): every file parses, `id` equals the file name and is `D<number>` without leading zeros, ids are unique (case-insensitively), only `D<n>.md` files live in the directory, and no `| D<n> |` row may be left in `docs/decisions.md`. Gaps in the numbers stay allowed (reserved ranges). Branches that still append an old-style row: after merging `main` run `build_decisions_index.py --migrate-pending` (idempotent; moves the rows into files, refuses on an id clash with different content). New rule for tasks: "create `docs/decisions/D<n>.md`", never append to `docs/decisions.md`.
