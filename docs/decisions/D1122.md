[security fix F5, major; supersedes the parquet-reader transport and limits of D890] A 755-byte parquet with one `list<null>` row of 25 M elements passed every check (Arrow `nbytes` barely counts null/bool list items) and the parent unpickled a ~500 MiB list. Now: (1) list items are counted on the Arrow arrays of every column type (all nesting levels, lists, maps, structs) before any Python object is built; a row above `OldpLimits.max_list_elements` (100 000) is one `record_too_large` (in the child and in process); (2) the child checks every row before sending (str/int/float/bool/None, dates/times/timedelta, Decimal, dicts/lists of them; texts up to `max_record_bytes`; depth 8) and an unsupported value is one `bad_record`; (3) **no pickle**: the child writes JSON event lines (`ingest/records_wire.py`, tagged values for dates/Decimal/mappings) and the parent (`ingest/records_proc.py`) never unpickles; it caps the line (2 x `max_record_bytes` + 1 MiB), the total output (`max_parquet_output_bytes`, 1 GiB), the rows (never more than the budget sent), texts, list items per row and nesting, checks the exact event shape and accepts the reported row budget only if it is not more than sent minus received; a violation is one counted `reader_protocol` problem; (4) `RLIMIT_AS` soft = hard, plus `RLIMIT_CPU` soft = hard (`max_parquet_cpu_seconds`, 600) and a wall timeout enforced by the parent (`max_parquet_wall_seconds`, 900 s); over either the file ends with one counted `read_timeout`; (5) the child gets a minimal environment: `PATH`, `HOME` and the `ARROW_`/`MALLOC_`/`OPENBLAS_`/`OMP_`/`MKL_` variables only (no secrets). Opus review round 1: (6) the parent decodes each line as strict UTF-8 (anything else is `reader_protocol`; `json.loads` on bytes would accept UTF-16/32), then, before `json.loads`, counts JSON values outside strings (`,` `[` `{`; strings counted by their quotes, scanned one match at a time) and refuses a line with more than 4 x `max_list_elements` + 1024; what remains is the string bytes (line cap) and one number object per counted value; (7) mapping keys count against `max_list_elements` with list items, in the child, in process and in the parent; (8) `list_view` / `large_list_view` are counted, any other nested or dictionary Arrow type is not read (`record_too_large`); `clean_row` (`ingest/records_clean.py`) also runs in process; (9) `RLIMIT_CPU` is soft N / hard N+1 so the reader gets `SIGXCPU` (reported `read_timeout`); (10) the reader runs in its own session and is stopped with `killpg`; (11) limits fail closed: when the memory or CPU limit cannot be set the file is not read (one `memory_limit`) unless `OldpLimits.allow_unlimited_reader`; (12) the wall budget counts only time spent waiting for the reader, not the caller's time on a yielded row (`records_proc.Watch`, injected clock). Regression: the 25 M-element file (1016 bytes) is generated in `test_oldp_child_hardening.py` and must end as one `record_too_large` with a traced Python allocation peak below 64 MiB.
