[model dir, `KV_CACHE_TYPE` and datagen mode superseded by D328/D330 (ADR-0019)] [ADR-0018, owner facts 2026-10-31, `docs/ops/setup-log.md`] **One Ollama server** on `cairo-s101lp` serves both A40s on `127.0.0.1:11434`: `CUDA_VISIBLE_DEVICES=0,1`, `OLLAMA_MAX_LOADED_MODELS=3`, `OLLAMA_NUM_PARALLEL=4` (server-wide), `OLLAMA_KEEP_ALIVE=24h`, `OLLAMA_MODELS` on the NAS (T0.6 C4 verifies the existing server's model dir). The running server is reused when healthy; `start-ollama.sh` starts one with `setsid nohup` only if none runs and never a second; modes day/night/datagen are API loads/unloads only (`keep_alive: 0`), datagen loads llama 70B alone and Ollama splits it over both cards. `OLLAMA_GPU0_URL` and `OLLAMA_GPU1_URL` stay two settings (code unchanged), both `http://127.0.0.1:11434` on the VM. GPU placement is Ollama's: `health.sh` requires `size_vram == size` per model via `/api/ps` (exit 15 otherwise, also for a model on both cards outside datagen) and reports the card per model. Wrapper ops `start-ollama`, `stop-ollama` take no mode/GPU argument; `stop-ollama.sh` stops only a server the scripts started. Template keys `OLLAMA_CONTEXT_LENGTH_GPU0/1`, `OLLAMA_SCHED_SPREAD_DATAGEN`, `OLLAMA_BIN_GPU0/1` dropped (`OLLAMA_BIN` stays).
