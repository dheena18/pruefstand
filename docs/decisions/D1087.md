[T6.2a S2, review of #139] (1) `select_jobs` fails closed on repo identity: a PR whose head or base repo name is missing or null (deleted fork, incomplete API data) is treated as a fork, so it is gated only when `gate/pr-N` was mirrored at the current head; otherwise `pending` "fork head moved since mirroring; re-run mirror_fork_pr.sh". Same-repo needs both names present and equal. (2) One parser for `state/nightly_counter`: `pruefstand.pipeline.select` now exposes `nightly_counter_path(env)` and `read_nightly_counter(path)` (ASCII digits only, bounded read, regular file, missing = 0, `ConfigError` otherwise; default `~/pruefstand/state/nightly_counter` when `PRUEFSTAND_HOME` is unset), and the orchestrator's `state.read_counter`/`nightly_counter_path` delegate to them, so the writer (executor) and the reader (`pruefstand run --block auto`) can never disagree about a value. The atomic `increment_counter` stays in the orchestrator.
