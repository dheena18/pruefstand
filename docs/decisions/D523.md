[T5.1, cache key] Key = interfaces §8 with `model_version` = provider version + `#e<epoch>`. Version probe once per model and run: Ollama `tag@digest[:12]` from `/api/tags` (warning when it differs from the catalogue pin), llama.cpp hash of `/props` `model_path`, GitHub Models from the first response (so the first GitHub call per model and run is never a hit); a failed probe leaves the version empty, the call that follows reports a real outage. Interface change (flagged): `LLMClient` gains keyword-only `retry` and `epochs`; `cache_epochs.py` (`current_epoch`, `invalidate_judge`, `clear_drift`, `read_drift`) works on `cache_epochs.json` / `judge_drift.json` in `PRUEFSTAND_CACHE_DIR`; epoch != `judge_epoch`, never in `eval_fingerprint`. Review fixes: for `ollama/` the version string also carries a hash of the effective catalogue options and `think=false` (a changed `num_predict` misses without a new digest); a probeable provider (Ollama, llama.cpp) whose version is unknown neither reads nor writes the cache; `complete_json` caches only validated answers, empty answers are never cached; `build_client` requires a `canaries` argument and refuses None (fail closed); a `Retry-After` above the cap ends retries for local providers too; an exhausted fallback is marked exhausted
