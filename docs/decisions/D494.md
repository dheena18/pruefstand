[T3.4, corpus reader, layout] The corpus reader streams `<tenant>.chunks.jsonl` line by line, validates each line against the shipped schema copy `rag_demo/index/chunk.schema.json` (byte-equal to `schemas/chunk.schema.json`, tested; it sits beside the code because `rag_demo/schemas.py` already exists, so a `rag_demo/schemas/` directory would shadow nothing but confuse imports) and fails with `<file>:<line>: ...`, also for invalid JSON and for a row whose `tenant` is not the file's tenant. `rag_demo/index.py` became the package `rag_demo/index/` (`corpus_reader`, `encoders`, `indexer`, `naming`, `qdrant_admin`, `tokens`, `fetch_tokenizer`); the package re-exports nothing. The tiny test corpus `apps/rag-demo/tests/fixtures/corpus/` (40 real chunks of `corpus/slice_v1`, 4 tenants, own manifest) lets app tests run without reading `corpus/` of the repo root. `make index-slice` runs `rag-demo index --collection slice_v2` and then only snapshots; a snapshot restore re-creates `chunks_active` (`tests/integration/conftest.py`)
