[T2.6, review fixes; OWNER DECISION to accept the threat-model limit in (3)] (1) Semantic values are distinctive: every template range starts at 101 (checked at load), units are Tage / Minuten / Basispunkte / Euro / kWh, and `ingest`, `validate_canaries.py` and `make_heldout_canaries.py` (`--corpus`, plus the approved documents) test every semantic pattern against all text outside the canary's own document, public and private (`pipeline/canary_collision.py`, prefiltered on the NFKC/format-stripped text); any match fails. The pattern uses a lookbehind `(?<![\w.,])` and word-bounded unit endings, so `1.113 Tage`, `4,113 Tage` and `113 Tagessätze` do not match. (2) `HELDOUT_SEED` must be 32+ hex characters or 39+ decimal digits with at least 8 distinct characters (128 bits). (3) Held-out documents carry ids `priv-<tp>-<nn>` that continue the public numbering, the same front matter and metadata shape, and their own plausible title (never the source's, heading included). THIS DOES NOT HIDE THEM from a candidate that reads or diffs the executor corpus against the public repo (doc-id set difference, text diff of near-copies of approved documents): the held-out set guards against hard-coded registry values, per-id filters and memorised public canaries only. The executor must not expose the corpus to candidate code beyond the retrieval API; the owner confirms this in T6.2a. (4) The generator plans all tenants with one shared set of used values, independent of `--tenant`.
