[T4.6, wiring and `attack_set_version`] New optional `corpus.yaml: attacks {seed, seeds_per_tenant (8), placements (all six)}` (`core.config.AttacksConfig`, like `private_docs`); committed `corpus.yaml` uses seed 7 and 8 payloads: 6 x 8 x 3 = 144 documents. `ingest._extra_documents` returns the documents (source `attacks`, customer tenants only; the check in `_checked_extras` keeps `shared_public` out), `pipeline/attack_set.py` flags their chunks `is_attack=True` and prefixes them with `Titel: <title>` (and `Autor:`), so a payload in a title is indexed (private chunks are NOT prefixed: T2.6 behaviour unchanged). `attack_set_version` = `atk-<12 hex>` over the GENERATED set (sorted document id, marker, title hash, text hash, tenant, and whether markers are public), so a change to a template, the marker draw or the data changes it; `sources["attacks.markers_public"]` is `true` or `false` (compared by `check_attack_versions` as well, which with `expect_secret_markers=True` fails on public markers); `CorpusManifest.sources["attacks"]` holds it and `check_attack_versions(sources, prompt_versions)` fails with `DatasetError` when `DatasetManifest.prompt_versions["attacks"]` differs (T4.7a calls it). `check_injection_set` runs in `ingest`: every marker (decoded for base64) in exactly one attack chunk of its tenant, none in `shared_public`, markers unique, all question words (4+ letters) in the document.
