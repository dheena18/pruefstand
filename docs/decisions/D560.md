[T3.1e, wrapper op `log [N]`, ADR-0019 addendum] The wrapper `pruefstand-cluster` gets the third read-only op (after `status` and `show`; the seventh op overall) `log [N]` (`N` an integer 1..1000, default 200, anything else exit 64; at most one argument). Like `status` and `show` it needs no lock, no `MAINTENANCE` and no allow-list entry, and it is the only change next to sudo: the sudoers file and the sudo rule are byte-identical (one wrapper path, `env_keep` of `PRUEFSTAND_LOCK_HELD`). It runs `bash <bin>/log-tail.sh <N>` on the cluster; `cluster_ssh.sh` `cluster_op log [N]` mirrors it with the same checks
