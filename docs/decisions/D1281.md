[T6.2a, owner decision for M4] `infra/gate-executor/host/runner-env-keys.sh` also creates `QDRANT_READ_ONLY_API_KEY` (`openssl rand -hex 32`) in `/home/pruefstand/runner.env` when it is missing. The safety rules are the same as for `PRUEFSTAND_NONCE_KEY` and `PRUEFSTAND_CANDIDATE_API_KEY` (D1267):
- no value is ever printed;
- the file has mode 600;
- an existing line is never overwritten;
- an empty line for the key is refused.

The owner never types this key. The same value reaches two places:
- the executor Qdrant reads it as `QDRANT__SERVICE__READ_ONLY_API_KEY` (`compose.executor.yml`, D1089);
- the orchestrator passes it into the candidate as its `QDRANT_API_KEY` (D1098).

`QDRANT_API_KEY`, the read-write key, is not generated by the script.
