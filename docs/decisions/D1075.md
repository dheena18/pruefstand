[T6.2a S4b, re-review of #137] Trickling clients: each connection carries one request (`Connection: close`) and must deliver request line, headers and body within `request_deadline_s` (60 s) in total, else its socket is shut down (the 30 s idle timeout alone restarts with every byte); the deadline is cancelled once the request is read, so upstream generation is never cut. Two connections beyond the cap of 32 are reserved for `GET /health` only (anything else there → 503), further ones are closed unread, so the orchestrator can always read the counters. Connection errors are logged by type only. The image now ships all four proxy modules (`llm_proxy_json.py` and `llm_proxy_server.py` were missing from the Dockerfile; a test checks every `llm_proxy*.py` is copied). Notes: `think: true` is forwarded unchanged (D252, sampling/behaviour fields pass), so CLAUDE.md §5 "thinking always off" is enforced by the rag-demo config (`enable_thinking: false`, D95), not by the proxy; JSON schemas under `format`/`tools` whose keys collide after casefold get 403 (an availability limit only)
