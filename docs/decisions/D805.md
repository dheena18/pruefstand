[T5.2b, pipeline wiring] `pipeline/run.py` shrinks to the flow; `pipeline/plan.py` (`Plan`, `complete_manifest`, `store_run`), `pipeline/abort.py` (aborted runs) and `pipeline/judging.py` (`JudgeSetup`, `prepare_judging`, `checked_pool`) hold the rest. `build_judge_pool(cfg, mode, *, tier, budget, recorder, canaries, cache)` builds the real pool through `judges.factory.build_pool` and `llm.factory.build_client`: every judge client shares the **runner's** budget, one `CallRecorder` and the canary registry. Canaries come from `store.canary_source.load_canary_registry`; an unreadable registry is an empty one for a local judge and **fails closed** (judges skipped, `judge_mode=skipped`) for GitHub Models. The `llm` cache namespace opens like the target cache (same trust rules, `target_cache(namespace="llm")`). `RunManifest.judge_fallback = fallback_used(recorder.rows)`; the call log is stored as `llm_calls.parquet`. A missing `PRUEFSTAND_NONCE_KEY` in a judged run is a `ConfigError` (exit 2), not a silent skip
