[T5.4d, drift anchors] Follow-up of D945. The stored verdict of a drift anchor is the **majority of 5 runs** (`judges.drift.majority_scores`, ties to the earliest run; `AnchorItem.majority_runs`, default 1 = T5.4 files), and the flip rate is counted on **4 further runs** against it (`count_flips`), so stored verdict and flip rate come from different runs (D934 rule otherwise unchanged: Wilson upper bound, smallest c >= 5 with P(Bin(50, f_upper) >= c) <= 1 %, cap 10). Screening run (`gemma3:12b`, 9 runs, cache bypassed, 4 in flight; `results/rq2/anchor_flips_screen.json`, every run's scores kept): the two T5.4 flipping anchors a00 / a02 are odd in one run of 9 (8 of 9 equal), a04 (`faithfulness_constructed:f4824f68f7e37f53`) is genuinely unstable (score 2 in 3 of 9 runs, 1 in 6; 4 counted flips), threshold 8. An anchor whose modal share is below 0.8 is unstable (`unstable_anchors`) and replaced in place by a spare of the same metric and stratum drawn with seed + 1 (`anchors.py --screen`); the other 49 stay. Second run (new set, 9 runs): 1 flip in 200 counted comparisons (rate 0.005, Wilson upper 0.028), `a0` 1.0, changed anchors 2 (a00 odd in run 2, a02 odd in run 9) -> `drift_threshold` **6** (P(Bin(50, 0.028) >= 5) > 1 %), not 5; written by `report.py` to `calibration_status.yaml` (`drift_threshold: 6`, `a0: 1.0`, `flip_rate_upper: 0.028`). No further screening (no fishing for 5). Over both 9-run passes (18 runs) a00 and a02 each differ in about 1 of 9 runs and a00 takes all three scores 0 / 1 / 2, so the flips still sit on 2 anchors: the D945 caveat is mitigated (majority verdict, counted runs separate, the 3:6 anchor replaced), not resolved. The Wilson bound is taken over comparisons and treats the repeats of one anchor as independent; an anchor-level bound (1 changing anchor of 50 -> Wilson upper 0.105) would make the judge unfit, but for false alarms the per-anchor binomial is conservative (the expected number of changed anchors per night is about 0.2), so threshold 6 is safe. `a0` is now the agreement of the first counted run with the stored majority, which supersedes D934's "run 2 vs run 1" for majority anchor files (still recorded only, D253). Epoch (D934/D945, D947 superseded by D1000): anchors and threshold only decide the nightly drift flag, they change no judged verdict and no judge prompt, so `judge_epoch` stays 1 and `eval_fingerprint` is unchanged (it reads `epoch` only); the lead decides if a bump is wanted anyway. Caveat: replacing an unstable anchor makes the anchor set more stable than the judge is on average (selection effect); its instability stays documented here. The drift cassettes were re-recorded from real calls (a04 replaced).
