[T5.2b, metrics] Four judged metrics in `metrics/judged/` (`Faithfulness`, `AnswerCorrectness`, `PerturbationConsistency`, `RefusalJudged`), `version = "1"`, `higher_is_better=True`, all on `JudgedBase`. A judge failure is **not** caught in the metric: `LLMError` / `PolicyViolation` / `QuotaExhausted` / `BudgetExceeded` propagate and the runner (`JudgeStage`, single owner, D9-07) turns them into `status="error"` (error type only), `judge_error`, `judge_degraded`. The metric value keeps the normalised score and `raw_score`, never the judge's `reason` (it can echo canary or private text). `MetricRegistry.full(top_k=None, refusal_judge=None)` is the registry of `run_eval`; `default()` stays the 16 deterministic metrics so existing tests and the T1.5b drift check hold; the gate takes its directions from `full()`. The adapter has no `top_k` setting, so the faithfulness fallback "first `top_k` returned chunks" takes every returned chunk unless the registry is built with a `top_k` (follow-up)
