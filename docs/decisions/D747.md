[T4.7a, stage layout] `build_dataset` runs six stages, `generate -> filter -> perturb -> attacks -> splits -> validate`, each writing `<work_dir>/<name>-<version>/stage_<n>_<name>.jsonl` (git-ignored) plus a `.meta.json` with the SHA-256 of its inputs (its settings and the digests of the files it reads); writes are atomic. `--resume` skips a stage whose output exists, whose meta hash equals the current input hash and whose file digest matches; `--stage S` runs one stage on the earlier outputs; `--only <prompt id or version>` restricts `generate` to one prompt and keeps the candidates of the others (the regeneration loop of T4.7b). `generate` keeps a per-unit ledger (`generate_ledger.jsonl`, D784) so a quota stop continues where it stopped; `generation.candidates_from` takes the candidates of an earlier `scripts/generate_qa.py` run instead of calling a model. Only `validate` writes `<out_dir>/<name>/<version>/`. `build_dataset(cfg, *, stage, only, resume, clients, root) -> DatasetManifest`; `run_build` also returns the report (`build_report.json`: counters per stage, `dropped_mixed_license`). The model review is NOT a stage: it needs the finished splits. |
