[T3.6a, client disconnect] `/v1/query` races the generator call against the ASGI `http.disconnect` (`rag_demo.disconnect.cancel_on_disconnect`): when the client hangs up the generation task is cancelled, which closes the upstream httpx connection so Ollama stops the queued or running generation, and the app answers 499 (nobody reads it; `ClientDisconnectedError` is internal). Only the generation is cancelled; the retrieval thread runs to its end. The regression test runs the real app under uvicorn against a loopback server that records the closing of the upstream connection (events, no sleeps). The D624 gate rule (tier-2 runner `timeout_s` > 300 s or `concurrency` <= 4) is a committed-config check in `test_committed_configs.py` for every gate config with the `core` split under `examples/**` and `apps/**/configs/**`; none exists yet. Open for T6.2a: the tier-2 gate config itself, a runner that does not retry a read timeout (today `max_retries` applies to it), and the root `pruefstand.yaml` template (splits with `core`, `timeout_s` 60, `concurrency` 8) which would fail the rule if it were scanned
