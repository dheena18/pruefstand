[T1.5b] New dependency `regex` 2026.9.29 (locked; Apache-2.0 with CNRI-Python parts) and dev stubs `types-regex`: `re:` forbidden patterns are searched with `regex.search(..., timeout=2.0)` because the haystack is the candidate's answer and Python `re` has no timeout; a timeout is `status=error` (`forbidden_match_timeout`). A structural check on the `re` parse tree rejects nested unbounded repeats and alternations inside unbounded repeats at compile time; the timeout covers polynomial blow-ups that check cannot see. ONE budget (2 s) per metric evaluation is shared by all patterns and texts, and regexes read at most 100 000 characters per evaluation. `regex` measures CPU time of the matching thread, not wall time: with several threads a case can hit `forbidden_match_timeout` early, so T1.8 must serialise regex matching or add a wall-clock guard.
