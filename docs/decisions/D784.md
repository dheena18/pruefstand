[T4.2, resume and quota] `scripts/generate_qa.py` keeps `ledger.jsonl` (one line per finished unit, appended and flushed as units finish, a damaged last line is ignored) next to `candidates.jsonl`, `cross_check.jsonl`, `validation.jsonl`, `summary.json` in `datasets/_work/<run>/` (git-ignored). A re-run sends only units without a ledger line, so it makes no request and writes an identical `candidates.jsonl` (sha256 recorded in `summary.json`). The ledger, not the LLM cache, gives that guarantee: by D523 the first GitHub Models call of a client is never a cache hit (the cache key needs the version the first response reports). `QuotaExhausted`, `BudgetExceeded` (`--max-requests`) or an outage stop the batch cleanly (counters `quota_exhausted`, `budget_exceeded`, `llm_error`, exit code 3, partial output written); a unit that stayed invalid after the repair is final (`invalid`); a unit hit by an outage is not recorded and is retried. The request seed and style of every unit come from the caller's generator in input order, so a resumed run asks the same questions.
