[T3.4 review, supersedes parts of D461, D490, D491, D493] (a) **Fresh collection per build:** a derived name gets a build suffix (`<fingerprint>__b<8 hex>`), so the app never reads a collection that is being written; the alias `chunks_active` moves in one atomic request after the metadata says `complete`; the previous alias target is deleted only after the swap; a build that raises drops its partial collection and leaves the alias untouched. An explicit `--collection` (PR jobs) is dropped and rebuilt if it exists, and refused when it is the served collection. In-place upsert and the stale-point prune of D491 are removed. (b) **`complete`:** the collection is created with `metadata.complete=false`; only the final metadata update after the last point sets `true`; the app answers 503 "index build is not complete; re-index" for a collection without `complete: true` (so an aborted `--no-alias` build is never served). (c) **Served default is the alias:** `RAG_COLLECTION` defaults to `chunks_active` (was `slice_v2`, D461) for tier 1 and tier 2; `make index-slice` builds through `rag-demo index` and snapshots the alias target; the integration restore recreates the alias. (d) The app re-reads the collection metadata every 10 s, so an alias swap is picked up without a restart. (e) The bge-m3 tokenizer source is pinned to the Hugging Face commit `5617a9f61b028005a4858fdac845db406aefb181` (`hf:BAAI/bge-m3@<rev>/tokenizer.json`), the sha256 check stays. Known limits (follow-up): `read_corpus` loads all rows into memory and the embedding pass is single-threaded, fine for the slice, to be streamed for the full corpus
