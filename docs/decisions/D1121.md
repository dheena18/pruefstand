[security fix F3/F6/F7, workflow guard] The guard (`scripts/workflow_hardening.py`) refuses string `permissions:` (`read-all` grants actions/models read implicitly), denies every write scope without its own table unless `OTHER_WRITE` lists (file, job, scope) with a reason (deny by default; never at workflow level), refuses `github.event.*` in `run:` / any `with:` input except numbers, SHAs, `workflow_run.id`, `repository.full_name` (also `toJSON(github.event...)`), refuses step outputs interpolated into `$GITHUB_ENV`/`$GITHUB_PATH`, requires a `DANGEROUS_TRIGGERS` entry for `workflow_run`/`issue_comment`/`pull_request_review(_comment)` (`docs.yml` `workflow_run`, N5.2) and scans `.github/actions/*/action.yml` (`make lint`, `--actions`). Dependabot `github-actions` covers `/.github/actions/*`; every ecosystem has `cooldown: {default-days: 5}` (supported for uv, npm, github-actions, docker, docker-compose per the Dependabot options reference, checked 2026-11-10). `cassettes-models.yml` installs with `uv sync --frozen`. No permission changed. Review rounds 2-3 (`scripts/workflow_taint.py`): the whole `github` context (`toJSON(github)`) and any computed context index (`github[format(...)]`) are refused; a value is tainted when an expression reads an event path outside `EVENT_VALUES` (which now also allows `pull_request.head/base.repo.full_name`: GitHub restricts owner/repo to `[A-Za-z0-9._-]`), an untrusted context, a step or job output, an action or `workflow_call` input, or a tainted `env.*` / `matrix.*` name (computed to a fixed point over workflow, job and step `env` and `strategy.matrix` incl. `include`/`exclude`; a matrix built from a tainted expression taints every key); code fields (`run`, `shell`, `working-directory`, `with.script`) may interpolate no tainted value and no `steps.*`/`needs.*` output (pass it through `env:`); other `with:` inputs no event, untrusted or tainted env/matrix value; a `run` block that mentions `GITHUB_ENV`/`GITHUB_PATH` anywhere may contain no `${{ }}`, no tainted env var and no attacker-set runner variable (`GITHUB_HEAD_REF`, `GITHUB_BASE_REF`, `GITHUB_REF_NAME`, `GITHUB_REF`, `GITHUB_EVENT_PATH`), except steps on `ENV_FILE_STEPS` (reviewed, with a reason); the triggers `issues`, `discussion`, `discussion_comment` need a `DANGEROUS_TRIGGERS` entry; `--actions` exits 2 on a missing directory or one without `*/action.yml`. **Known limits:** the guard is defence in depth, not a proof: it reads expressions and shell text, not shell semantics (e.g. values that reach a file and are read back, or `eval` of a trusted variable that was built from untrusted parts, are not tracked; nor are `printenv T >> "$GITHUB_ENV"` / `env >> "$GITHUB_ENV"` with a tainted `T`, which name no `$T`, nor writes to `$GITHUB_STEP_SUMMARY`); zizmor and review stay required. Final check: a dynamic `include`/`exclude` or a whole-matrix expression taints every `matrix.*` name, also through `env:`; untrusted contexts are refused in every code field and `with:` input.
