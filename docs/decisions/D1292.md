[T9.1a, lead decision on the release lock lines; amends the X2.9 / W2.6 exemption] The release exemption also covers the `version` line of the **virtual workspace root** `pruefstand-workspace` in `uv.lock`, alongside the members `pruefstand` and `rag-demo`.

**Why.** release-please runs with `release-type: python` on the root package. It bumps the root `pyproject.toml` version, which is already exempt by the `pyproject.toml` rule. `uv lock` then rewrites the root's lock entry `name = "pruefstand-workspace"`, `version = …`.

**Exactly one line more, nothing wider.**
- Every other line of that entry (`source`, `default-groups`, dependencies) still gates.
- Every other package's lines still gate.

**Where the rule lives.** One rule, kept in three places that must agree:
- `scripts/ci/check_release_lock_diff.py`, the guard of the release PR's `uv lock` commit;
- `scripts/ci/gate_router_regex.RELEASE_RULES`;
- `gate-router.yml`, which inlines those rules (owner path).

Tests in `scripts/ci/tests/` check that all three agree, including the Node decision of the workflow script.
