[T3.5, reranker] `CrossEncoderReranker` posts **one** batched `POST <RERANK_URL>/rerank` `{query, texts, truncate: true}` with the first `rerank.top_n` (10) passages, each cut client-side to the catalogue entry's `max_input_tokens` (256) by a word-and-punctuation count (a lower bound of the model's tokens, so it never cuts text the model would keep; the service enforces the exact limit), sends no `Authorization` header and reads no key (D217), and uses the catalogue's new optional `request_timeout_s` (60 for `cpu/bge-reranker-v2-m3`; `infra/gpu/catalogue_schema.py` gains the field). The reranked count is `max(rerank.top_n, top_k)` (a request with `top_k` above `top_n` reranks all returned hits, so a result never mixes cross-encoder and RRF scores). The result is the scored hits sorted by score (ties keep the fused order) followed by the unscored remainder, ranks 1..n, then cut to `top_k`; all scores are reranker scores. A failing or malformed answer raises `RerankError` (503): the retrieval never degrades silently to the fused order. There is no retry (an infra failure is retried by the executor, D226). `reranker: off` builds `IdentityReranker`; `reranker: on` needs `RERANK_URL` (checked at app start like the other endpoints)
