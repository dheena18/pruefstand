[T1.3, security hardening of `HttpTargetAdapter`; no interface change] The target is untrusted, so every call has a connect timeout (min(`timeout_s`, 10 s)), read/write timeouts and a **total deadline** of `timeout_s` (`asyncio.timeout`, bounds a slow-drip body); the body is read raw with a hard cap `MAX_RESPONSE_BYTES` = 8 MiB (declared `Content-Length` checked first; `Accept-Encoding: identity` is sent and any other `Content-Encoding` is a permanent error, so no decompression bomb); redirects are **never followed** (3xx = permanent `TargetError`, `Location` not echoed); the adapter refuses non-http(s) URLs and URLs with credentials, query or fragment (`ConfigError`); `trust_env=False` (no `~/.netrc`, no proxy env). The bearer token is read from `auth_env` **at call time** (supports rotation; unset or non-printable value = permanent `TargetError` naming only the variable) and is redacted from error excerpts; error excerpts are <= 200 chars with control characters removed. Hostile bodies (NaN/Infinity/`1e999`, lone surrogates, 100 000-deep nesting, non-objects) are permanent `TargetError`s, never `RecursionError`/`ValueError`. The wire `request_id` is **always** a fresh `uuid4().hex`; the caller's `TargetRequest.request_id` (a case id may sit there) is never sent. No retries (T1.8 owns them; the prompt forbids them here). 4xx stays `transient=False` as in interfaces §4 (429/408 retry policy is a T1.8 question). OpenAPI: `top_k` is optional+nullable in `QueryRequest`, chunk `tenant_id`/`used_in_prompt` optional+nullable; `test_target_api_v1.py` fails when component properties drift from the pydantic models. **Review round 1 (same row):** response bodies are parsed in `adapters/wire.py` in a worker thread inside the total deadline, with bounds checked before pydantic (citations <= 1000 and strings, chunks <= 10 000; no unbounded `exc.errors()` message, no raw parser exception on the chain). Third-party tolerance without touching core models: unknown keys are dropped at response/chunk/usage/info level, null optionals (`citations`, `chunks`, `tenant_id`, `used_in_prompt`, `serving`...) are absent, `usage` without both token counts is absent, type errors in known fields stay permanent `TargetError`s; OpenAPI response schemas are `additionalProperties: true` (requests strict; `RetrieveResponse` forbids `answer`). `info()` returns `None` for 404 only (405/501 raise). Token redaction covers plain, JSON-escaped and URL-encoded forms and anything after `Bearer `. TLS certificate failures are permanent; a status is judged before `Content-Encoding` (a gzip 503 stays transient). Duplicate JSON keys: last wins; BOM accepted; `Content-Type` not checked. **Review round 2:** token redaction also covers `quote()` with the default `safe="/"` and the doubly JSON-escaped form. Integer citation ids (not bool) are stringified (`[1, 2]` -> `("1", "2")`); every other non-string item stays permanent. A `usage` with only one of the two token counts is dropped as absent, so `usage=None` can mean partial usage (a token-cost metric must not read it as none reported). Wire parsing runs in the adapter's own `ThreadPoolExecutor(max_workers=4)`, shut down in `aclose()`, not in the loop's default executor. Accepted: junk inside ignored keys can still cost ~230 MiB peak at the 8 MiB cap.
