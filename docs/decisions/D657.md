[T8.2a, hard-fail rule label] Published hard-fail findings carry `rule: "hard_fail"` and the specific rule in `metric` (`tenant_leak`), so the label lookup tries `rule` first and then `metric` in `labels.json` `hard_fail_rules` (en) / `rule.<code>` (de), else the raw rule in mono. A finding whose `case_id` is redacted or not an id is shown without an `Open case` link. A rule other than `hard_fail` (for example `hard_fail_unverifiable`) is followed by the marker `finding.unverifiable`, like the PR comment and the report. D656 also covers: block R / J show all their rows when none is `overall`, and the omissions are written into ui-spec §11.1.
