[T4.5, two passes, quota] `perturb/batch.py`: `rewrite_pass` stores each draft at once in `<dir>/rewrites.jsonl` (key = item, text, perturbation, prompt version, rewrite model, seed), skips stored drafts, and stops at `QuotaExhausted` (`stopped=quota`) or the client `Budget` request cap (`--max-requests`, `stopped=budget`); a transient `LLMError` leaves the item for the next run (`failed`); `validate_pass` reads the stored drafts and never calls the rewrite model. Items are processed in the caller's order, so T4.7a puts the `robust_pr` bases first and the first round (core plus the smaller full sample, D585) fits the daily quota before the rest. `perturb_case_async` returns `None` for a rejected rewrite or an `LLMError` (warning `perturb_llm_error`) but re-raises `QuotaExhausted`, so a batch stops instead of silently skipping every case. A question the data guard blocks is rewritten by the local model (role `DATAGEN`, never external).
