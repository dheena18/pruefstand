[T3.1c, ADR-0019 amendment] The cluster data root is owner-supplied, not committed: `PRUEFSTAND_CLUSTER_DATA_ROOT` or `/etc/pruefstand/cluster-data-root` (one line, ASCII `[A-Za-z0-9_./-]` checked in the C locale, absolute, at most 4096 characters, no `..`, no trailing `/`; `lib/cluster_paths.sh`, exit 78 when missing or invalid; the file source is used only if it is a regular non-symlink file owned by root, not group/world-writable, in a root-owned directory that is not group/world-writable; the variable wins over the file, so only the file is set for the service user). `cluster.env.template` carries `@MODELS_DIR@`, `@BIN_DIR@`, `@LOG@`; `deploy-cluster-bin.sh` renders them (a leftover placeholder is refused) so the rendered file is byte-identical to the former hard-coded one and `SHA256SUMS`/`bin-integrity` are unchanged; `cluster_ssh.sh` resolves the same value; the root-owned wrapper keeps a fixed `bin=` line that `install-cluster-wrapper.sh` renders at install time (an unrendered copy exits 64; no new environment seam in a sudo-able script). Docs use `$CLUSTER_DATA_ROOT`; a repo test fails on any tracked `/data/<name>/{Models,pruefstand-bin,ollama.log}` with a non-synthetic name.
