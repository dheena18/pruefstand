[T8.2b, runtime data] Shards 1+ are validated in the browser by a hand-written structural check (`validateShard`), not by Ajv: Ajv compiles schemas with `new Function`, which the meta CSP forbids (no `'unsafe-eval'`, ui-spec §7.4). It checks what `dashboard_cases.schema.json` does: exactly the schema's keys (none extra, none missing, top level and per case), types and enums, at most 500 cases per shard, unique case ids (inside a shard and, in `ShardStore`, across shards), and parallel `retrieved_chunk_ids` / `retrieved_chunk_tenant_ids` (an empty tenant list is the pre-R3 form); a failed fetch, a fetch slower than `SHARD_TIMEOUT_MS`, or a failed check is a failed shard (`C-SHARD-ERROR`, Retry). The one runtime URL helper `dataUrl()` lives in `src/lib/data-url.ts` (no Node imports, so client code can use it) and is re-exported by `data.ts`; `BASE_PATH` is read as `process.env.NEXT_PUBLIC_BASE_PATH` so the bundler inlines it. No source file has a string literal starting with `/data/` or `/_next/` (grep test).
