[T9.1a S1, S1b, S2, S3 as built; confirms D159 / X2.9] **The release-please side.**
- `release-please-config.json`: one root package (`release-type: python`, `include-component-in-tag: false`, so tags are plain `vX.Y.Z`). `extra-files` bump the version of the two member pyprojects; `action/action.yml` joins with the first release PR (D1293).
- `release-please.yml`, in environment `release`, with the `pruefstand-release` App token (secrets `RELEASE_APP_ID`, `RELEASE_APP_KEY`):
  1. runs release-please;
  2. on the release branch: pinned `uv lock`, then the guard `check_release_lock_diff.py` (D1292);
  3. commits **only** `uv.lock` and pushes it with the App token.
- `GITHUB_TOKEN` is `contents: read`; no `id-token`.

**`release.yml`.**
- On tag `v*`:
  - `build-dist` (`uv build`, `twine check`), then `publish-pypi`: Trusted Publishing, environment `pypi`, no token.
  - `image-action` and `image-rag-demo`: refuse an existing `:vX.Y.Z`, build, Trivy gate (HIGH/CRITICAL with a fix), push.
  - `sign`: keyless cosign of both digests with the `release.yml@refs/tags/vX.Y.Z` identity.
  - `attest`: syft SPDX SBOM, attached with `cosign attest --type spdxjson`, plus build provenance.
  - `release-assets`: writes `image-digests.json`, the SBOMs and the dists as release assets. It never uses `--clobber` and never touches `demo-ready.json`. It also keeps `image-digests.json` as an artefact.
- `workflow_dispatch` with `prerelease`: `build-dist` and `publish-testpypi` only.
- No `docs-deploy` job: `docs.yml` stays the single Pages writer.

**Permissions.**
- `id-token: write` only on `publish-pypi`, `publish-testpypi`, `sign` and `attest`; `contents: write` only on `release-assets`.
- The `packages` and `attestations` writes are on the workflow-policy allow-list (`OTHER_WRITE`).

**New action pins** (resolved from the GitHub API, all released more than two weeks ago):
- `googleapis/release-please-action` v5.0.0;
- `pypa/gh-action-pypi-publish` v1.14.3;
- `anchore/sbom-action` v0.24.3;
- `actions/attest-build-provenance` v4.2.2.

The other actions reuse the repo's existing pins.
