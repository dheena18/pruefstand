[T3.1a] Wrapper hardening (review M1, M2): the mutating ops need the GPU lock held by an ANCESTOR of the wrapper (`/proc/locks` inode match, PPid chain through `sudo`); tags must be in the allow-list `/usr/local/lib/pruefstand-cluster.allow` generated at install time from `models.yaml`; `pull` takes its size from that list and `ollama-op.sh pull <tag> <bytes>` checks bytes + reserve on the models filesystem (unreadable free space is exit 17); `rm` needs `MAINTENANCE` (exit 3). `infra/vm/pruefstand-lock` (T0.7) changed: it now runs `flock -w N -E 75 <lock> <cmd>` instead of taking fd 9 and exec-ing, so the process that holds the lock stays an ancestor of `<cmd>` (the kernel records the pid of the short-lived `flock` child otherwise, which is dead by then and reusable); same exit codes 2/64/75; the owner reinstalls it if `/usr/local/bin` holds a copy (`sudo infra/vm/setup-users.sh`). The wrapper matches device and inode in `/proc/locks`. Preflight `health.sh` exit 14 is what verifies the cluster scripts' integrity before they are trusted. `health.sh` exit priority 16, 11, 12, 14, 13, 15, 10. A mode model that is not resident and a second `ollama serve` are exit 11; a catalogue model outside the mode is a WARN row (`--repair` unloads it), a non-catalogue model a WARN row (left alone); `--repair` progress goes to stderr so stdout is the CSV only. Free VRAM threshold `PRUEFSTAND_MIN_FREE_VRAM_MIB` (default 1024).
