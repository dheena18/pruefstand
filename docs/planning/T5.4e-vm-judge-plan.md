# T5.4e plan: RQ2 arms (b', c) on the VM CPU model (D1242)

Status: plan and skeleton only (`experiments/rq2/vm_arm.py`, `--dry-run`). No server start, no model call.

## Why

The RQ2 arms (b') large non-gemma judge and (c) tier-1 informational judge were planned on GitHub Models (D939).
GitHub Models is retired (D1202). The replacement is the VM CPU model **Ministral 3 14B Instruct 2512** (Q4_K_M,
Apache-2.0; D1200), started on demand by `scripts/models/vm_llm.sh` (PR #165) and called through the
`openai_compatible_local` backend (PR #166, `PRUEFSTAND_DATAGEN_BASE_URL`, loopback only). One model now stands for
both arms: the large contrast to `gemma3:12b` (b') and the only candidate of the tier-1 role (c).

## Steps (after 1 and 2)

1. **Config.** `rq2_judges.yaml`: one entry `{id: openai_compatible_local/ministral-3-14b-instruct-2512, family: mistral,
   arm: c, subsample: <from step 2>}` (enabled); the three `github/...` entries stay disabled (history).
   `datagen_family` follows the family plan (`model_families.yaml` `plan.datagen`); with #166 the public datagen model is
   this same Ministral, so it **is** the datagen family: `select_tier1` then compares it on faithfulness only and its
   `answer_correctness` agreement is reported separately (AI9-26), exactly as for `gpt` before.
   `run_judges.make_judge`: for a VM id build the backend with `build_vm_backend` and call `check_vm_served` once
   (never the judge URL); concurrency 1 (the VM server serves one request at a time).
2. **Pilot (GPU lock, VM server).** `pruefstand-lock`-held session via `vm_llm.sh start 14b`; 20 items (5 per
   publishable set) through `run_judges.py --judge <vm id> --limit 5`; measure s/call (estimate: 30-60 s, prompt
   ~1 000 tokens at ~26 tok/s, JSON answer ~60 tokens at ~3 tok/s). Record the cassettes for
   `experiments/rq2/tests/cassettes/vm_judge/` from those real calls (new `record_cassettes.sh --rq2-vm-judge` hunk);
   `vm_llm.sh stop`. Decide the subsample size from the measured s/call (D1242 follow-up row).
3. **MEMERAG routing.** MEMERAG (CC BY-NC) may be judged by local judges only. The VM model is local (127.0.0.1,
   the text never leaves the VM): add the VM provider prefix to `rq2.binarise.LOCAL_PROVIDERS`, with a test, then
   `vm_items` includes MEMERAG (274 `test` items). Without this step the VM arm has no human-labelled faithfulness
   number.
4. **Full run.** `vm_arm.py --dry-run --size N --s-per-call <pilot>` prints the session plan (e.g. 1 200 calls at
   45 s = 5 sessions of <= 256 calls, about 15 h). Each session: `vm_llm.sh start 14b`, `run_judges.py --judge <vm id>
   --split test --pairs` (the judge cache makes every session resume where the last stopped), `vm_llm.sh stop`.
   Sessions only outside the night window and never while a gate or `make check-vm` runs (the launcher refuses then,
   exit 75). Then `report.py` (agreement matrix gets its second judge; `select_tier1` gets a measured candidate).
5. **Docs.** Decision file with kappa (CI), specificity, discrimination, cost (CPU-s per 1 000, USD 0), latency;
   README results table; `calibration_status.yaml` only as `report.py` writes it. `judge_epoch` is untouched
   unless the gating judge changes (it will not: the VM model cannot serve the A40 gate).

## Open decisions (owner)

  D850), and GitHub Models is gone. Options: (a) tier 1 runs `judge_mode=skipped` for good (judged metrics were
  informational there anyway, W1.4); (b) a self-hosted path is out (no self-hosted runner in the public repo). T5.4e
  therefore measures the model for RQ2 only; `examples/live` keeps no hosted judge pin once #167 lands.
- **Arms.** b' and c collapse into one VM model; the size contrast b'' (`gemma3:4b`) stays an owner `MAINTENANCE` swap.
- **Subsample size** after the pilot (300 per set is ~15 h of CPU sessions; 150 per set halves it, wider CIs).
