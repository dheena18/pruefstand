## Assumptions (planning numbers, not measured; all **verify** in T0.6 / T3.1a / T3.1b / T4.7b)

- A40 696 GB/s: 27B `Q8_0` (≈ 28.7 GB) decode is bandwidth-bound at ≤ 24 tok/s per step, ≈ 45–60 tok/s aggregate
  at 4 slots; prefill ≈ 900–1 300 tok/s. Mistral Small 24B `Q4_K_M` prefill ≈ 1 100–1 600, decode ≈ 80–110 aggregate.
- Tier-2 generator prompt ≈ 4–6 k tokens (system + rules + 8 per-§ chunks inside `num_ctx − num_predict`), answer
  ≈ 200–400 tokens (German legal answers with citations; Qwen with thinking off, no length cap other than
  `generation.max_tokens`).
- KV/token (f16): Qwen 27B dense with 8 KV heads × 64 layers 256 KiB (**verify**: if `qwen3.8` is a hybrid
  linear/full-attention architecture the KV is far smaller and Ollama's parallel-slot behaviour differs);
  Gemma 3 27B 62 L × 16 KV × 128 ≈ 0.48 MiB without a sliding-window cache.
- Qdrant normalises vectors on upsert and query for `Distance.COSINE`; Ollama `/api/embed` returns L2-normalised
  vectors (both **verify** on the pinned versions; high confidence).
- Ollama silently truncates a chat prompt longer than `num_ctx` (which end is kept depends on the version,
  **verify**); it exposes no public tokenize endpoint on the pinned version (**verify**).
- Nightly cap arithmetic (binding rules D248/D281): refusal stratum ≈ 150 cases (every `unanswerable` `full` case),
  so each block holds ≤ 450 cases and `full` without the refusal stratum holds **≤ 1 350 cases**.
- MDE = max(4.07·SE, δ + 0.84·SE), SE = σ_d/√n_clusters, m ≈ 40, σ_d = 0.25 (SPEC §7.2).
