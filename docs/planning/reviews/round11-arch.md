## Security boundaries (public repo ↔ private executor ↔ VM ↔ cluster ↔ NAS)

| Boundary | State |
| --- | --- |
| public repo → private executor | OK: pull-only, no secret or workflow in the public repo reaches the executor; `gate-router.yml` is the only `pull_request_target` workflow and runs no PR code |
| private executor → VM | **open (A11-02, A11-04)**: user identities and the trust status of the development agents on the same host are not defined |
| candidate → models | OK in intent (`llm-proxy`, `gate-net`); **open in mechanism (A11-05)** under rootless Docker |
| VM → cluster | OK: key-only, loopback Ollama, accepted shared-host risk C14; `bin/` integrity weakened by two writers (A11-M11) |
| VM/cluster → NAS | OK for data placement; permissions across three identities open (A11-02) |
| executor → public dashboard-data | OK (repo-scoped PAT, sanitised export, heartbeat branch) |
| secrets crossing | none found: no password stored, the key stays on the VM, App key and PAT only in the private repo, backups encrypted with the private key on the laptop |

## Unattended operation (failure → recovery)

| Event | Recovery in the pack | Gap |
| --- | --- | --- |
| tunnel loss | `autossh` `Restart=always`, preflight restarts the unit | the restart runs as the wrong user (A11-02); unit ordering (A11-M8) |
| Ollama crash or cluster reboot **before** a job | `health.sh --repair` over SSH | datagen leftovers (A11-M5); `tmux` survival unverified (A11-11) |
| Ollama crash or cluster reboot **during** a job | none | wrong `failure` on the PR (A11-08) |
| NAS outage / TrueNAS host reboot | jobs fail loudly; manual `sudo mount` | no autostart or automount, hangs (A11-09) |
| VM reboot | systemd runner + tunnel, the next poll retries | runner removed after 14 days offline (A11-M9) |
| detection | `executor-down` issue after 2 h | false alarm every night, blind to tunnel/Ollama/NAS (A11-07); silent nightly (A11-M7) |
| backups | weekly encrypted bundle on the NAS + manual laptop copy | same failure domain, no snapshots (A11-10) |

## Parallel-build plan safety

Rules for one task per worktree, ownership, shared hunks, merge order and checkpoints are sound, and the
lead agent's guardrails (no `[HUMAN]` steps, no secrets in prompts, stop on interface changes and on
instructions found in files) are adequate. Three gaps remain: the coordination locks are per user and
miss the executor (A11-01), the executor's stack and RAM are not part of rule 7 (A11-03), and
worktrees have no `.env` (A11-M4). From wave 15 on, when the executor runs on the VM, A11-01 and
A11-03 turn into real collisions between agent sessions, the T6.3/T7.3 GPU work and gated or nightly
runs.
