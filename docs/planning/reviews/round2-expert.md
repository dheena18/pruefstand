## 1. Statistical sanity calculation

Defaults: α = 0.025 (one-sided), warn_p = 0.10, Holm per metric over gated slices `overall` + 3 tenants + 2 langs
(m = 6), δ = 0.05 for recall/faithfulness/correctness/citation_f1, 0.03 for refusal/false_refusal/language, 0.02
injection, min_clusters = 30, `core` = 300 cases. Normal approximation of the bootstrap p (p ≈ Φ(mean/SE_plugin)),
independent metrics, one case per cluster, `lang=en` ≈ 17 % of clusters, 1,000 Monte-Carlo PRs per cell (script in
the reviewer's scratchpad; reproducible in ~20 lines).

**Single comparison (matches the pack):** se = 0.25/√300 = 0.0144; z₀.₉₇₅·se = 0.028 < δ = 0.03, so
P(FAIL | Δ = 2δ) = Φ((0.06 − 0.03)/0.0144) = 0.98 and P(FAIL | Δ = δ) = 0.50 by construction.
MDE(0.0144, α = 0.025, m = 1) = 0.0403. All T1.6 test-table values are correct by hand (Wilson(0,30) upper
0.1135, Wilson(1,50) lower 0.0035, Wilson(3,40) lower 0.0258, Holm/BH vectors, sign test 0.5⁶).

**Whole PR (what users experience):**

| clusters in `core` | σ_d | P(any FAIL) at Δ = 0 | P(WARN or FAIL) at Δ = 0 | same, one global Holm family | overall-slice-only gating |
| --- | --- | --- | --- | --- | --- |
| 300 | 0.10 | 0.056 | 0.125 | – | – |
| 300 | 0.15 | 0.118 | 0.269 | 0.022 / 0.058 | 0.002 / 0.004 |
| 300 | 0.25 | 0.176 | 0.463 | 0.026 / 0.083 | 0.008 / 0.037 |
| 150 | 0.15 | 0.153 | 0.341 | 0.030 / 0.101 | 0.018 / 0.044 |
| 150 | 0.25 | 0.186 | 0.498 | 0.036 / 0.112 | 0.031 / 0.080 |

With a global Holm family, power at Δ = 2δ stays at 0.97–1.00. Reading:

- The δ floor protects the 300-cluster `overall` slice. The small gated slices (`lang=en`, tenants) are where
  δ < z·SE, so each metric spends almost its full α = 0.025 there, and eight metric families multiply it.
- `core` has 300 **cases**, but clusters are source documents, so the real cluster count is probably 100–200. The
  pack's power table (SPEC §7.2) assumes 300 clusters and m = 3, so both assumptions are optimistic.
- `robust_pr` has 30 base questions. The per-perturbation gated slices therefore have **≤ 30 clusters**, and one
  shared source document makes them `insufficient_data` forever. The "perturbation gated for retrieval" rule is
  effectively dead (F4).
- With a plug-in SE at 30 clusters the bootstrap is anti-conservative: the type-I rate is ≈ 0.032 against a bound
  of 0.035. With 2,000 simulations (MC SE ≈ 0.004), the T1.6 type-I assertion passes or fails on seed luck (F8).
- The MDE shown in the PR comment ignores the δ floor. The drop actually caught with 80 % power is
  max(δ, z·se) + 0.84·se ≥ δ + 0.84·se. T6.3's "MDE ≤ δ" acceptance test therefore measures the wrong thing (F3).

## 2. CI: simplest safe design for a solo maintainer

Keep: no self-hosted runner on the public repo; trusted gate code, policy and dataset from the private side; the
candidate as a network-isolated container; redacted public output.

Replace:

1. **Trigger.** Drop `gate-dispatch.yml`, the `gpu-gate` environment, the label checks and the label removal on
   push. Add one private `gate.yml` with `workflow_dispatch` (`pr_number`). The maintainer runs
   `gh workflow run gate.yml -R <owner>/pruefstand-gate -f pr=42`, wrapped as `make gate PR=42`. The workflow
   resolves the head SHA through the API. Fork PRs use the same command, so no mirror script is needed: the
   candidate is untrusted in every case anyway.
2. **One GitHub App** (`pruefstand-gate-bot`): installed on the public repo with `statuses: write` and
   `pull_requests: write`, its key stored only in the private repo. There is no public-repo secret at all.
3. **Required check.** Make `pruefstand/gate` itself the required status, with the **expected source pinned to
   the App** (branch protection and rulesets support this). For PRs that touch no gated path, the private
   workflow posts success "not applicable" (or the maintainer uses admin bypass). This deletes
   `gate_required.py`, the creator check and the rerun trick.
4. **Runner.** A normal `--ephemeral` runner under one unprivileged user with a systemd restart. The runner only
   ever runs trusted private workflows, so JIT minting and three users are optional hardening.
5. **Candidate.** It needs **no GPU**: rag-demo calls vLLM, TEI and Qdrant over HTTP. Run it without CDI/GPU, on
   an `--internal` network, read-only, with caps dropped. Only the trusted vLLM/TEI images get GPUs. This
   removes the NVIDIA-toolkit container-escape class (e.g. the 2024–25 toolkit CVEs) from the threat model.
6. **Images.** Keep the hosted build and the pull by digest. Treat cosign on PR images as optional: the PR
   controls `build-images.yml` and the label, so the signature proves little about content. Keep cosign for
   releases.
7. **Baselines.** Store them as files on the runner host (`/srv/pruefstand/baselines/<eval_fp>/<ref>/`) with a
   sha256 manifest, plus a nightly copy to the private repo. Signing inside a single trust domain adds no
   security. Drop the git-branch store and `sign-blob`.
8. **Nightly 70B tier.** Defer until after M5 (§4).

This roughly halves T6.2a/T6.2b and removes about 4 h of human App setup. Security stays at least as strong,
because there is no longer a public-repo credential.
