## Eval method, RAG, dataset, RQs — summary verdict

- **Metrics:** sound set, but three SPEC metrics have no owner (AI9-06), `false_refusal` is mis-scoped (AI9-05),
  `ndcg_at_k` is expected by mutations but not gated (AI9-10), the 6 k cap biases faithfulness on A40 (AI9-12).
- **Judge prompts:** German, reason-before-score, nonce blocks with HMAC (cache-stable), injection-robustness rule,
  no `erwartet` for refusal: good. One stale line in T5.2a (AI9-16).
- **Calibration:** hard negatives were added, but the pass statistic is degenerate (AI9-01, blocker) and the
  in-domain hard set exists only in SPEC (AI9-02). Refusal judge has no pass rule (AI9-19).
- **Drift / cache key:** cache key fixed correctly (D113); fingerprint does not follow judge version/epoch
  (AI9-07); drift rule too twitchy and coupled to the fingerprint (AI9-08).
- **Gate statistics:** Holm/one family, MDE, MC-error refinement and per-metric ≥ 30 rule are right; the
  `overall` slice composition (AI9-03) and the core quota conflict (AI9-04) make the planning MDEs wrong.
- **RAG design:** hybrid with in-prefetch tenant filter, e5 prefixes, thinking off, no hosted generator,
  `in_prompt` context: sound. Tier-1 injection check is fragile (AI9-13).
- **Dataset build + model review:** datagen/judge family separation is good; the reviewer = PR judge with
  `fix` rights undoes it for references (AI9-11).
- **RQ validity:** RQ1 needs the `evidence_span` definition fixed (AI9-06, AI9-23); RQ2 lacks its size contrast
  (AI9-26) and in-domain set (AI9-02); RQ3 needs tier/metric-consistent expectations (AI9-10), churn σ_d
  (AI9-09) and N09/N10 (AI9-22).
