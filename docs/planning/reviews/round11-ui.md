## Checks asked for

1. **Contract fields, same names.** Yes for every page and component. Field lists in §15 match
   interfaces §2/§9/§10.1 exactly: `RunIndexEntry`, `DashboardSliceRow`, `DashboardCase`, `LabelsDocument`,
   `CostSummary`, `judged_cases`, `no_baseline`, `used_in_prompt`. Gaps: the renderer `base` argument
   (UI11-08) and the judge source label (UI11-14).
2. **Identical builds.** Wireframes, tokens, copy (de/en), a11y table, breakpoints, banners and the
   table rule are concrete. Divergence points that remain: tier-1 slices (UI11-01), static HTML of
   query-driven pages (UI11-09), PR comment absolute-check rows (UI11-12), no-baseline Diff/Slices
   (UI11-20).
3. **PR comment and HTML report vs data.** Every column maps to a field. They match, except UI11-08 and
   UI11-12.
4. **Per-set build and Playwright matrix from committed fixtures.** The design (two sets, two
   `webServer`s, delay-only routing, offline emulation) is sound. It is runnable once UI11-02 (empty
   set), UI11-03 (fixture provenance), UI11-04 (allowlist) and UI11-18 (offline mechanics) are fixed.
   The Try-it job needs UI11-07.
5. **CSP with the static export.** The per-page meta with hashes of the Next inline scripts, header-only
   `frame-ancestors`, the separate report rule and client-only charts (CSSOM styles) fit `output:
   "export"`. Open: delivery to Vercel (UI11-05), report hash drift (UI11-10), `basePath` (UI11-11).
6. **Demo on free CPU hosting.** It does not fit as written (UI11-06). The latency budget (≤ 2B Q4,
   `max_tokens` 256, concurrency 2, client timeout 90 s) is plausible on 4 vCPU, but the server timeout
   is unset (UI11-17) and the reranker state is inconsistent (UI11-16).
7. **Prompt citations.** They are correct apart from UI11-23. Every ui-spec section a prompt builds on is
   cited, including the round-9 gaps (§7.1/§14 in T8.2b, §2.2/§6/§7 in T8.4).

## What is good

- §11.1 is a real single predicate. T1.9 `tables.py` and T8.2a `tables.ts` share one expectations
  JSON, and every surface test asserts "exactly one table".
- No-baseline is coherent end to end: `baseline_run_id: None`, ⚪/⊘ badge, `set_check` → `failure`, and
  it never appears together with `S-BASELINE-MISSING`.
- §2.4 build-time validation turns a whole class of runtime states into a tested build failure
  (`B-INVALID-DATA`).
- §7.4 is precise enough to test: hashes per page, disjoint header rules, `check_csp.mjs`, a CSP
  assertion in every Playwright combination.
- The Try-it error contract is the same in interfaces §16, ui-spec §4.6 and T8.4, and the reducer has a
  test per transition.
