# Review round 1 — executability of the task prompts

Reviewer: independent AI reviewer (no project files edited). Scope: `CLAUDE.md`, `tasks/TASKS.md`,
`prompts/README.md`, `_TEMPLATE.md`, `_review.md`, `_session-start.md`,
`docs/engineering/ai-workflow.md`, and all 63 task prompts T0.1 … T10.4. Cross-checked against
`docs/architecture/interfaces.md`, `docs/spec/SPEC.md` headings, `docs/engineering/ci-cd.md` and the
`docs/adr/` file names.

Question asked of every prompt: can a Claude Code session do it in one sitting, using only the files
the prompt lists, at its place in the dependency order, with no extra human explanation?

Short answer: the prompts are well above average. They have concrete tables of inputs and expected
outputs, layering notes, and the "Prompt to paste" block is consistent everywhere. Three kinds of
problem recur. (1) Dependency gaps: a prompt needs something (Judge, LiteLLM backend, held-out
canaries, a fixture dataset, a GitHub repo) that a later task or no task creates. (2) Drift between
prompts and `interfaces.md` / `ci-cd.md`: file names, field types and rule strings disagree. (3) "Done
when" checks that need a GPU, network, a hosted account or a human, but don't say so.

Legend: **SC** = self-contained (1–5), **Size** = fits one session (< ~400 changed non-test lines,
< ~4 h), **Amb** = ambiguity score (5 = very clear).
