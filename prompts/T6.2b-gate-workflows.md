## Goal

These workflows are in place:
- **public**, hosted runners, no executor secrets: `build-images.yml` (extended to push + sign from the PR **head**
  SHA, X2.4), **`gate-router.yml`** (new, the only `pull_request_target` workflow: posts `pruefstand/gate` =
  success "not gated" on PRs that touch no gated path or only the release-exempt lines, X2.2, with the
  **`pruefstand-bot` App token** from environment `gate-router`, round 13 P1.1), `executor-health.yml` (new, hourly
  heartbeat check, W2.10);
- **private** executor repo (source in `infra/gate-executor/workflows/`): `gate-executor.yml`,
  `baseline-promote.yml` (incl. the monthly `baseline-prune` step, R9-14), `nightly.yml`, `backup.yml` (weekly,
  whole bundle `age`-encrypted, X2.6).

Together they gate owner-dispatched PRs on the A40s (round 13 P1.2), while PRs without gated changes get their required
status within seconds from a hosted runner and never wait for the A40 runner (R9-10). The nightly run catches
cumulative drift against the last release.

## Context

There is **no** `gate-dispatch.yml` and no `gate-required` job: the public repo never sends anything to the
executor VM or the cluster. **Tier 2 for a PR starts only when the owner dispatches the private `gate-executor.yml`
(input `pr`) from the browser or the GitHub mobile app** (round 13 P1.2): there is no `run-gate` label and no PR
poll, and the VM token cannot read the private repo, so no agent can start it. `main` pushes (`baseline-promote.yml`
poll) and nightlies stay automatic.

**Time budgets (round 10 Z4/D199, round 11 Y4.3/D223; numbers in gpu-cluster.md §5, measured by T3.1b and pinned):**
a tier-2 PR run (core + `robust_pr`, the latter through the candidate's `POST /v1/retrieve` only, no generation,
Y4.1/D222; `robust_pr` runs **without the reranker** if the reranker lane takes more than 20 min per PR run, SPEC §6.2) ≤ **90 min**; the **whole** `nightly.yml` workflow ≤ **8 h** incl. the `flock` wait, inside the night
window **22:00–06:00 Europe/Berlin** (the **sum** of its jobs' `timeout-minutes` ≤ 480, A11-06); the first model load
of a mode (from the NAS) is excluded (the preflight warms the models with the catalogue `options` before the timed
run). `timeout-minutes`: PR/promote jobs ≤ lock wait (120) + **2 × 90** (one infra retry, D226) + 15 min = 315
(round 12 A12-M1). If T3.1b measured more than the budget, PR runs pass `pruefstand run --judged-subset` (T1.10,
round 12 N1.2, round 13 P3.4): the fixed 150-case subset of `core` (`TestCase.judged_subset`, assigned by T4.1,
stratified by category incl. injection, part of `eval_fingerprint`) limits **generation and judging** of the `core`
answerable cases (the others run retrieve-only through `/v1/retrieve`); deterministic security cases always run in
full; the switch is one constant in
`gate_orchestrator/plan.py` set from the recorded T3.1b decision; this task only wires it, it never shrinks a split
silently. A
budget overrun reports `stop_reason` and fails.
**Unattended operation (round 11 Y5, D225–D229).** The orchestrator (T6.2a) refreshes the heartbeat every **15 min**
during every job and lock wait; an infra failure during a run (Ollama, tunnel, NAS, `llm-proxy`/judge upstream errors)
posts **`error`** (never `failure`) and retries **once** after `health.sh --repair`; a model reload during a run also aborts it as `infra_error` (SPEC §6.2). No workflow step implements
either: they are orchestrator behaviour, the workflows only call `gate-orchestrator`.

Public `build-images.yml` (round 9 X2.4):
- trigger (ci-cd.md §1.1): `pull_request`, `push: main`, `push: gate/pr-*` (fork heads pushed by the maintainer,
  W2.5), `push: bench/**`; the `push-sign` job runs for same-repo branches only (`if: github.event_name == 'push'
  || github.event.pull_request.head.repo.full_name == github.repository`); the T0.3 jobs keep running for every
  PR and stay under the aggregate `build`;
- `push-sign` checks out **`${{ github.event.pull_request.head.sha || github.sha }}`** (never the merge commit
  `refs/pull/N/merge`), builds with `GIT_SHA` = that SHA, tags `ghcr.io/dheena18/rag-demo:sha-<head sha>`, sets
  the OCI label `org.opencontainers.image.revision` = that SHA, signs with cosign keyless and posts commit status
  `pruefstand/image` (digest in the description) **on that SHA** (read by T6.2a `select_jobs` at dispatch: no
  image status → `pending` "awaiting signed image", P1.2). The signing identity may still end in
  `pull/N/merge` (that is the workflow ref, not the content);
- the GHCR package `rag-demo` is **public** (W2.8, D107: it contains no secrets), so the executor pulls without
  credentials; new user-owned packages start private, hence the S6 [HUMAN] step after the first push;
- `push-sign` job permissions `contents: read, packages: write, id-token: write, statuses: write`; no secrets.

Public `gate-router.yml` (round 9 X2.2; round 13 P1.1/P4.2, binding; ci-cd.md §1.1 row):
- `on: pull_request_target` (`opened`, `synchronize`, `reopened`), hosted `ubuntu-24.04`, top-level
  `permissions: {}`, job permissions exactly `pull-requests: read`, **`environment: gate-router`** (deployment
  branch `main` only, T0.5 S7a); **no checkout step, no PR code fetched or executed** (the T0.2 guard allowlists
  exactly this file and asserts this). Its only secrets are `BOT_APP_ID` and `BOT_APP_KEY` of the environment,
  turned into a short-lived **`pruefstand-bot` installation token** by `actions/create-github-app-token` (pinned by
  SHA); the status is posted with that token, because the ruleset accepts `pruefstand/gate` only from the App
  (P1.1). No other workflow may reference `environment: gate-router` or `secrets.BOT_APP_*`;
- one job `route`: reads the PR's changed files (`filename`, `patch`) from the REST API (`gh api --paginate
  repos/{repo}/pulls/{n}/files`, `GITHUB_TOKEN`), matches the names against the gated-path list of ci-cd.md §5,
  inlined in the workflow as **one** anchored regex (it cannot read repo files without a checkout); no gated path
  → status `context=pruefstand/gate`, `state=success`, description "not gated (no gated paths changed)".
  **Release exemption (moved here from the executor, P4.2: "not gated" is posted only by gate-router):** a
  release-please PR (head ref `release-please--*`, author `pruefstand-release[bot]`) whose files are all in the
  release-exempt list of ci-cd.md §5 and whose every changed patch line (`+`/`-`, not `+++`/`---`) matches that
  file's exempt-line regex (version values, the `uv.lock` member `version` lines, X2.9, `CHANGELOG.md`) → success
  "not gated (release version bump)". Any other gated PR gets **no** status from this workflow (its
  `pruefstand/gate` comes only from the executor after the owner's dispatch). The PR title, body and branch name are
  never interpolated into a shell (zizmor template-injection rule);
- `concurrency: { group: gate-router-${{ github.event.pull_request.number }}, cancel-in-progress: true }`;
- the inlined regexes (gated paths; release-exempt files and lines) are generated from
  `infra/gate-executor/orchestrator/gate_orchestrator/gated_paths.txt` (T6.2a) and the ci-cd.md §5 release-exempt
  list by `scripts/ci/gate_router_regex.py`; a test asserts the regexes in the workflow equal the generated ones and
  both equal ci-cd.md §5.

Private workflows: all `runs-on: [self-hosted, linux, a40]` (the **persistent** runner on the VM, T6.2a; the label
`a40` names "the runner that reaches the A40 Ollama servers", the runner itself has no GPU). **One
concurrency group per workflow**, `cancel-in-progress: false` (W2.2, D101), except that `gate-executor.yml`
dispatches get their own group per PR (R9-05): `group: ${{ github.workflow }}-${{ inputs.pr || inputs.sha }}`
(`gate-executor-<N>` | `gate-executor-<sha>`; the `sha` input is added by T7.2, until then the term is empty and
the expression behaves like `inputs.pr`; written in its final form here so T7.2 needs no change; there is no poll,
P1.2); `baseline-promote.yml`, `nightly.yml`, `backup.yml` use
`group: ${{ github.workflow }}`. A newer queued run cancels a *pending* run of the same group, so a shared
cross-workflow group would silently drop nightlies, promotions and dispatches. **GPU mutual exclusion is the host
`flock` on `/var/lib/pruefstand/gpu.lock` taken once per job by the orchestrator** (X2.1, Y1.1/D211, T6.2a; the
owner's and agents' GPU work uses the same file through `pruefstand-lock`); no workflow step calls `flock` or the
T3.1a scripts directly. The runner runs as the system user `pruefstand` (D211). Each dispatch sits in its own group, so a second
dispatch for another PR never replaces it; a repeated dispatch for the same PR queues behind the running one. Private artefact uploads use `retention-days: 14` and contain only `run.json`, `gate.json`,
`comment.md` (W2.11); full run dirs stay on the VM disk (`$PRUEFSTAND_HOME/runs/`). `PRUEFSTAND_HELDOUT_DIR` is set only for trusted
`pruefstand` steps, never passed to the candidate container (X2.5). Crons sit on off-minutes (R9-22); the times in
the text stay "about".
