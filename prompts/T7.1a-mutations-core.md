## Goal

reverted on a temporary worktree.

## Context

Each entry is a directory `benchmarks/mutations/<ID>/` (IDs zero-padded: `M01`, `N03`) with
`mutation.yaml` and either `patch.diff` (`git apply` at `base_sha`) or `rag_overrides` (merged into the worktree's
**`apps/rag-demo/configs/rag.gpu.yaml`**, the tier-2 profile the executor reads from the PR (round 9 X3.15, D9-12);
for `tier1: true` entries the same overrides are also merged into the tier-1 `rag.yaml`, the file `RAG_CONFIG`
selects in tier 1, T1.13).
`MutationSpec` fields:

```text
id, title, kind: config|code|data, patch | rag_overrides, needs_reindex: bool,
cache_invalidating: bool, tier: pr|nightly, splits: [smoke|core|robust_pr|full, ...],
stratum: deterministic|statistical|normaliser, tier1: bool, in_detection_rate: bool,
expected: {status: FAIL|WARN|PASS, hard_fail: bool, metrics: [...], secondary_metrics: [...],
          gated_slices: [...], informational_slices: [...],
          likely_cause: retrieval|generation|citation_format|language|refusal_policy|errors|mixed|null},
rationale
```

**Tier mapping (round 9 X3.10, binding):** each mutation is scored **only in the tier whose split can detect it**,
i.e. where every metric in `expected.metrics` is **gated** under the shipped policy (`pruefstand.yaml`, SPEC
§5.6): `tier: pr` = tier-2 PR run (`splits: [smoke, core, robust_pr]`, PR judge); `tier: nightly` = tier-2 nightly
(`splits: [full]`, run in the **nightly rotation shape** of SPEC §6.2 / round 11 D223: the fixed **refusal stratum**
(all unanswerable cases of `full`, ≥ 100 clusters) plus one of the 3 stratified blocks, ≤ 600 cases; benchmark
nightly-table runs use **block 0**, pre-registered, so baseline and mutant see the same cases). M06
(`refusal_correct`, gated only in nightly runs, on the refusal stratum) → `tier: nightly`, `splits: [full]`, reported
in a nightly table outside the PR-tier headline; M14, M15, M20 (T7.1b) follow the same rule. `secondary_metrics`
may name report-only or experiment metrics (e.g. `evidence_recall`, owned by **T7.3**, X3.2; never gated, not in
`KNOWN_METRICS`); they never decide detection. The **pre-registration check** in `test_mutations.py` asserts for
every `statistical` entry that each `expected.metrics` entry is gated in its declared tier and split.
**Round 13 P3.3 (binding):** for a `statistical` entry `expected.status` is **`FAIL`** (detection counts FAIL only;
WARN is reported separately, never "WARN or FAIL acceptable"). Whether a `statistical` mutation enters the detection
denominator is not declared here: T7.2 decides it from the measured **true effect** on its reference run
("should-detect" = true drop on the expected metric ≥ δ). `mutation.yaml` therefore gets no `should_detect` field;
`in_detection_rate` keeps its meaning (false only for the `normaliser` stratum).

`benchmarks/mutations/index.yaml` holds `base_sha` and the entry list.
**Bug switches first.** rag-demo has real bug switches in `rag.yaml` / `rag.gpu.yaml` since T1.13 / T3.6 (real code paths,
no test doubles): `tenant_filter: inside | post_topk`, `shared_public_merge: filtered | unfiltered`,
`reranker: on | off`, `injection_guard: on | off`, `prompt_file` variants (no citation / no refusal
instruction), `answer_language: auto | en`. A mutation that one of these switches can express is a
`rag_overrides` entry (kind `config`). `patch.diff` is used only where no switch exists.
**Strata and tiers (round 8, binding).** Every entry has `stratum`: `deterministic` = the expected outcome is
a hard fail or an absolute check (M07, M08, M09; later M12, M16), `statistical` = the expected FAIL/WARN comes
from the paired cluster bootstrap (all other M entries except M20), `normaliser` = M20 only (T7.1b; expected PASS,
`in_detection_rate: false`, its own "normaliser robustness" row). This is the one stratum list shared with SPEC
§8 RQ3, T7.1b and T7.2 (AI9-22). The tier-1 gate decides on hard fails and `error_rate` only and reports
language/citation/refusal and injection checks (round 9 X5.6, X3.11); its paired statistics are
`INSUFFICIENT_DATA` at n = 20, so **only entries whose expected outcome is a hard fail or a run-precondition abort
may set `tier1: true`** (M08, M09; M16 in T7.1b); M07 (`injection_success`, ≥ 30 injection cases, Wilson rule) is gated only in **tier 2** (X3.11) and has
`tier1: false`. Mutations that need statistics run in **tier 2** only (W1.5, D98). T7.2 reports the strata
separately.
Expected effects use **gated slices** only for FAIL/WARN claims: `overall`, `tenant`, `lang`, and
`perturbed_all` for retrieval metrics. Perturbation effects show up at PR time through the `robust_pr`
split (40 bases × the perturbations that apply to each base, ≈ 300–440 cases, W3.14 / D125), which the runner scores
through the target's `POST /v1/retrieve` only (no generation, round 11 Y4.1/D222), so only **retrieval** metrics can
be `expected.metrics` on `perturbed_all`; if T3.1b/T6.3 set the D222 reranker-off rule for `robust_pr`, a
reranker-only mutation has no `robust_pr` effect and its pre-registration names that; per-perturbation
slices (e.g. `perturbation=compound_split`) are
informational and go into `informational_slices`. `expected.likely_cause` is the SPEC "7.4" code that
T7.2 checks (null for hard fails and no-ops).
Canary hygiene: M8/M9 use the **held-out** canary set from T2.6, which lives only in the private executor
repo (git-ignored `datasets/private/heldout/canaries_heldout.json` on the executor VM, path from
`PRUEFSTAND_HELDOUT_DIR`). Only the trusted `pruefstand` process reads that registry; it is never mounted into
or reachable by the candidate container (round 9 X2.5). The
framework refuses `--canary-set published` for leak mutations unless `--allow-published` is passed.
`needs_reindex: true` means the executor uses a PR-scoped collection. M2 needs the rag-demo
indexer option `chunking: {strategy: fixed_tokens, size: N}` (T3.4: sub-chunking at index time, so
`corpus_version` is unchanged). If it is missing, record a follow-up for T3.4 and mark M2 `blocked`.
