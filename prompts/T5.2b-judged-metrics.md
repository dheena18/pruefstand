## Goal

Four judged metrics (`faithfulness`, `answer_correctness`, `perturbation_consistency`,
`refusal_judged`) run inside `pruefstand run` through the `JudgePool`, are skipped when a hard fail
fired, and appear in `results.parquet`.

## Context

Metrics live in `pruefstand.metrics.judged` (one layer above `judges`) and type their judge argument
as `core.protocols.JudgePoolLike`. Inputs per metric:

| Metric | Inputs (block names) | `requires` | `applies_to` |
| --- | --- | --- | --- |
| `faithfulness` | `antwort`, `kontext` (**exactly the chunks the generator saw**, in prompt order: the chunks with `used_in_prompt=True`; when the target leaves the field `None`, the first `top_k` returned chunks; W3.4, round 9 X3.14) | `chunks` | all except `UNANSWERABLE`, `INJECTION`, `LEAK_PROBE`, `FILTER_BYPASS`, `SYSTEM_PROMPT_EXTRACTION` |
| `answer_correctness` | `frage`, `antwort`, `referenz` | `reference_answer` set | `FACTUAL`, `MULTI_HOP`, `COMPARISON`, `CROSS_LINGUAL` |
| `perturbation_consistency` | `antwort_basis`, `antwort_variante` | perturbed case + base answer in the same run | cases with `perturbation` set |
| `refusal_judged` | `frage`, `antwort` (no `erwartet`) | – | **ambiguous** answers only (see below), any case with `expect_refusal` defined |

Missing inputs → `status="not_applicable"`, never 0. Cost control (SPEC "10.1 Cost control"): judged
metrics do not run on the `robust_pr` split: the runner calls the target's **`POST /v1/retrieve`** for it (round 11
Y2.3/Y4.1: `{tenant_id, question, top_k}` → `{chunks}`, no generation), so every answer-requiring metric is
`not_applicable` there, never 0.

**Round 8 rules (binding, `docs/planning/reviews/round8-resolution.md`):**

- **Tier 1 (W1.4, W1.6; round 9 X4.5, D9-06, AI9-14)**: judged metrics are **informational** (never decide a
  required check), judged through GitHub Models within **≤ 10 judge calls per PR run** (≤ 60 per nightly); the unit
  is **calls** everywhere: the selection is "as many cases as fit in 10 calls" (2–4 judged metrics per case). Cases
  whose rendered judge inputs contain a registered canary (leak probes, private-doc cases) are **excluded before
  counting**. The order is deterministic, seeded by the **dataset version** (not `eval_fingerprint`), so baseline
  and PR judge the same case ids. The runner calls `Budget.reserve()` before each judge call and `release()` for
  unused repair slots (under an `asyncio.Lock`); a refused reservation → `not_applicable`, reason `judge_cap`, never
  `BudgetExceeded`. The judge cache (W3.2 key, T5.1) is used. Quota exhausted (`QuotaExhausted`) → the remaining
  judged metrics are `not_applicable` (reason `judge_quota`, counted in `counts["judge_skipped"]` by the runner,
  D9-07) and `RunManifest.judge_mode = "skipped"`. No CPU fallback judge. Tier 2 judges `core` with the A40 PR
  judge.
- **Faithfulness context (W3.4, round 9 X3.14)**: `kontext` = the chunks with `RetrievedChunk.used_in_prompt=True`
  (optional field, Target API v1, backward compatible), in rank order; when every chunk has `used_in_prompt=None`,
  the first `top_k` returned chunks. `faithfulness_top_n` is dropped.
- **Judge input cap (round 9 X3.9)**: per judge, cap = the judge's context window − 1 024 tokens (A40 judges:
  the catalogue `options.num_ctx` from `infra/gpu/models.yaml` (AI13-05; Ollama has no `max-model-len`); GitHub Models: the model's documented input limit from
  `llm/quotas.yaml`), counted with that judge's tokenizer (the catalogue entry's `tokenizer: {source, sha256}`, T3.1a, AI13-05; never the `bge-m3` tokenizer). A rendered input over the cap is truncated to fit
  (lowest-ranked `kontext` chunks dropped first, then the last kept chunk cut at a sentence boundary; question,
  answer and reference are never cut) and the value carries `details["truncated"] = True`; truncation is never
  silent: every truncated case is logged (case id, metric, tokens before/after, cap), counted in
  `RunManifest.counts["judge_truncated"]`, and the truncated case ids are listed in the report (T1.9 renders them
  from `details`).
- **Refusal (W3.5)**: refusal is decided by the gate; the target's `refused` flag is informational.
  `refused = phrase_match(answer)` (T1.5b list `metrics/data/refusal_phrases.txt`); a flag/phrase disagreement
  is counted (`counts["refusal_flag_mismatch"]`). **Ambiguous** (round 9 AI9-19) = no phrase match **and** (a
  hedge-lexicon hit: "keine Angaben", "nicht eindeutig", "lässt sich nicht", "not specified", …, versioned in
  `metrics/data/refusal_hedges.txt`, **or** (answer ≤ 40 words **and** no citation **and** no number)). Only
  ambiguous answers go to `refusal_judged`, and only when T5.4 marked the refusal judge as passing
  (`calibration_status.yaml`; otherwise refusal = phrase match only). Layering (round 9 D9-15): the deterministic
  `refusal_correct` / `false_refusal` are computed **before** judges from the phrase match; a runner post-step
  `finalise_refusal(case, values, judged)` in `runner/` rewrites both from phrase match OR the judged verdict and
  sets `details["refused_source"] ∈ {"phrase", "judge"}`. `false_refusal` is gated in PR runs (tier 2) and
  `refusal_correct` nightly-only (round 9 X3.7); when a refusal metric is gated in the run's tier, the refusal
  judge id joins `judge_models` in `eval_fingerprint`.
- **Judge failure (W3.9)**: `LLMError`/timeout/`PolicyViolation` from the judge → `MetricValue(status="error",
  value=None, details={"error": <type>})`; the case continues, the runner (single owner, D9-07) counts the error
  in `counts["judge_error"]`, and the case is left out of that metric's pairing (never worst-filled). If judge
  errors exceed 5 % of `RunManifest.judged_cases` the runner sets `judge_degraded` (T1.8; T5.1 S12 only reads it)
  and judged metrics are informational.
  `BudgetExceeded` is **not** caught here: it propagates to the runner (`stop_reason="budget_exceeded"`, T1.8).
- **Informational switches**: the pipeline builds `informational: Mapping[str, str]` (metric → reason) and
  passes it to `evaluate_gate(..., informational=)`; the reasons are the `SliceDecision.informational_reason`
  values `"tier1_judged"` (every judged metric in tier 1), `"judge_degraded"`, `"judge_drift"` (W3.3; flag
  from T5.1 S13 / T5.4), `"judge_uncalibrated"` (T5.4 found no passing judge, W3.8;
  `judges/data/calibration_status.yaml` `passed: false`), `"judge_truncated"` (round 9 X3.9: more than 5 % of that
  metric's applicable candidate cases carry `details["truncated"] = True`), `"judge_fallback"` (round 11 Y4.4: the run
was judged by any judge other than the configured one, `RunManifest.judge_fallback`, e.g. a configured judge missing from the catalogue (ADR-0019: one judge for PR and nightly); never compared across judges, and the run is not promoted as a judged-metric baseline). `evaluate_gate` itself adds
  `"applicable_clusters<30"` (W3.6). Informational = computed and shown, PASS, outside the Holm family,
  never `fail`/`warn`. `RunManifest.judge_mode` is `"github"` (tier 1), `"local"` (A40) or `"skipped"`;
  `RunManifest.judged_cases` counts cases sent to a judge (tier 1 ≤ 10).
Order per case (interfaces §8): deterministic → hard-fail check → judged. Base answers for consistency
are looked up from the same run's records; the runner judges perturbed cases after their base case.
Real configs only: `examples/live/pruefstand.yaml` (tier 1, T1.12) sets `judge.pr` to a GitHub Models
free-tier model of a non-`qwen` family (W3.1), `budget.max_requests_per_run: 10` (no new config field; the 10-call selection is the runner rule above), no `llm.fallback_judge`, and marks
judged metrics informational; the tier-2 config uses the one A40 judge `gemma3:12b` as `judge.pr` and
`judge.nightly` (ADR-0019) from
`infra/gpu/models.yaml`.
