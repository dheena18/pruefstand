## Goal

Measured evidence that the default thresholds behave as claimed on the real system:
- σ_d per gated metric × gated slice is measured on no-op changes **with regeneration**, i.e. under real answer
  churn (round 9 X3.5, binding);
- the detectable drop (80 % power) at the core size is reported against δ, and the core size needed is
  computed where it is too large;
- the expected no-op false-block and false-warn rates of the **full gate** are estimated from the measured σ_d;
- PR-tier timing meets the budget.

Validating `likely_cause` on real mutations is **not** this task (it needs T7.1a/T7.1b runs); it is done in
T7.2. Here `likely_cause` is checked against the **real rag-demo bug switches in tier 2** (A40 executor,
`core` split). Round 8 (binding): the tier-1 gate decides on deterministic checks only and its paired
statistics are `INSUFFICIENT_DATA` at n = 20 (W1.3), and bug-switch scenarios that need statistics run in
**tier 2** (W1.5, D98). Tier 1 keeps only the deterministic scenario matrix (T1.11).

## Context

δ (`max_drop`) is a **product decision**, not a noise artefact. Defaults: 0.05 for
answer_correctness, faithfulness, context_recall, `citation_recall` (the gated citation metric; `citation_f1` is
report-only, AI9-18) and `false_refusal`; **0.10 for refusal_correct** (D142; gated in nightly runs only — every nightly contains the fixed **refusal stratum** of `full` (all unanswerable cases, ≥ 100 clusters; SPEC §6.2, D223), so it is gated every night, MDE
reported in `mde.csv` and the comment). `false_refusal` applies to the answerable cases and **is gated in PR runs**
(round 9 X3.7, D167: `core` = 300 cases = 220 answerable, 50 unanswerable, 30 security probes). Noise is
already inside the paired bootstrap's variance, so δ is **not** set "above noise".
All tier-2 runs use the tier-2 rag-demo profile `apps/rag-demo/configs/rag.gpu.yaml` (round 9 X3.15); `rag.yaml`
is the tier-1 CPU profile and is not used here. Slices follow X3.6: `robust_pr` perturbed cases count only in
`perturbed_all`; `overall`, `tenant` and `lang` use unperturbed cases.
This study:
1. **σ_d from no-op changes with regeneration (round 8 W3.7, D118; round 9 X3.5 / D165, binding).** Paired runs
   of `main` against **no-op changes** that a real PR produces without changing behaviour, each with **real
   regeneration**: target cache off, the index **rebuilt**, and a **different generator sampling seed** per run, so
   every answer is generated again. Kinds: (a) **re-index** (fresh Qdrant collection from the same corpus
   version), (b) **reordered config** (`rag.gpu.yaml` keys and list order permuted, same values), (c) **rebuilt
   image** (same source, new build → new digest). Each kind × 2 runs against a `main` run, judge cache on. The
   pooled **σ_d(no-op)** is the number for the no-op A/A replay (SPEC §7.3). Because at
   the production temperature 0 a new seed alone mostly measures serving nondeterminism, a **churn arm** (AI9-09)
   adds behaviour-neutral but answer-changing PRs: N04 prompt synonym, the generator in a second quantisation of
   the same checkpoint (N09: two Ollama quantisation tags of the same Qwen checkpoint, e.g. `q8_0` vs `q6_K`, both catalogue entries with their own digest; **verify** both tags exist and fit one card with `num_ctx` 8192) and the same config at temperature 0.3 with
   3 seeds. Round 12 N2: `llm-proxy` enforces only `num_ctx` and `keep_alive`, so rag-demo's `generation.temperature`
   and `seed` from `rag.gpu.yaml` **reach the generator** (within the catalogue `option_bounds`); the `temp03` arm and the
   per-run seeds of the no-op runs are real behaviour changes, not identical re-runs (checked below). **σ_d(churn)** is the number for **MDE sizing** and the `core`-size check (steps 3 and 5) and the
   second arm of the replay (SPEC §7.3). The **identical repeats** (unchanged `main` 5 times, production caches
   on, and with all caches off) are the **floor**.
2. Estimates σ_d per metric × gated slice from all run pairs (per-case paired diffs, cluster-aware), per
   no-op kind and pooled, for the no-op and churn arms. **The runs estimate σ_d only**; a handful of pairs cannot
   estimate a ~2 % false-block rate. Only metric × slice pairs with **≥ 30 applicable clusters** are gated (W3.6,
   D117); `false_refusal` is measured on `core` (≈ 220 answerable clusters); `refusal_correct` is gated only in
   nightly runs, whose fixed refusal stratum holds all unanswerable cases of `full` (≥ 100 clusters, SPEC §6.2), so
   its σ_d is measured on that stratum; it uses δ = 0.10 (D142) and its `mde.csv` row is expected at ≈ 1.2δ. The
   answerable metrics of a nightly are measured on one stratified block (≤ 600 cases in total with the refusal
   stratum); `mde.csv` gets one row per block id 0/1/2 so the nightly's real power is visible (D223).
3. Computes the detectable drop with `minimum_detectable_effect(se, alpha, delta, m=m_family)`, where
   `m_family` = size of the run's single Holm family (all gated metric × gated slice pairs). It already
   includes the δ floor: max((z₁₋α/m + z₀.₈)·se, δ + z₀.₈·se).
4. Estimates the full-gate no-op rates by **A/A replay**: resample the paired per-case scores with the
   measured σ_d (≥ 2 000 synthetic no-op pairs per arm, CPU only) through `evaluate_gate`, once with
   σ_d(no-op) (the checked arm) and once with σ_d(churn); reports FAIL and WARN-or-FAIL rates with Wilson 95 % intervals per
   arm. The real no-op runs are a sanity check. T7.2's replay arm uses both σ_d values and reports both.
5. Checks MDE ≤ 1.5δ per gated metric at its applicable `core` cluster count with σ_d(churn) (SPEC §7.2/§7.3).
   If not, writes the per-metric `core` quota needed (power 0.8 at Δ = 1.5δ) as a follow-up for the dataset task.
   **No threshold change is made to hide it; δ is never raised silently.**
6. Times every PR-tier stage (target, retrieval/reranker lane, deterministic, judges) against the budgets (D199,
   round 11 D222/D223, gpu-cluster.md §5): PR tier (core + `robust_pr`) ≤ **90 min**, where `robust_pr` calls the
   candidate's `POST /v1/retrieve` only (no generation, Y4.1) and the tier-2 reranker reranks the top **10** passages
   truncated to 256 tokens, batched (Y4.2); the **reranker lane** (VM CPU `rerank-cpu`) is timed on its own and must
   be ≤ **20 min** per PR run, else record it and run `robust_pr` with the reranker off (documented as first-stage
   robustness, D222); the nightly = the fixed **refusal stratum** (all unanswerable cases of `full`, ≥ 100 clusters)
   **plus one of 3 stratified blocks**, at most **600 cases** in total, so `full` is covered every 3 nights (SPEC §6.2,
   D223); a model reload during a run aborts it as `infra_error` (SPEC §6.2) and the run is repeated; the whole
   `nightly.yml` ≤ **8 h** inside 22:00–06:00 Europe/Berlin (generation on GPU0 overlapping gemma judging on GPU1,
   D205/D223); smoke ≤ 10 min; the first model load of a mode (from the NAS) is excluded and reported separately.
   If the PR tier exceeds 90 min, record it and switch PR runs to the fixed 150-case judged subset of
   `core` (D199, `pruefstand run --judged-subset`, T1.10/T4.1; round 13 P3.4: it limits generation **and** judging of
   the `core` answerable cases, the others run retrieve-only; deterministic security cases always run in full) and recompute
   the MDE rows for that subset; never shrink a split silently. The nightly block sizes come from the dataset
   manifest's `blocks` (T4.1); `mde.csv` uses the **measured** unperturbed answerable cluster count per block (P3.1
   quota: 300 unperturbed answerable cases with ≥ 250 clusters per block, AI12-05b), never the SPEC planning number. Record the measured weekly cause-switch duration (S4) so T6.2b can check that it fits the
   Sunday window.

## Constraints and non-goals

- Thresholds live in config, never as constants in `gate/` (rule-internal constants in `cause.py` excepted).
- Do not change the statistical method (ADR-0007). If the detectable drop at σ_d(churn) is > 1.5δ, record the core quota needed and open a follow-up.
- No direction field on `MetricPolicy`. No change to `gate/cause.py` (validation on real mutations is T7.2).
- Every `[GPU]` command of this task runs under the shared lock as the owner user: `pruefstand-lock <cmd>` (lock file `/var/lib/pruefstand/gpu.lock`, the same one the executor's orchestrator takes; round 11 Y1.2/D212), never while `/var/lib/pruefstand/MAINTENANCE` exists, and outside the night window 22:00–06:00 Europe/Berlin (D223). Long loops are wrapped as one locked command (`pruefstand-lock bash -c '…'`) so no gate job can switch modes between runs of one noise arm; never touch `/var/lib/pruefstand/**` directly.
- A run that ends with `stop_reason="aborted"` and `infra_error` (Y5.2) is discarded and repeated; it never enters a σ_d estimate.
