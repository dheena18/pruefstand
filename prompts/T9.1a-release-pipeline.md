## Goal

Merging the release-please PR publishes the following, with no long-lived secret:
- the `pruefstand` wheel and sdist to PyPI;
- signed container images (Action + rag-demo) on GHCR, with SBOM and provenance;
- a GitHub Release with changelog.

Every image is built **once**, at the tag, and is never overwritten.

## Context

**Tags must trigger workflows.** Tags and releases created with `GITHUB_TOKEN` do not start
other workflows, so `release-please.yml` uses a token of GitHub App `pruefstand-release`
(contents: write, pull_requests: write; installed on the public repo only, separate from the gate
App `pruefstand-bot`). The App token is minted only in environment `release`, which has deployment-branch
policy `main` only and **no required reviewer** (it runs on every push to `main`; a reviewer would leave a
pending approval after every merge). Required reviewers stay on `pypi`, `demo` and `huggingface`.

**One version, plain `v*` tags.** release-please runs in manifest mode with a **single** package (the
repo root, `release-type: python`, `include-component-in-tag: false`), so tags are `vX.Y.Z` and match
`on: push: tags: ["v*"]`. `extra-files` bump the version strings in `packages/pruefstand/pyproject.toml`,
`apps/rag-demo/pyproject.toml` and `action/action.yml`.

**`uv.lock` in the release PR (round 9 X2.9, binding; D159).** `pruefstand` and `rag-demo` are uv workspace
members, and `uv.lock` records their versions, so after a bump `uv sync --locked` (ci.yml, the rag-demo
Dockerfile, live-e2e) would fail on every release PR. `release-please.yml` therefore has a second job step that
runs **after** release-please has created or updated the release PR: check out the release branch
(`release-please--branches--main`), run `uv lock` with the pinned uv version, and, if `uv.lock` changed, commit
**only** `uv.lock` (message `chore: update uv.lock for release`) and push it to the release branch with the
`pruefstand-release` App token. This is the **only** bot commit on the release PR. release-please force-rewrites
its branch when it updates the PR, so the step runs on **every** `release-please.yml` run that touched the PR and
re-applies the lock update (idempotent: no change → no commit). The diff it adds must be exactly the `version`
lines of the two workspace-member entries (`pruefstand`, `rag-demo`) in `uv.lock`; the step fails if `uv lock`
changes any other line (dependency drift belongs in a normal PR). Because the push uses the App token, it
triggers the required checks on the release PR.

**Release PRs are not gated (round 8 W2.6, D105).** `apps/rag-demo/pyproject.toml` is under the gated path
`apps/rag-demo/**`, so the executor's `select_jobs` (T6.2a) exempts a release-please PR whose diff only
touches the version strings listed in `extra-files`, `.release-please-manifest.json` and `CHANGELOG.md`: it
gets `pruefstand/gate` = success "not gated (release version bump)". The exemption also covers exactly the two
member `version` lines in `uv.lock` written by the `uv lock` step (X2.9; ci-cd.md §5; T6.2a `select_jobs`); any
other `uv.lock` line, or any other change in a release PR, is gated normally. Keep `extra-files` and the lock
lines exactly in sync with that rule (a test checks it).

**Tag protection.** Legacy tag protection is retired: S5 creates a **tag ruleset** on `refs/tags/v*`
(restrict creation, update, deletion; bypass = App `pruefstand-release` only).

**Pages has one writer.** `docs.yml` (T0.4) deploys GitHub Pages on every `main` push; `release.yml` has
**no** `docs-deploy` job (two writers would overwrite each other and conflict).

**Images (build once at the tag):** `release.yml` builds the Action and rag-demo images from the tag,
first checks that `ghcr.io/dheena18/pruefstand-action:vX.Y.Z` does **not** exist yet (fail otherwise:
no overwriting), pushes `:vX.Y.Z`, signs the **digest** keyless with the `release.yml@refs/tags/vX.Y.Z`
identity, and records tag → digest in `image-digests.json` and the release notes. `action/action.yml`
references `docker://ghcr.io/dheena18/pruefstand-action:vX.Y.Z` (bumped by release-please); users who
want immutability pin the digest from the release notes.

**PyPI:** job `publish-pypi` uses `environment: pypi`, job-level `id-token: write`, and
`pypa/gh-action-pypi-publish` pinned by SHA. There is no API token.
- TestPyPI has its **own** trusted-publisher registration (environment `testpypi`).
- Release candidates come from `workflow_dispatch` with `prerelease: true`, not from tags. A dispatch run
  executes only `build-dist` + `publish-testpypi`; every image, sign, SBOM and `publish-pypi`
  job has `if: startsWith(github.ref, 'refs/tags/v')`, so an RC never pushes images or `image-digests.json`
  (T8.5's `deploy.yml` also ignores non-`push` `release.yml` runs).

**Images and supply chain:**
- Trivy blocks on HIGH/CRITICAL with a fix available (the docker.md policy, with ignore-file
  rationale).
- SBOM with syft (SPDX JSON), attached via `cosign attest --type spdxjson` and as a release asset.
- Provenance via `actions/attest-build-provenance`.
- Release assets written by `release.yml` are exactly its own (`image-digests.json`, the SBOM, the dists); it never writes, overwrites or deletes `demo-ready.json`, which only the public `demo-ready.yml` (T8.5) uploads to the same release (round 13; upload with `gh release upload` without `--clobber` for any other name).
- `image-digests.json` (tag → digest per image) is published as a **release asset** of the GitHub release (round 12, ci-cd.md; A12-M9: it does not expire, unlike an artefact) and also uploaded as an artefact; T8.5 and the private `demo-nightly` read the digest from the release asset.
- GHCR visibility: `rag-demo` is already **public** since T6.2b (W2.8, D107); S5 also makes
  `pruefstand-action` public after its first push.

**Permissions:** top-level `permissions: {}`, per-job minimal. `id-token: write` is granted only on the
publish and sign jobs.

**User verification:** `cosign verify ghcr.io/dheena18/pruefstand-action@sha256:<d>
--certificate-identity https://github.com/dheena18/pruefstand/.github/workflows/release.yml@refs/tags/vX.Y.Z
--certificate-oidc-issuer https://token.actions.githubusercontent.com`
