## Goal

Correct, fast, fully tested statistical primitives for the gate:
- a vectorised paired **cluster** bootstrap that gives a one-sided p-value for "no drop", with an exact sign-test fallback when there is little information
- Holm and BH adjustment
- the Wilson interval and the absolute-check decision
- the PASS / WARN / FAIL / INSUFFICIENT_DATA decision for one (metric, slice) pair
- closed-form power and MDE helpers

A Monte-Carlo test proves the error rates. Slices, the Holm family over the run and hard fails are T1.7.

## Context: the decision rule (SPEC §7.2, binding)

- `diffs[i]` is already oriented so that **negative = worse** (T1.7 flips metrics with `higher_is_better=False`).
- Clusters = `TestCase.cluster_id`: cases from one source document are resampled together. k = number of distinct clusters.
- **Estimand:** the mean over cases (each case weight 1); clusters are only the resampling unit. State this in the docstring.
- **Bootstrap replicates:** precompute per-cluster `sums` and `counts`; for each replicate draw k cluster indices with replacement; replicate mean = `sums[idx].sum() / counts[idx].sum()`.
- **Small-sample correction (always applied, k ≥ 2):** the plain percentile bootstrap is anti-conservative for small k (≈ 0.032 instead of 0.025 at k = 30, from Student-t tails). Before computing p and the CI, rescale every replicate's deviation from the observed mean:
  `boot_c = mean_diff + (boot − mean_diff) · c_k` with `c_k = sqrt(k / (k − 1)) · t_{k−1, 1−α} / z_{1−α}` and α = 0.025 (the policy's α, passed in via `alpha`).
  At k = 30, c_k ≈ 1.061; at k = 300, c_k ≈ 1.006. `t` from `scipy.stats.t.ppf`, `z` from `statistics.NormalDist`. k = 1 → c_k = 1 (and the pair is insufficient data anyway).
  This correction is already in SPEC §7.2, ADR-0007 and interfaces §9 (`paired_cluster_bootstrap(..., alpha=0.025)`).
- **p-value (H0: Δ ≥ 0, no drop):** `p = (1 + #{boot_c ≥ 0}) / (B + 1)`. **CI:** two-sided percentile interval of `boot_c` at `confidence` (display only). **SE:** standard deviation of `boot_c` (`BootstrapResult.se`).
- **Sign-test fallback:** if fewer than 10 clusters have a non-zero cluster-mean diff, `p` comes from an exact one-sided sign test on the non-zero cluster mean diffs: `p = P(X ≤ n_pos)`, `X ~ Binomial(m, 0.5)`, m = number of non-zero clusters, n_pos = number of positive ones; m = 0 → p = 1. `method="sign_test"`; the CI and SE still come from the corrected bootstrap.
- **`decide(r, *, max_drop, p_adjusted, alpha, warn_p, min_clusters, gated)`**, in this order:
  1. `r.n_clusters < min_clusters` → `INSUFFICIENT_DATA`
  2. `gated is False` → `PASS` (informational slice; T1.7 sets `notable` from BH; it never WARNs or FAILs)
  3. `p_adjusted < alpha` **and** `r.mean_diff < −max_drop` → `FAIL`
  4. `p_adjusted < warn_p` **and** `r.mean_diff < −max_drop` → `WARN`
  5. otherwise `PASS`
- **`decide_absolute(k, n, *, max_value)`** (SPEC v2.4 §7.2, round 9 AI9-24): `FAIL` if the Wilson 95 % **lower** bound of k/n > `max_value`; `WARN` if the Wilson lower bound > `max_value / 2`; else `PASS` (a point estimate above `max_value` alone does **not** warn: at n ≈ 30–60 and a 1 % per-case rate it would warn on most no-ops). n = 0 → `PASS`. No `min_clusters`. The second WARN trigger of SPEC §7.2 ("or the paired `max_drop` rule warns") is applied by `evaluate_gate` (T1.7 step 7), not here.
- **Power (normal approximation of the rule):** FAIL iff mean < −max(δ, z·se) with z = z₁₋α/m and se = σ_d/√n. So `power_estimate(sigma_d, n_clusters, delta, alpha, m, *, true_drop=None)` = Φ((true_drop − max(δ, z·se)) / se), `true_drop` defaults to 2δ. It models one case per cluster.
- **MDE:** `minimum_detectable_effect(se, alpha, delta, power=0.8, m=1)` = max((z₁₋α/m + z_power)·se, δ + z_power·se).
