## Goal

`experiments/rq2/` reproduces a calibration table for the candidate judges below on the T5.3 label sets (human
annotations from MEMERAG and GermanQuAD, plus labels true by construction): binary agreement with
CIs, the ability to discriminate degraded answers, request/GPU cost, latency and bias. It records the
chosen PR judge (tier 2), the tier-1 informational judge and the nightly judge, the pass/fail status of
calibration, the `judge_epoch` per judge, the 50 drift-anchor items per pinned judge, and the limitations of
constructed labels.

Agreement statistics (primary): **binary** Cohen's κ, judge "2" vs "< 2" on 3-point metrics and the
raw label on binary metrics, against the T5.3 labels; plus accuracy, balanced accuracy and Gwet's AC1

bootstrap** over `cluster_id` (2,000 resamples, seed 1234). Quadratic-weighted 3-point κ is computed

reported by its paper (cite it); for constructed sets, "n/a (labels by construction)".
Discrimination: 50 `correctness` positives (label 2) are paired with `swap_first_number` versions
(T5.3 rule), and 50 with `negate` versions. A judge passes if it scores the degraded version strictly
lower in ≥ 90 % of pairs **per edit type**.
**Dev/test (round 13 AI13-12, binding):** prompt iteration, rubric changes and the choice between candidate judges use
only the T5.3 `calib_split == "dev"` items; the pass rule below and every RQ2 number are computed **once per prompt
version on `test`**, and `calibration_status.yaml` and the RQ2 report state the number of prompt versions tried next to κ.
**Pass rule (round 9 X1.1, binding; replaces the round-8 hard-negative κ).** Per metric, a judge passes only if
(1) binary κ ≥ 0.6 on the **full** calibration set of each gating label set (faithfulness: MEMERAG and
`legal_hard`; correctness: `correctness` and `legal_hard`), **and** (2) **specificity** (true-negative rate) ≥ 0.80
on the **hard-negative subset** (`hard_negative=True` items of T5.3, incl. MEMERAG "Not Supported" and every
`legal_hard` edit) **with the 95 % Wilson lower bound ≥ 0.70** (`judges/calibration.py specificity`, interfaces
§6), **and** (3)
discrimination ≥ 0.90 (unchanged). κ is **never** computed on a single-label subset: every hard negative has
label < 2, so κ there is 0 or `nan` by construction (AI9-01). Never lower the thresholds.
**Refusal judge (round 9 AI9-19)**: `refusal_judged` passes iff accuracy ≥ 0.95 on the T5.3 `refusal` set
(incl. the 50 in-domain near misses) **and** false-positive rate on `hard_type="hedged_answer"` ≤ 0.05; otherwise
`calibration_status.yaml` marks it failed and refusal = phrase match only (T5.2b).
Selection: the cheapest passing judge (GPU-seconds) that fits the day GPU1 plan becomes the tier-2 PR judge
— (a) if it passes, else (a'). The passing `gemma` judge (b) becomes the nightly judge (if it fails, the nightly uses the PR judge; any run judged by a judge other than the configured one has its judged metrics informational with reason `judge_fallback` and is never compared across judges, round 11 Y4.4). **Family separation when `gemma` becomes the PR judge (round 11 AI11-12a)**: the `core` references touched by the gemma review batch are re-reviewed with `mistral` in reject-only mode and rejected items are regenerated by datagen (T4.2 follow-up); record it in `docs/decisions.md` next to D168. Judge (c) is
recorded with its numbers; tier-1 judged metrics are informational regardless (W1.4).
**If no judge passes** (W3.8): pin the best-κ local judge anyway, write
`packages/pruefstand/src/pruefstand/judges/data/calibration_status.yaml` with `passed: false` (per judge
and metric), so judged metrics are **informational only** in both tiers (T5.2b reads it), and open a
follow-up task (better prompt version or another judge). With a passing judge the file says
`passed: true` for it.
**`judge_epoch` (round 9 X3.3)**: `calibration_status.yaml` holds the integer `judge_epoch` (`RunManifest.judge_epoch`,
interfaces §1.4; starts at 1) and, per pinned judge, its **serving version** (engine + engine version +
quantization + model digest[:12] from `infra/gpu/models.yaml`, round 11 AI11-09; GitHub Models: the pinned model id). Both feed `eval_fingerprint`
(T1.1 / T5.2b S6). Only a **successful re-calibration** of a pinned judge (this task's pass rule re-run on the
full sets) bumps `judge_epoch`; the
fingerprint change then forces `no_baseline` until `baseline-promote` re-runs `main` (D103), so baseline verdicts
are never mixed with another judge state.
**Drift anchors (W3.3, round 9 X3.4)**: for every pinned judge, select **50** anchor items (seeded, stratified by
metric and label, half of them hard negatives, publishable sets only (incl. `legal_hard`), so they may go to
GitHub Models) and store the rendered judge requests with the judge's raw verdicts in
`packages/pruefstand/src/pruefstand/judges/data/anchors/<model-slug>.jsonl`. `judges/drift.py`
`anchor_agreement(stored, fresh) -> float` (interfaces §6, D114) = share of the 50 anchors with equal `raw_score`
(`ValueError` on length mismatch). The **nightly drift step** (this task): `pipeline/judge_drift.py` + CLI
`pruefstand judge-drift --judge <model> --anchors <file>` (interfaces §15) re-judges the anchors **with the cache bypassed**.
**Drift rule (round 12 N3, binding; supersedes the R9 X3.4 Wilson form and the R11 AI11-10/D246 binomial form):** one
rule for hosted **and** local judges: `changed = n − round(agreement · n)` (anchors whose `raw_score` differs from the
stored verdict); **drift iff `changed ≥ max(3, ceil(0.1 · n))`** (n = 50 → 5). `judges/drift.py is_drift(agreement, n,
*, a0=None)` keeps its signature (interfaces §6): `a0` (the local judge's self-agreement, S11, judged twice at production
concurrency `OLLAMA_NUM_PARALLEL=4`) is accepted and written to `judge_drift.json` for the report but **does not enter
the decision** (a single double-judging gives `a0 = 1.0` often, which made any flip an alarm, AI12-03).
**Threshold check against the measured flip rate (round 13 AI13-07):** S11 judges the 50 anchors **≥ 4 times** at
production concurrency, estimates the per-anchor flip rate f with a 95 % CI (upper bound f̂_upper) and computes
P(false drift per night) = P(Bin(50, f̂_upper) ≥ 5). If it is ≤ 1 %, the threshold stays 5; otherwise it is raised to
the smallest c with P(Bin(50, f̂_upper) ≥ c) ≤ 1 %, recorded per judge in `calibration_status.yaml`
(`drift_threshold`) and used by `is_drift(..., threshold=<that value>)` (new keyword-only `threshold: int | None =
None`, default = the N3 rule; interface change listed in the reply). For local judges a
digest/engine mismatch also counts as drift (already `health.sh` exit 13). Clearing a local-judge flag needs only an anchor re-run that
passes (`clear_drift`), not a `judge_epoch` bump → writes
`judge_drift.json {model, agreement, changed, threshold, a0,
cache_epoch, ts}` and calls T5.1's `invalidate_judge` (cache-epoch bump), so later runs set
`RunManifest.judge_drift` and the pipeline marks that judge's metrics informational (`"judge_drift"`). **Drift
never changes `eval_fingerprint`** (it holds the configured gating judges, their serving version and
`judge_epoch`, independent of run-time flags); the flag stays until a re-calibration passes, bumps `judge_epoch`
and calls `clear_drift`. It runs in the tier-1 `live-e2e.yml` nightly job for the GitHub judge (own hunk; 50 of
the 60 nightly calls (W1.6): on a drift-check night the tier-1 nightly judged sample is limited to the remaining
10 calls) and in the tier-2 `nightly.yml` `judge-drift` job (T6.2b) for the A40 judges.
Limitations to write into `experiments/rq2/README.md` and hand to T9.3: constructed labels have no
partial credit; off-topic constructed negatives are easier than real errors, so κ on them is an upper
bound, which is why hard-negative specificity is reported and gated separately; MEMERAG answers come from
other systems and MIRACL contexts, not from the reference app. Datagen (`llama`) differs from both
gating judge families (`mistral`, `gemma`; D141); only the optional (b') arm shares the datagen family, so
its `answer_correctness` agreement is reported separately and never used to pick a judge.
