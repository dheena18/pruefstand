## Context

Same schema, tools and validation as T7.1a. Generator swaps must use a catalogue model;
otherwise the gate reports `UNSUPPORTED_CONFIG`. T7.1a's test requires every `rag_overrides` key to exist in
`RagConfig`: a "config" row whose knob is not a `RagConfig` field (check M13 `rerank.top_n`, M15 RRF `k`) becomes
`kind: code` with a `patch.diff`; never add the field to rag-demo on `main` here. **M17 (round 12 N2):**
`generation.temperature` is a `RagConfig` field sent by rag-demo's tier-2 client as the Ollama option `temperature`
(T3.6), and `llm-proxy` now passes sampling options through within the catalogue `option_bounds` (it enforces only
`num_ctx` and `keep_alive`), so M17 is `kind: config` with `rag_overrides: {generation.temperature: 0.7}` and really
reaches the generator; a test asserts 0.7 lies inside the generator's catalogue `option_bounds.temperature`. M13: the
tier-2 reranker reranks the top **10** passages (Y4.2/D222; the old "T3.5 default `top_n = 20`" no longer holds), so
the mutation sets `rerank.top_n` from the actual configured value (10) to 2 and records both numbers in the rationale.
Round 8/9 (binding): every entry sets `stratum`, `tier`, `splits` and `tier1` as in T7.1a (only hard-fail or
precondition entries may be `tier1: true`; mutations needing statistics run in tier 2 only, W1.3/W1.5). Here M12
(language) and M16 (precondition abort) are `deterministic` (M16 `tier1: true`; M12 `tier1: false`, because the
tier-1 language check is reported, not decided, X5.6/D188); M20 is the only `normaliser` entry
(`in_detection_rate: false`, a separate "normaliser robustness" row, SPEC §8); all others are `statistical`.
**Tier mapping (round 9 X3.10):** each mutation is scored only where its expected metric is gated. M14 and M15
(`ndcg_at_k`, gated `max_drop` 0.05, SPEC §5.6) → `tier: pr`, `splits: [core]`, and they are also reported in the
nightly table (nightly rotation shape, block 0, T7.1a/D223); M15's typo effect is reported on that nightly run's
`perturbation=typos` slice (informational), not on `robust_pr`. M13 changes the reranker: since the tier-2 reranker
reranks the top 10 passages truncated to 256 tokens (round 11 Y4.2/D222), M13 sets `rerank.top_n` from the
**configured** value to 2 and its rationale records both; with the D222 reranker-off rule active for `robust_pr`, M13
has no `robust_pr` effect (expected on `overall` only). M18/M19 expect `context_recall` on `perturbed_all`, scored
through `/v1/retrieve` (no generation, Y4.1). M20 → `tier: pr`, `splits: [core]`, also run nightly, never counted in the
detection rate. The T7.1a pre-registration check covers all of them. `rag_overrides` target
`apps/rag-demo/configs/rag.gpu.yaml` (X3.15). M11 stays inside the generator family
`qwen` (a smaller local Qwen from `infra/gpu/models.yaml`, W3.1 / D112; never a hosted generator, W3.15 /
D126), so the judge-family rule still holds. **M11 model (round 10):** an official Qwen3 8B or 14B `q8_0` **Ollama
tag** (catalogue id `ollama/<tag>`, its own fixed catalogue `options`, round 11 Y3.2/Y3.3) on GPU0 (gpu-cluster.md §2, chosen and pinned by digest in T3.1b; **verify** the exact tag in the Ollama
library and that it is in the catalogue with `role: generator`, family `qwen`, `num_ctx: 8192`, thinking off). The
swap is an unload/load on `ollama-gpu0` by the orchestrator under the lock (T6.2a `serve`), never by the mutation.
