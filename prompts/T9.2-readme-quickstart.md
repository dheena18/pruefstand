## Goal

A README a recruiter understands in 60 seconds and a stranger can follow on a fresh machine to get a
gate report in under 20 minutes (model download included) — proven by a CI job that runs the quickstart verbatim in a clean
container.

## Context

The quickstart must not need a GPU or any API key, and it runs the **real stack** (no test doubles):
`pip install pruefstand` (or `uvx`), then `pruefstand init --example quickstart ./demo` copies out of
the **wheel** (package data `pruefstand/examples/quickstart/`) a `docker-compose.yml` that pulls the
signed GHCR rag-demo image by digest, the pinned llama.cpp server image + GGUF generator, the CPU
judge model of another family, Qdrant and the CPU embedding service `embed` (T1.13) — rag-demo waits for
it — plus a one-shot `index` service that runs the rag-demo indexer on the bundled corpus before
`rag-demo` starts (the tier-1 `live` profile from T1.13/T1.12: **no reranker**; `rag.yaml` keeps the
interfaces §16 default `reranker: off`, UI11-16); the real
5-law slice corpus and the 40 hand-written smoke cases from T1.11; `pruefstand.yaml` (judge = CPU
llama.cpp, so no token is needed; GitHub Models is shown as an optional upgrade); `rag.yaml`; and the
bug variant `rag.bug.yaml` (`tenant_filter: post_topk`, a real rag-demo switch). The package data is
generated from the repo's `examples/live/`, `datasets/fixtures/` and the rag-demo configs (`apps/rag-demo/configs/rag.yaml` → `rag.yaml`,
`apps/rag-demo/configs/bugs/tenant_filter_post_topk.yaml` → `rag.bug.yaml`, T1.13) by a script so they never drift.
The user sees a real PASS (`rag.yaml` vs itself) and a real hard FAIL (`rag.bug.yaml` leaks another
tenant's canary). `init` is implemented here (`cli/init.py`); it is already listed in interfaces §15, so no interface change.
GitHub Action usage is documented as `uses: dheena18/pruefstand/action@vX` (Linux runners; the
Marketplace repo is mentioned only if T9.1b is done). A second, optional section shows the A40 / tier-2 setup. README sections:
one-line pitch, GIF of a blocked PR, results table (RQ3 headline, from `results/rq3/table.md` via an
include marker), architecture diagram (Mermaid), quickstart (5 commands), how it works (3 bullets),
German failure modes, **live demo** (UI-27: dashboard URL from T8.5 —
`https://dheena18.github.io/pruefstand/de/` and `…/en/` (GitHub Pages site root, D243; docs at `…/pruefstand/docs/`) — plus the
Try-it page `…/pruefstand/de/try/` only if T8.4's demo is deployed on the VM (`https://demo.<domain>`
behind the Cloudflare Tunnel, Y7.5; it may be paused by the kill switch, so the README says
"when available"); a dashboard screenshot of the FAIL run summary taken
from T8.3's committed visual baselines (project `populated-1280`, fixture `F-FAIL`, `en`), light and dark via `<picture>` +
`prefers-color-scheme`, with alt text naming status and blocking count; the section is omitted if T8.5
is not done), docs links, data licenses, citation (`CITATION.cff`). "How it works" says that tier 1
decides on hard fails and the error rate only, reports language, citation, refusal and injection
results plus an informational judge, and that tier 2 runs the statistical gate (ui-spec §12, X5.6); for
PRs, tier 2 starts only when the maintainer dispatches the private `gate-executor.yml` (R13 P1.2,
D288). The README never mentions a `run-gate` label (it no longer exists). Code blocks in README are
extracted and executed by the CI job — a README block marked `<!-- quickstart -->` is the single source.
