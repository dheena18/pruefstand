## Goal

`experiments/rq3/` pre-registers the analysis, then runs every mutation and no-op through the
executor, applies three gate variants to the **same** runs and produces the headline table. The table
gives detection, false-block and false-warn rates (with CIs), time and cost per run, a dose-response
comparison at matched error rates, and the first validation of `likely_cause` on real mutations
(moved here from T6.3).

## Context

**Pre-registration:** `experiments/rq3/PREREGISTRATION.md` is written and committed
**before** any mutation run. Its commit SHA is recorded in every output file. It fixes:
- the three variants and their parameters;
- the expectations taken from `mutation.yaml`;
- the **true-effect reference** (round 13 **P3.3**, binding): every `statistical` mutation's true effect is measured
  on a large reference run of **all 3 blocks + the refusal stratum of `full`** (`--split full --stratum all`, no
  block), **3 seeds**, each paired with a **matched `BASE` re-run** of the same shape and seed made for that
  mutation (never one shared baseline); Δ̂_true = mean over seeds of the paired cluster-bootstrap mean drop on the
  expected metric, with its 95 % CI. A mutation is **should-detect** iff Δ̂_true ≥ δ of that metric; the rule is
  fixed here before any run;
- the primary outcomes (detection rate on the **should-detect `statistical` mutations, per tier**, plus the
  `deterministic` stratum; the mutations with Δ̂_true < δ in a separate table ("correctly passed" vs "flagged
  anyway"); false-block and false-warn rates on **N01–N10**), reported in the pre-registered **strata** from `mutation.yaml` `stratum` (T7.1a/b; the one list
  shared with SPEC §8, AI9-22): `deterministic` (M07, M08, M09, M12, M16 — caught by hard fails, absolute checks or
  the precondition, so every variant catches them by construction), `statistical` (M01–M06, M10, M11, M13–M15,
  M17–M19; M14 = "embedding input truncated to 128 tokens", P3.3) and `normaliser` (M20 only: expected PASS, its own "normaliser robustness" row, **outside** the
  detection rate). **The headline comparison with the naive and no-slices gates is on the `statistical` stratum
  of the PR tier only**; the pooled number is secondary;
- **tier mapping (round 9 X3.10, binding):** each mutation is scored **only in the tier whose split can detect
  it**, as declared by `tier` / `splits` in its `mutation.yaml` (T7.1a pre-registration check): PR-tier entries on
  `smoke` + `core` + `robust_pr` with the PR judge; M06 (`refusal_correct`, gated only in nightly runs, on the
  refusal stratum) in a **nightly table** with the nightly judge, run in the nightly rotation shape (refusal stratum
  of `full` + block 0, ≤ 600 cases; SPEC §6.2, D223), outside the PR-tier headline; M14, M15 and M20 on `core`
  (PR tier) and additionally in the nightly table;
- the repeat counts;
- the rule that results are reported whatever they show, including if the naive gate detects more.

**Variants:** all are computed from identical baseline/candidate runs, so only the decision rule
differs. Variants 2 and 3 live in `experiments/rq3/baselines.py`, not in `pruefstand.gate`.
1. **Prüfstand**: production `evaluate_gate` (one Holm family over gated metric × gated slice pairs).
2. **Naive mean gate**: FAIL if the overall mean drop > δ for any gated metric. Hard fails and absolute
   checks still apply, so leaks are not the differentiator.
3. **No-slices gate**: Prüfstand statistics on the overall slice only.

**Outcomes:**
- Detection = a mutation yields **FAIL** (P3.3, for every mutation incl. M17). WARN is reported separately and is
  never counted as detection.
- Detection rate denominator = should-detect `statistical` mutations (Δ̂_true ≥ δ, reference arm above); a
  mutation with Δ̂_true < δ that passes is "consistent with the rule", not a miss.
- False block = a no-op yields FAIL. False warn = a no-op yields WARN.
- Each no-op runs 3× with production cache settings (N03 as-is). Rates come with Wilson 95 % CIs
  (0/30 still has an upper bound ≈ 0.11, so the real runs are the validation arm).
- **A/A replay arm (primary false-alarm estimate):** ≥ 500 synthetic no-op pairs per variant, built by
  resampling the cached responses/judgments of the main baseline, run **twice**: once with **σ_d(no-op)** (no-op
  changes with regeneration, round 9 X3.5) and once with **σ_d(churn)** (N04 prompt synonym, N09 re-quantisation,
  temperature 0.3 seeds, AI9-09), both measured in T6.3 (`results/noise/mde.csv` columns `sigma_d_noop`,
  `sigma_d_churn`; the identical-repeat σ_d is only a floor and is not used; `experiments/noise/replay.py` logic,
  CPU only). Both rates are reported; the σ_d(no-op) arm is pre-registered as the primary false-block /
  false-warn outcome, and the 30 real no-op runs must lie inside its 95 % interval or the deviation is reported.
- `cache_invalidating` no-ops (incl. the realistic-churn N09/N10, AI9-22) are also reported as their own class.

**Dose-response:** real rag-demo runs with a graded real config knob, `top_k` ∈ {8, 6, 4, 3, 2}
(8 = baseline) plus `reranker: off` at each step, 2 repeats each, compare the variants at a **matched**
false-block rate (≈ 5 %). These are statistical scenarios, so they run in **tier 2** (round 8 W1.3/W1.5, D96/D98:
tier-1 paired statistics are `INSUFFICIENT_DATA` at n = 20): bench runs through the same executor path as the
mutations (`bench/DOSE-<topk>-<reranker>-<rep>` branches, `tier=bench`, `core` + `robust_pr` splits, the knob set
in `apps/rag-demo/configs/rag.gpu.yaml` (X3.15), A40 generator `qwen`, PR judge). Per-case scores are aggregated to `results/_inputs/rq3/dose_runs.parquet`
(committed). No job in the public `live-e2e.yml`.

**Run rules (unattended path):**
- Each entry is pushed as branch `bench/<ID>-<rep>` to the public repo. `build-images.yml` is extended
  with `push: branches: ["bench/**"]`, so every bench SHA gets a signed image by digest.
- The private `gate-executor.yml` gains `workflow_dispatch` inputs `sha`, `tier=bench` and `bench_splits`
  (`pr` = `smoke,core,robust_pr` with the PR judge, `robust_pr` through `/v1/retrieve`; `nightly` = the nightly
  rotation shape (refusal stratum + block 0) with the nightly judge, for M06 and the nightly table; the orchestrator
  runs `switch-mode.sh night` for it under the lock and `day` in `finally`; this is the one D281 exception, "nightly-table bench runs switch to night mode under the lock, outside 22:00–06:00", AI13-15) (private-repo users only, so trusted); `run_all.py` triggers it with
  `gh workflow run -R dheena18/pruefstand-gate` and waits for the run. **Concurrency:** a bench dispatch has no
  `pr` input; the group expression `${{ github.workflow }}-${{ inputs.pr || inputs.sha }}` already in
  T6.2b's workflow (dispatch-only, round 13 P1.2), guard test and ci-cd.md §6 gives each bench SHA its own group (R9-05);
  this task only adds the `sha` input (no guard-test change). The orchestrator still takes `/var/lib/pruefstand/gpu.lock` once per job (X2.1, D211).
- **GPU-time plan (AI11-13, pre-registered):** before the first dispatch, `PREREGISTRATION.md` records the estimated
  GPU hours from T6.3's measured timings (`results/noise/timings.csv`) and a calendar. `run_all.py` never dispatches
  inside the night window 22:00–06:00 Europe/Berlin (D223), dispatches at most 4 bench runs per weekday (gated PRs
  keep priority through the lock queue) and the rest on weekends, and resumes from its state file; repeats are never
  cut ad hoc (a cut changes the pre-registered analysis and is reported as a deviation). No public PR, label
  or approval is needed for bench runs. Bench runs never post to public PRs and never promote baselines.
- `build-images.yml` builds bench images from `github.sha` of the `bench/**` push (head = pushed commit, X2.4).
- PR-scoped index for `needs_reindex`; held-out canary set (private executor only).
- **Baseline = the unmutated `base_sha`**, run first as entry `BASE` (`bench/BASE-<rep>`, 2 reps) with the
  same tier, splits and judge. Every variant compares each entry against that run (fetched like the others)
  — never against the store's `main` baseline, which moves with `main` and would confound the no-op rates.
- An infra failure (`stop_reason="aborted"` with `infra_error`, status `error`, Y5.2/D226) or a run with
  `judge_fallback=True` (judged metrics informational, never compared across judges, Y4.4/D224) is re-run, never
  scored, and counted in `summary.csv` column `reruns`.
- Incomplete runs (`complete=False`) are re-run, never scored — except entries with `expected.precondition == "corpus_mismatch"` (M16): an aborted run with `counts.corpus_mismatch == 1` (CLI exit 1) is scored as FAIL = detected, without calling `evaluate_gate`.

**likely_cause validation:** for every mutation with an `expected.likely_cause` code in `mutation.yaml`,
record whether `GateReport.likely_cause` equals it (codes from SPEC "7.4": `retrieval`, `generation`,
`citation_format`, `language`, `refusal_policy`, `errors`, `mixed`). Only rule-internal threshold
constants in `gate/cause.py` may be tuned afterwards, in a separate follow-up PR referencing these
results; the observed `SliceDecision` patterns become fixtures in `packages/pruefstand/tests/unit/gate/test_cause.py`.
