## Goal

`make docs` builds a strict mkdocs-material site with working Mermaid diagrams, CI fails on broken
internal links, the module dependency graph is generated on `main`, and the site is published to
GitHub Pages at `https://dheena18.github.io/pruefstand/docs/` by `docs.yml`, the **single Pages
writer**, which deploys one artefact: the dashboard at the site root (T8.5's `dashboard-site`, or the
placeholder page) and the docs under `docs/` (D243). The deploy job runs only on `workflow_run` of a
successful `deploy.yml` (N5.2), so the first real Pages deploy happens once T8.5's `deploy.yml` exists;
this task builds and tests the whole path locally.

## Context

All diagrams are Mermaid inside Markdown so GitHub renders them too. `REVIEW.md`, `tasks/` and
`prompts/` sit outside `docs/`. They reach the site through `mkdocs-include-markdown-plugin` stub pages
in `docs/_external/`, never as copies. The generated graph is rendered into the built site and never
committed; `docs/architecture/generated/` holds only a README. GitHub Pages must be enabled with source
"GitHub Actions" (T0.5 S6).

**Pages layout (D243, binding).** One Pages site, one writer (`docs.yml`), one artefact `_pages/`:
`_pages/` = the dashboard static export at the root (`basePath` `/pruefstand`, built and uploaded as
artefact `dashboard-site` by T8.5's `deploy.yml`) + the mkdocs `site/` under `_pages/docs/` + `.nojekyll`
(the only `.nojekyll`; Jekyll never runs with the Actions deploy, the file documents intent; UI12-20)
+ **`build-id.txt`** at the root (R13 P5.5). `mkdocs.yml` sets `site_url: https://dheena18.github.io/pruefstand/docs/`.
The root is a one-file placeholder `index.html` that links to `docs/` (and `404.html` = the same page)
**only** when the triggering `deploy.yml` run passed the provenance check but uploaded no
`dashboard-site` (pre-data bootstrap). A failed provenance check never deploys anything, so a misfire
cannot overwrite the live dashboard with the placeholder (UI13-09).

**Build id (R13 P5.5).** Every Pages build writes `<out>/build-id.txt`: one line
`<git_sha>-<deploy_run_id>` = the commit SHA the site was built from (`github.event.workflow_run.head_sha`)
suffixed by the triggering `deploy.yml` run id (`github.event.workflow_run.id`), so a data-only refresh
of the same commit (daily cron) still gets a new id. `assemble_pages_site.sh` takes it from the env
`BUILD_ID` (required; exit 1 when unset or not matching `^[0-9a-f]{40}-[0-9]+$`). T8.5's
`post-deploy-smoke` polls `/pruefstand/build-id.txt` until it equals this value before any check.

**Handshake (N5.2, binding; replaces the R11 dispatch).** `docs.yml` is triggered by **`workflow_run`**
on workflow `deploy` (`types: [completed]`) in addition to its own `pull_request` and `push: main`
triggers. Only the `workflow_run` path deploys. `dashboard-site` is downloaded **from
`github.event.workflow_run.id`**; there is no `workflow_dispatch`, no `dashboard_run_id` input and no
run-id search through the API. A docs-only change on `main` reaches Pages through the `deploy.yml` run
that every `push: main` triggers (T8.5). Before T8.5 no `deploy.yml` exists, so the deploy job never
runs; T8.5 adds the real-dashboard cases and the `post-deploy-smoke` job.

**Size cap (N5.1).** `assemble_pages_site.sh` fails (exit 1, message names the measured size) when the
assembled `<out>/` is larger than `PAGES_MAX_BYTES` (default 800000000, measured with `du -sb`); the
variable exists only so tests can use a small limit.
