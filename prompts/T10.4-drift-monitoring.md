## Goal

`pruefstand drift` scores a sample of production (question, answer, chunks) logs with
reference-free metrics nightly and alerts when the weekly distribution drifts versus a reference window.

## Context

Production logs have no gold answers, so only reference-free metrics apply: `faithfulness`,
`language_match`, `canary_leak`, `tenant_leak`, `injection_success`, `latency_ms` (registry metrics), plus two drift-local
statistics that are not registry metrics: refusal rate (share of answers with `refused` true or detected as a refusal) and citation presence. Input format: JSONL `ProductionRecord {ts, tenant_id, question, answer, chunks[],
citations[]}` (new model in `core.models.drift`). Privacy: a mandatory `Redactor` step removes
e-mails, phone numbers, IBANs, names (simple regex + optional spaCy de NER extra) **before** anything
is stored or sent to a judge; sampling (default 1 %, max 500/day) seeded per day. Drift test: for each
metric compare current window vs reference window with a two-sample bootstrap of the mean difference
(unpaired; reuse gate stats helpers where applicable, pure function in `gate/drift.py`) and Holm across
metrics; leaks are absolute alerts. Output: `drift.json` + Markdown summary; optional webhook.
**Judge (round 8, binding):** there is no CPU judge in any tier (D97). Production logs are private data, so
the `faithfulness` judge must be a **local** endpoint (the A40 PR judge, family `mistral`/`gemma`, W3.1);
`LLMPolicy`'s data guard refuses hosted providers for it. Without a configured local judge `faithfulness` is
`not_applicable` with reason `judge_skipped` and the report says `judge_mode=skipped`. Judge failures follow
W3.9 (`status=error`, > 5 % → `judge_degraded`, faithfulness drift then informational); a judge flagged
`judge_drift` makes the faithfulness comparison informational; if the reference and current windows were judged by
different judges (any fallback), the faithfulness comparison is informational with reason `judge_fallback` and is
never computed across judges (round 11 Y4.4, D224). A40 judge calls use the native Ollama API with the catalogue
`options` (`ollama/<tag>` ids; D219–D221, through T5.1's `LLMClient`).
Round 9 (binding): the faithfulness judge sees exactly the logged chunks with `used_in_prompt=true` (fallback: the
first `top_k`; X3.14); the judge input cap is the judge's context window − 1 024 tokens, truncation is logged per
record and counted in `counts["judge_truncated"]` (X3.9); `judge_drift` is the nightly 50-anchor rule (X3.4) and
never changes any fingerprint (X3.3). Judge quota/cap accounting uses the runner's keys (`judge_error`,
`judge_skipped`, reasons `judge_quota` / `judge_cap`, D9-07); a config without a local judge sets `judge_mode=skipped`.
