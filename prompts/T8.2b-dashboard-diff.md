## Goal

Four more static page types under `/[locale]/runs/[id]/` — `diff/`, `slices/`, `cases/` (list over the
sharded case files with a detail panel) and `cases/[caseId]/` (only for failing cases) — with every
state of ui-spec §4.3–§4.5 and §6.

## Context

- **Diff (ui-spec §4.3, §8):** one dot-and-whisker row per block-G decision (Gated table of ui-spec
  §11.1, via T8.2a's `tables.ts`; Informational and Notable rows are not on this page); shared x scale; dashed `−max_drop` line per row
  (none when `max_drop` is null, row text "no threshold"); `result == null` → "n/a";
  `INSUFFICIENT_DATA` greyed with `n_clusters`; sort + slice filter in the URL; tier-1 run
  (`stack == "live"`) → `Tier1Notice` + block R, no chart (`S-TIER1`). Pages are generated only for
  runs with `gate.json` **and** `no_baseline == false`; a no-baseline run has no Diff or Slices page
  (its path is the 404 page; T8.2a's `RunSubNav` shows "(nothing compared)", UI11-20).
- **Static params (UI12-08, ui-spec §2.1):** each page exports its own `generateStaticParams`
  (bottom-up; no `generateStaticParams` in any `runs/[id]/layout.tsx`): diff and slices → runs with
  `gate.json` and `no_baseline == false`; cases list → runs with published shards (`cases/<id>/0.json`
  exists, the newest 20, N5.1); case pages → `{id, caseId}` of the failing shard-0 cases of those runs.
  When a page's own set is empty (e.g. every run is no-baseline or ungated, which is normal for early
  production data) it returns `[{id: "_empty"}]` and renders `EmptyState` `empty.runs` with `noindex`;
  `dynamicParams = false` everywhere.
- **Runtime URLs (UI12-05):** every runtime fetch (shards 1+, baseline shards) and every link is built
  from `basePath` (`process.env.NEXT_BASE_PATH` inlined at build, one helper in `src/lib/data.ts`); no
  string literal starting with `/data/` or `/_next/` exists in `src/`. T8.3's required `basepath-smoke`
  job checks this at `/pruefstand/`.
- **Slices (ui-spec §4.4):** rows from `slices.json` (`DashboardSlices.rows: DashboardSliceRow[]`,
  X5.3); groups by the ui-spec §11.1 table rule (`gated && informational_reason == null` → Gated, every
  other row → Informational; each row once; `kind` only tells decisions from absolute checks, so a
  tier-1 `injection_success` row with `kind == "absolute"` and `tier1_injection_reported` is
  Informational); gated and informational in separate `<section>`s, informational labelled "informational, does
  not block"; `notable` marker; `informational_reason` label; ≤ 12 bars then `slices.show_all`; Δ text
  only if the row has `mean_diff` (R2), else bars + values. **Tier 1 (Y7.4, UI11-01, ui-spec §4.4):**
  `Tier1Notice`, then three sections in this order: the Gated group titled `tier1.checks` ("Checks
  (decide)") with block C (`error_rate`, which decides and shows its status word); `tier1.reported`
  with the block R rows (`tier1_deterministic_only`, `tier1_injection_reported`,
  `applicable_clusters<30`) and their reason labels, no status word; then the Informational group with
  blocks J, I and N. The grouping rule is unchanged; the layout only splits the Informational group by
  block via `assignBlock`.
- **Cases (ui-spec §4.5, W5.3, UI-04, UI-05):** shard 0 is read at build time for the failing count and
  the static case pages and fetched at runtime for the list; then shards `1…n_shards−1` in parallel;
  "Failing only" default renders from shard 0 (R4 order); client-side filter (failing, tenant,
  category, lang, perturbation), search (id + question), sort (`failing` first, then `case_id`) and
  pagination (25), all in the URL query incl. `?case=`; detail panel ≥ 1024 px, full-width < 1024 px
  with focus moved to the detail `<h2>`; partial-load (`C-LOADING`) and shard-error (`C-SHARD-ERROR`,
  a failed fetch, a fetch slower than `SHARD_TIMEOUT_MS = 15000`, or failed validation of shard 1+)
  states (ui-spec §4.5.1, UI11-18). Totals per ui-spec §4.5.1 item 5: sum of
  loaded shard lengths with "(partial)" until complete; never `RunIndexEntry.n_cases` (UI9-22).
- **Static case pages (ui-spec §4.5.3):** `generateStaticParams` = shard-0 cases with
  `failing == true` only (top failing cases and hard fails); same `CaseDetail`. A run without failing
  cases returns the placeholder `[{caseId: "_empty"}]` with `dynamicParams = false`, which renders
  `EmptyState` `empty.cases` with `noindex` (Y7.2). The `runs/_empty` placeholder of the empty set also
  covers `diff/`, `slices/` and `cases/` (`empty.runs`).
- **Query-driven pages (ui-spec §6, UI11-09):** cases list, diff (`?sort`, `?slice`) and slices
  pre-render the default view from build-time data as the `<Suspense>` fallback around the
  `useSearchParams` reader; the client applies the query after hydration and sets `data-hydrated` on
  `<main>`. The cases list's static default is the "Failing only" view from shard 0; never a skeleton.
- **Case detail (ui-spec §4.5.4):** question + answers (`pre-wrap`, `lang={case.lang}`, UI9-12),
  refused badge, expected refusal, error class, `citations` (`CitationList`, `lang="de"`), metrics with
  `metric_status` (`ok` / `not_applicable` / `error`), this case's hard-fail findings, chunk cards for
  `retrieved_chunk_ids` ("Chunk text is not published"); tenant badge and "⚠ LEAK" from
  `retrieved_chunk_tenant_ids` (R3), or, for data without it, from the case's `tenant_leak` finding.
  Baseline side from the baseline run's shards; `baseline_run_id` null or not exported → "Baseline not
  exported".
- Charts are client-only: each chart has a `'use client'` wrapper `src/components/charts/<Name>.client.tsx`
  that calls `next/dynamic(…, {ssr: false})`; pages import only the wrapper (Next 15 rejects
  `ssr: false` in Server Components; ui-spec §8, UI11-22). Their table alternative is server-rendered.
  Bars and lines are positioned with SVG attributes, never a `style` attribute in server-rendered
  markup (ui-spec §7.4).
- All text renders as text; never `dangerouslySetInnerHTML`. No metric computation in TS.
