## Goal

Every page × state of ui-spec §14.2 is tested in **light + dark × de + en × 360 px + 1280 px** with
state assertions, axe (0 serious/critical) and CSP checks on every UI PR, against **one static build per
fixture set** (`populated`, `empty`). Visual regression for the same matrix, WebKit/mobile projects and
Lighthouse run nightly (informational until M7). All deterministic, on real sanitised run data.

## Context

- **Builds and servers (X1.2):** `scripts/dashboard/build_set.sh populated` and `… empty` build
  `apps/dashboard/.sets/{populated,empty}/`. `playwright.config.ts` has two `webServer` entries
  (`serve` pinned devDependency: `serve .sets/populated -l 4173` and `serve .sets/empty -l 4174`, each
  using the header-free `serve.json` that T8.1's `build_set.sh` wrote, so local serving matches GitHub
  Pages, which sends no header of ours; Y7.1). No network during tests.
- **Projects (ui-spec §14.2):** PR: `populated-360`, `populated-1280`, `empty-360`, `empty-1280`
  (Chromium; `baseURL` per set) and `populated-basepath-1280` (below). Nightly: `{populated,empty}-webkit-1280`,
  `{populated,empty}-mobile-chromium` (Pixel 7), `{populated,empty}-mobile-webkit` (iPhone 14).
- **`basePath` smoke (N5.5, UI12-05, UI12-06; ui-spec §14.2, binding):** the PR matrix above uses an
  empty `basePath`, so a hard-coded `/data/…` would pass it and break production. Job `basepath-smoke`
  (every PR, in the aggregate `check`'s `needs:`, i.e. part of the required `ui / check`) runs
  `NEXT_BASE_PATH=/pruefstand scripts/dashboard/build_set.sh populated --out populated-bp`, then the new
  helper `scripts/dashboard/serve_under_base.sh <site> <base> <tmp>` (makes `<tmp>/<base>/` = the site,
  copies `<site>/404.html` to `<tmp>/404.html` because Pages serves the site-root 404 for the whole
  project path, writes the header-free `<tmp>/serve.json`), serves `<tmp>` on 4177 and runs
  `e2e/basepath.spec.ts` in project `populated-basepath-1280` (Chromium, light, `de`). Checks: `/pruefstand/`
  → `de/`; runs list; `F-FAIL` summary + report link (opens `report.html`, 200, own CSP meta); `D-MANY`
  1,500-case cases list with shard 1 loaded; one static case page; unknown path → 404 page with status
  404 and the `notfound.docs` link `/pruefstand/docs/`; `theme-init.js` loaded; **every same-origin
  request starts with `/pruefstand/`**; no CSP violation, exactly one CSP meta. T8.5's local smoke reuses
  `serve_under_base.sh` (port 4176).
- **Fixtures (ui-spec §14.1):** this task completes `fixtures/populated/`: refresh it with the tier-2
  rows `F-PASS`, `F-WARN`, `F-FAIL` (sanitised runs from the public repo
  `dheena18/pruefstand-dashboard-data`, W2.9; extend `refresh_snapshot.sh` with
  `--dashboard-data <ref>`; they are already exported, so they go straight into `fixtures/populated/`
  and are recorded in `SOURCE.md`), and derive `D-T2-HARD-FAIL` and `D-JUDGE-FLAGS` with
  `derive_fixtures.mjs`; regenerate `fixtures/empty/`; remove the allow-list in
  `check_fixture_states.mjs`. Never hand-written JSON; everything stays under `apps/dashboard/fixtures/**`
  (Y7.3). Both sets must pass `validate_data.mjs`.
- **Matrix (ui-spec §14.2):** `e2e/matrix.ts` exports `{page, state, set, fixtureRunId, path, expect}`
  for every row; each project runs the rows of its set × `{light, dark} × {de, en}`. Per combination:
  state assertions (banner text by i18n key, status word, landmarks, expected sections present/absent),
  axe (fail on serious/critical), no page-level horizontal scroll, `<html lang>` = locale and the ui-spec
  §9 `lang` rules on data, footer attribution present, **no `securitypolicyviolation` event or CSP
  console error, exactly one CSP `<meta>` and no `Content-Security-Policy` response header** (ui-spec
  §7.4, Y7.1). Query-driven rows (runs list, cases list, diff, slices) first wait for
  `main[data-hydrated]` (ui-spec §6, UI11-09). The
  theme is set through the real `ThemeToggle` storage key before load (`addInitScript`); the locale
  through the route.
- **Network rules (X1.2):** no mocks. `page.route` is allowed **only to delay** a real fixture response
  (handler awaits a test-controlled promise, then `route.continue()`); never `fulfill`, `abort` or a
  changed body. `C-LOADING` = shards 1+ of the `D-MANY` 1,500-case run delayed until the assertions ran.
  `C-SHARD-ERROR` (ui-spec §14.2, UI11-18): first write `e2e/offline-probe.spec.ts`, a one-off probe
  that checks whether a request intercepted before `context.setOffline(true)` fails when it is
  continued offline. Record the result in `docs/decisions.md` and use exactly one mechanism:
  **primary** (probe: it fails) = delay shards 1+, `setOffline(true)`, release, assert the shard error,
  `setOffline(false)`, Retry, assert the shard loaded; **fallback** (probe: it passes through) = hold
  shard 1 longer than T8.2b's `SHARD_TIMEOUT_MS` (15 s) so the loader aborts it, assert the shard error,
  release, Retry, assert loaded (delay only, no offline emulation). Delete the probe spec after
  recording the result. A helper `e2e/delay.ts` is the only place that calls `page.route` (T8.4's
  Try-it spec reuses it), and a lint rule (`no-restricted-syntax`) forbids `route.fulfill` and
  `route.abort` in `e2e/`.
- **Error state (X1.2):** the 404 page (`X-404`) is the site's error state and is in the matrix for both
  sets, incl. the Diff and Slices paths of `F-NO-BASELINE` (not generated, UI11-20). `X-ERROR` stays in
  Vitest. Invalid data is a build failure (`B-INVALID-DATA`, T8.1's `validate-data.test.ts`), not a page.
- **Placeholder (Y7.2, UI12-18):** `E-PLACEHOLDER` rows: empty set `/de/runs/_empty/`,
  `/de/runs/_empty/diff/`, `/de/runs/_empty/slices/`, `/de/runs/_empty/cases/` (`empty.runs`); populated
  set `/de/runs/<F-PASS id>/cases/_empty/` (`empty.cases`). Each: `noindex`, no page links to it, and the
  usual axe/CSP/footer checks.
- **Size cap (N5.1):** `S-CASES-PRUNED` summary row (an old `D-MANY` clone: Cases "(cases not
  published)", no report link) and its `cases/` path in the `X-404` row.
- **Determinism:** timezone `Europe/Berlin`, reduced motion, fonts bundled, animations off in test mode,
  masks for export time and latency. Visual baselines only in the pinned Playwright Docker image
  (`make ui-update-snapshots`); never on a laptop. Visual screenshots run in the nightly job only
  (UI9-18).
- `report.html` rows run on `<set>/data/runs/<id>/report.html` (light/dark × 360/1280, English only =
  4 combinations per row), incl. its own CSP `<meta>` written by `render_html` (hash = its own script).
- Try-it rows are T8.4 (nightly on the VM, real demo stack, `workers: 1`, delays only through
  `e2e/delay.ts`; ui-spec §14.2 Try-it run); this task provides the `matrix.ts` hooks and `delay.ts`
  they reuse. `T-DISABLED` (no demo URL) runs here on the populated build.
- Lighthouse on runs list, FAIL summary and the cases list of the `D-MANY` 1,500-case run (3 shards;
  UI-28). If LCP > 2.5 s on the cases list, open a follow-up for smaller shards.
