## Goal

The real v1 dataset `datasets/pruefstand-de/1.0.0/` is built with the pinned models; a judge model of
a different family (local A40) has reviewed **100 % of `smoke` and `core`** and a 20 % sample of `full` (round-8 W3.13) with every stratum ≤ 10 % bad (prompt
`_v2` loop otherwise); the owner's 50-item spot-check confirms the model review is trustworthy;
smoke is selected by rule, contamination-prone cases are tagged `closed_book:<generator model id>`, and v1 is published to
Hugging Face (one config per license) and loads with `datasets.load_dataset`.

## Context

- Build: `pruefstand build-dataset --config dataset.yaml` (T4.7a) with the real backends (T5.1; ADR-0019, D330): the pinned GitHub Models datagen model for public text (T4.2,
  resumable cached batches), a second GitHub Models model for the 10 % cross-check, the local judge model for private
  docs (T2.6) and the review below; free providers only.
- No German reader is available, so the review (100 % `core`/`smoke`, 20 % `full`) is done by a model (decision in `docs/decisions.md`);
  the owner only spot-checks citations and plausibility.
- **Closed-book tagging:** `scripts/closed_book.py --model <generator id from models.yaml>
  --split core` asks the generator each core question **without retrieval** (direct endpoint call,
  temperature 0). A case gets tag **`closed_book:<generator model id>`** (round 9 AI9-21: the tag names the model, so it is recomputed, not reused, when the generator changes, e.g. M11) if a citation extracted from the answer
  (`core.citations.extract_citations`) matches a gold citation by `citations_match` (not a substring test:
  gold citations use the default granularity, `§ 622 Abs. 2 BGB`, while answers often add `Nr. 1`) **and** the answer contains ≥ 80 % of the reference answer's content words (AND, not OR: knowing the norm is not answering correctly; deterministic heuristic, no
  judge; documented as such; may be re-tagged with a judge after T5.2b as a follow-up). `--retag` removes every `closed_book:*` tag of another model id before tagging. Tags are an
  informational slice; they never gate.
- First release: the canary registry from T2.6 is used as is; `retired.json` stays empty
  (rotation via `rotate_canaries` starts with v2). Held-out canaries are never exported (test from T4.1).
- HF push is manual from your machine with `HF_TOKEN` (scope: `docs/ops/secrets.md`; private first, public after you check the
  card). The automated `dataset-release.yml` workflow is owned by T9.1b, not this task.

### Model review (AI, A40)

1. `make review-model BUILD=<build>` (round 9 X3.8, AI9-11; reviewer per split as in T4.7a): all `core`/`smoke` items and the seeded 20 % `full` sample are reviewed by the `judge` entry of
   `infra/gpu/models.yaml` (`gemma3:12b`, family `gemma`; ADR-0019) as a **batch job** in day mode under the GPU lock, in **reject-only** mode: it grades every split, so it never writes or rewrites a reference; its fixes may change only the question (a wrong reference → `reject` + regeneration with the GitHub Models datagen model). It uses
   `review_item_de_v1.txt` against criteria (a)–(e) of T4.7a; deterministic checks (citation key,
   numbers kept in fixes) override them.
2. `make review-summary` prints the model error rate per (category × prompt version) stratum.

### Owner spot-check protocol (you, ~1 h, no German fluency needed)

1. `make review-app` → http://localhost:8501 shows 50 items: all smoke citations plus a stratified
   draw of model-`ok` and model-`fix` items.
2. Left: question, answer, gold citation. Right: the source § with the cited Absatz highlighted.
3. Answer two yes/no questions per item: **citation_ok** ("Does the citation point to this §/Absatz,
   same law, same number?") and **plausible** ("Do the numbers, dates and durations in the answer
   appear in the highlighted text?"). Add a note if something looks odd. You do not judge German
   style; the model review covers that.
4. Put your pseudonym in the sidebar. About 1 min per item.

### > 10 % bad loops

- **Generation loop:** if any stratum's **model-review** error rate is above 10 %: the session reads
  the bad items, writes a short failure analysis in `docs/decisions.md`, creates
  `<prompt>_v<N+1>.txt` (never edits v1), regenerates only that stratum
  (`build-dataset --stage generate --only <prompt>`), re-filters, and the model reviews a **new** 20 %
  sample of the regenerated items. Repeat until ≤ 10 %. Every iteration is a `ReviewRound`.
- **Trust loop:** if you flag more than 10 % of the spot-checked model-`ok` items, the model review
  is not trusted: the session writes `review_item_de_v<N+1>.txt`, re-runs the model review on the same
  sample, recomputes error rates, and you spot-check a fresh draw of 50.
