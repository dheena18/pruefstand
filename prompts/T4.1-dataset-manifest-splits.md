## Goal

A dataset directory `datasets/<name>/<version>/` can be validated, split and exported: splits keep
whole clusters (`cluster_id`) together, every row belongs to exactly one license config, the manifest
records counts, prompt versions and review rounds, and `export_hf` pushes one HF config per license
so `datasets.load_dataset("<HF_USER>/pruefstand-de", "laws_eurlex", split="core")` works.

## Context

- `SplitPlan` and `DatasetBuildConfig` are already listed in interfaces.md "Where types live"
  (`core.config`); this task defines their fields and writes them into §14 (pre-approved).
- Splits (`Split` enum incl. `ROBUST_PR` and, round 13 P3.2, **`RQ1`** (value `"rq1"`, added to the enum by T1.1)) and `SplitPlan` defaults:

  | Split | Size | Content | Runs |
  | --- | --- | --- | --- |
  | `smoke` | 50 | selected by rule from model-reviewed items (T4.7a `select_smoke`), every category ≥ 3 | every PR |
  | `core` | 300 = **220 answerable** (factual, multi_hop, comparison, cross_lingual; ≥ 30 `cross_lingual`; ≥ 200 distinct clusters) + **50 `unanswerable`** + **30 security probes, all `injection` cases** (so the tier-2 Wilson check has n ≥ 30); leak, system-prompt and filter-bypass probes sit in `smoke`, not `core` (round 9 X3.7, D167; SPEC v2.4 §3.4) | generated + **100 % model-reviewed** by the nightly `gemma` judge as a batch job (round 9 X3.8: the PR judge `mistral` never reviews or rewrites `core`/`smoke` references, T4.7a) | every tier-2 PR (judged; `false_refusal` gated on the 220 answerable, `refusal_correct` informational) |
  | `robust_pr` | ≈ 300–440 | 40 base questions × **the perturbations that apply to each base** (round-8 W3.14: not all 11 change every question; `numbers`/`dates`/`citation_style`/`abbreviations` need such tokens, `umlaut_translit`/`eszett` need ä/ö/ü/ß). Bases chosen by **applicability score** (number of the 11 perturbations that change the text), the 40 bases from **40 distinct `cluster_id`s**; quotas: ≥ 20 bases per perturbation type, ≥ 300 perturbed cases; the manifest and every report state the real `perturbed_all` n; only retrieval metrics are computed (no judge). Gated slice: `perturbed_all` (all perturbed cases vs their bases); per-perturbation slices are informational. **Slice membership (round 9 X3.6):** perturbed cases count **only** in `perturbed_all` (and the informational per-perturbation slices); `overall`, `tenant` and `lang` use unperturbed cases (T1.7 step 4) | every PR |
  | `full` | ≈ 1 500 = refusal stratum ≈ 150 + 3 blocks × 450 (round 13 **P3.1**, binding) | **refusal stratum**: every `unanswerable` `full` case (≈ 150, ≥ 100 clusters, runs every night). **Each block** = **300 unperturbed answerable cases** (≥ 250 distinct clusters, ≥ 30 per tenant) + **150 perturbed variants** of bases inside the same block (a fixed seeded base set, applicable perturbations only). Nothing else goes into `full`: surplus generated cases are dropped and counted in the build report | nightly (refusal stratum + one block); release run (all) |
  | `rq1` | ≈ 300 bases × their applicable perturbations (round 13 **P3.2**) | the RQ1 robustness set, cluster-disjoint from every other split (cluster rule below) | offline only (`experiments/`, T7.3); **never** in the nightly or any gate |
  | `human_labels` | 0 (not built) | reserved; judge calibration uses the T5.3 sets from existing human data, optional T5.3-opt labels live outside the dataset | never gated |

  The 40 `robust_pr` base questions are themselves in `robust_pr` (not in `core`), so splits stay disjoint.
  Cluster targets (checked by `validate_dataset`), **per metric, by applicable clusters** (round-8 W3.6: a metric is gated only with ≥ 30 applicable clusters in the split): `core` answerable categories (factual, multi_hop, comparison, cross_lingual; `context_recall`/`citation_*`/judged metrics/`false_refusal`) ≥ 200 distinct `cluster_id`s among the 220 answerable cases and ≥ 30 per tenant (tenant slices are gated); `core` injection = 30 (X3.7); `full` ≥ 100 `unanswerable` clusters in the refusal stratum (refusal metrics are gated only in nightly `full`) and, per block, ≥ 250 unperturbed answerable clusters with ≥ 30 per tenant (P3.1); `rq1` ≥ 300 bases from ≥ 300 distinct clusters; `robust_pr` bases = 40 distinct `cluster_id`s. `pruefstand power` takes these per-metric n.
- **Hard-negative-friendly data (W3.8):** gold citations are at **Absatz level** whenever the source § has Absätze (so span-level scoring, W3.11, and same-paragraph wrong-span negatives are possible), and the build report lists, per split, how many reference answers contain a number, date, period or § reference (T5.3 builds number/date swaps and negation flips from them).
- **Cluster rule:** `TestCase.cluster_id` = source document of the base question (first
  `gold_doc_ids` entry, else `base_id`); all cases sharing a `cluster_id` — including every
  perturbation (same `base_id`) and DE/EN parallel questions (same `parallel_id` → use the DE doc id)
  — go to the same split. Leak probes cluster by canary id, injection cases by attack doc id.
  `assign_splits` sets nothing else on the cases except `split`, `block` and `judged_subset` (below);
  `cluster_id` is set by the builders (T4.2, T4.5, T4.6) and checked here.
- **Nightly blocks and judged subset (round 12 N1.1, D223/D199; pre-approved interface change):**
  `TestCase` has `block: int | None = None` and `judged_subset: bool = False` (T1.1). `assign_splits`
  sets them after the split assignment, seeded from the same `rng`:
  - `full`: every `unanswerable` case (the **refusal stratum**, runs every night) gets `block=None`;
    every other `full` case gets `block` ∈ {0, 1, 2}, **whole clusters** per block, stratified by
    **tenant × category** (interfaces §14; round 13 P3.4: no `lang` stratum; largest-remainder allocation per
    stratum, ties by `cluster_id`), filled to the P3.1 quota (300 unperturbed answerable + 150 perturbed per block).
  - every case outside `full` keeps `block=None`.
  - `core`: a fixed seeded **150-case judged subset** (`judged_subset=True`), stratified by **category
    including `injection`** (round 13 P3.4, interfaces §14 wins: answerable, `unanswerable` and `injection` shares as
    in `core`, i.e. ≈ 110 / 25 / 15) and by tenant inside each category, **no `lang` stratum**, whole clusters where
    possible; every other case keeps `judged_subset=False`. In a PR run with `--judged-subset` the subset limits
    **generation and judging** of the `core` answerable cases (T1.10; deterministic security cases always run in full).
  - The manifest records them (interfaces §14, D248): `DatasetManifest.blocks: dict[str, int]` (case counts
    with keys `"refusal"`, `"0"`, `"1"`, `"2"`), `DatasetManifest.judged_subset: int` (150) and
    `DatasetManifest.assignment_seed: int` (the seed `assign_splits` used).
  - `validate_dataset` problems: a `full` non-`unanswerable` case with `block=None`; a `block` outside
    {0, 1, 2} or set outside `full`; an `unanswerable` `full` case with a block; a cluster spread over
    two blocks; `judged_subset=True` outside `core`; a `core` subset size other than 150 (warning only
    for `datasets/fixtures/*`); manifest `blocks` / `judged_subset` that differ from the rows. Capacity check
    (AI12-05c): refusal stratum + largest block > 600 cases → problem "nightly block exceeds 600 cases
    (refusal <r> + block <k> <n>)"
    (the nightly cap of SPEC §6.2; a growing `full` needs a decision, never a silent overrun). **Composition
    (P3.1):** refusal stratum outside 135–165 cases or < 100 clusters; a block with ≠ 300 unperturbed answerable cases,
    < 250 distinct clusters among them, a tenant with < 30 of them, or > 150 perturbed variants; a perturbed `full`
    case whose base is in another block; any other category in `full` → problem (warnings only for
    `datasets/fixtures/*`). **`rq1` (P3.2):** < 300 bases or a base cluster shared with another split → problem;
    an `rq1` case with a `block` or `judged_subset=True` → problem.
- Validation (`validate_dataset`) returns a list of problems: schema errors (file:line), duplicate
  ids, `base_id` pointing to a missing case, a `cluster_id` spread over splits, `license_config` not
  in the allowed set, a cluster mixing `germanquad_derived` and `oldp_derived` (such cases are
  dropped by the builder, so their presence is an error), `category=injection` without
  `injection_marker`, `leak_probe` without `forbidden_strings`, `unanswerable` without
  `expect_refusal=True`, `robust_pr` case without `perturbation` (except its 40 bases), `robust_pr` bases with fewer than 40 distinct `cluster_id`s, a perturbation type with fewer than 20 bases, fewer than 300 perturbed cases, `core` category counts other than exactly 220 answerable / 50 `unanswerable` / 30 `injection` (X3.7), `core` answerable cases with fewer than 200 distinct `cluster_id`s or a tenant with fewer than 30, `full` with fewer than 100 `unanswerable` (cluster targets and quotas are warnings only for `datasets/fixtures/*`),
  `corpus_version` mismatch with the manifest, split counts below the quotas above (warning only
  for `datasets/fixtures/*`). **Warnings are logged** (structlog, `warning` level) and are **not** in the returned list (round 9 D9-33: `validate_dataset -> list[str]` returns problems only).
- License configs: `laws_eurlex` (CC BY 4.0), `germanquad_derived` (CC BY 4.0; CC BY-SA 4.0 only if T2.1 finds a share-alike GermanRAG card), `oldp_derived`
  (ODbL-1.0), `own` (CC BY 4.0: canaries, attacks, hand-written). There is **no** "most restrictive"
  rule; ODbL never mixes with another share-alike licence. HF dataset card generated from a template with per-config
  license + attribution (from `DATA_LICENSES.md`).
- `DatasetManifest.review` is `tuple[ReviewRound, ...]` (interfaces §14); T4.7b appends rounds.
- This task **replaces** the basic `validate dataset` command from T1.10 with `dataset.validate`
  (same CLI name, `cli/validate.py`).
- `export_hf(dir, repo_id, private, *, dry_run=False)` (interfaces §14, W4.6) uses `huggingface_hub` with token from env `HF_TOKEN`; `dry_run=True` builds the exact HF layout under `dir / "hf_export"` and uploads nothing (used in tests). Never runs in CI except dry-run. Held-out canary cases
  (`datasets/private/`) are never exported (test).
