## Goal

Six versioned label sets that let T5.4 measure judge agreement **without a German annotator**, built
only from existing human annotations or from labels that are true by construction (set 6 is in-domain, round 9 X3.1):

| Set | Metric | Source | Label origin |
| --- | --- | --- | --- |
| `faithfulness_memerag` | faithfulness | MEMERAG German subset (expert annotators, majority vote) | human |
| `faithfulness_constructed` | faithfulness | GermanRAG / GermanDPR (positive vs hard-negative context) | construction |
| `correctness` | answer_correctness | GermanQuAD test (3-way human answers) | human answers + construction |
| `refusal` | refusal_judged ("is this a refusal?", W3.5) | GermanRAG answerable / unanswerable | construction |
| `consistency` | perturbation_consistency | GermanQuAD test | human answers + construction |
| `legal_hard` | faithfulness + answer_correctness | 200 A40 generator answers on the law-corpus `full` split (T4.7b), deterministic legal edits | reviewed positive + construction |

## Context

- **MEMERAG** (`amazon-science/MEMERAG`, ACL 2025) is **CC BY-NC 4.0** and its README says the data
  must not be used to train models. Rules: download only, pinned to a git commit SHA in
  `data/sources.yaml`; derived files go to the **git-ignored** `data/derived/memerag_de/`; they are
  never committed, never pushed to Hugging Face, never sent to an external API (local A40 or CPU
  judges only), and never used for training or few-shot examples. The report publishes only
  agreement numbers and the method. Use `data/memerag_ext_w_majority_voting/` (majority vote over 5
  annotators). Inspect the actual file schema first and record it in `docs/decisions.md`.
- **GermanQuAD**, **GermanDPR**: CC BY 4.0 on their HF cards (checked 2026-10-28). **GermanRAG**:
  read the license from its card via T2.1's recorded metadata; if it says CC BY-SA, put the
  refusal/constructed-faithfulness sets in a separate CC BY-SA config. The derived sets go to
  `datasets/calibration/v1/` and may be published with attribution in a license-homogeneous config.
- Constructed labels have no partial credit (only 0 or 2 on 3-point scales). T5.4 therefore reports
  binary agreement (judge 2 vs < 2) as the primary number; this limitation goes into the report (T9.3).
- No LLM is used to build any set: every transformation is deterministic Python, so labels stay
  true by construction.
- **Dev/test split (round 13 AI13-12, binding).** Every label set (incl. `legal_hard`, MEMERAG, `refusal` and the
  hard-negative subsets) gets a seeded **cluster-level** split field `calib_split` ∈ {`dev`, `test`} (≈ 30 / 70, seed
  1234, whole `cluster_id`s, stratified by label and `hard_type`; the hard-negative subset of `test` keeps ≥ 105
  items per metric, so the Wilson rule stays testable). Prompt work and judge selection (T5.4) use **`dev` only**; the
  pass rule and the RQ2 tables use **`test`**, once per prompt version; the number of prompt versions tried is
  reported next to κ.
- **Hard negatives (round 8 W3.8, binding).** Off-topic negatives alone make κ an easy upper bound. Every
  faithfulness and correctness set therefore carries a tagged **hard-negative subset**
  (`hard_negative=True`, `hard_type` ∈ `same_paragraph_span`, `number_date_swap`, `negation_flip`,
  `partial_answer`, `memerag_not_supported`). Target ≥ 150 hard negatives per metric (correctness and
  faithfulness each, MEMERAG counted for faithfulness). **Pass rule (round 9 X1.1, binding)**: T5.4 passes a
  judge iff κ ≥ 0.6 on the **full** calibration set **and** specificity (true-negative rate) ≥ 0.80 on the
  hard-negative subset **with the 95 % Wilson lower bound ≥ 0.70**. κ is never computed on a single-label
  subset (every hard negative is label < 2, so κ there is 0 or `nan` by construction). Hence each metric needs
  ≥ 150 hard negatives (Wilson LB at p̂ = 0.80, n = 150 ≈ 0.73); `stats.json` reports the subset size per
  `hard_type` and per set. The criteria are applied on `legal_hard` **and** on MEMERAG (faithfulness).
- **In-domain hard negatives (round 9 X3.1, AI9-02)**: the Wikipedia/GermanRAG sets do not test wrong §, wrong
  party or wrong period in long legal answers. Set 6 `legal_hard` (S7) covers this on the law corpus. It is the
  only set that uses an LLM (to produce the base answers and review the positives); every label-0/1 item is still
  a deterministic edit of a reviewed positive, so negative labels stay true by construction.
- The refusal judge asks only "is the answer a refusal?" (no `erwartet`, W3.5), so the `refusal` set labels
  "refusal (1) / not a refusal (0)"; expected-behaviour correctness is computed deterministically by T5.2b.

### Construction rules (exact)

**faithfulness_memerag.** One item per (question, model answer). If labels are per sentence: item
label = 2 iff every sentence is `Supported`; 0 iff at least one sentence is `Not Supported`; drop the
item if it has a `Challenging to determine` sentence and no `Not Supported` sentence. If labels are
per answer: `Supported` → 2, `Not Supported` → 0, `Challenging…` → drop. Judge inputs: `antwort` =
answer text, `kontext` = the passages the annotators saw. `cluster_id` = MEMERAG question id (several
models answer the same question). Every label-0 item is tagged `hard_negative=True`,
`hard_type="memerag_not_supported"` (real model errors, the hardest negatives available).

**faithfulness_constructed.** From GermanRAG answerable rows (and their GermanDPR hard negatives):
supported item = full-sentence gold answer + its positive context → 2; unsupported item = the same
answer + one hard-negative context that does not contain the answer string (case-insensitive,
NFC) → 0. `cluster_id` = positive-context id. Seeded sample 300 rows → 600 items.
Hard negatives (same positive context, so the topic matches; label 0 unless noted, `hard_negative=True`):
`number_date_swap` = `swap_first_number(answer)` when the answer has a number or date;
`negation_flip` = `negate(answer)`; `partial_answer` = answer + one sentence from a **different** article
appended (label 1 = partially supported; binarised < 2). Seeded down-sampling keeps the set at 50 % positives.

**correctness.** Seeded sample of 300 GermanQuAD test questions (seed 1234), stratified by article.
Reference = annotator answer 1. Items:
- positive (label 2): candidate = annotator answer 2; `trivial=True` if NFC-casefolded equal to the
  reference (kept, but excluded from the primary κ);
- negative "other question" (label 0): candidate = an answer to a **different** question about the
  same article whose token Jaccard with the reference is < 0.3 and which is not a substring of it
  (or the reverse); skip if none exists;
- negative "number swap" (label 0), only if the reference contains a number: `swap_first_number`
  changes exactly the first number: digits `n → n + 1` (keeping the digit count, `1990 → 1991`),
  German number words `eins … zwölf` → the next one (`vier → fünf`, `zwölf → dreizehn`), the day in a
  date `3. Oktober` → `4. Oktober`.
- hard negatives (`hard_negative=True`): `same_paragraph_span` (label 0) = a sentence or a span of the
  reference's length from the **same paragraph** (GermanQuAD context) that does not contain and is not
  contained in any annotator answer; `negation_flip` (label 0) = `negate(reference)`; `partial_answer`
  (label 1) = the first half of the tokens of a reference with ≥ 6 tokens, cut at a word boundary, or one
  conjunct of an "A und B" reference. `number_date_swap` is the "number swap" negative above (tagged).
Judge inputs: `frage`, `antwort` = candidate, `referenz` = reference. `cluster_id` = article id.
Balance positives and negatives to 50/50 by seeded down-sampling; hard negatives are kept before
off-topic negatives when down-sampling.

**refusal.** 150 unanswerable + 150 answerable GermanRAG rows (seed 1234). Label = 1 if the candidate is
a refusal, 0 if it is an answer (W3.5; no `erwartet`). Refusals (1): one of 6 fixed refusal paraphrases
picked by seed (`"Die Dokumente enthalten dazu keine Information."`, `"Dazu lässt sich den Unterlagen
nichts entnehmen."`, `"Darauf kann ich anhand der vorliegenden Texte nicht antworten."`, …; listed in
`construct.py`, at most 2 of them on T1.5b's phrase list so the judge is tested on non-canonical
wording). Answers (0): the row's gold answer; hard negatives (0, `hard_negative=True`,
`hard_type="hedged_answer"`): the gold answer prefixed with a fixed hedge (`"Soweit ersichtlich, "`,
`"Nach den Dokumenten "`). Inputs: `frage`, `antwort`. `cluster_id` = positive-context id.

**consistency.** From the 300 GermanQuAD questions: consistent (1) = (annotator answer 1, answer 2)
when not trivial, plus (answer 1, `frame(answer 1)`), where `frame` is one of 4 fixed sentence frames
picked by seed (`"Die Antwort lautet: {a}."`, `"Laut dem Text: {a}."`, `"{a}, so steht es im
Abschnitt."`, `"Es handelt sich um {a}."`); inconsistent (0) = (answer 1, answer to another question
about the same article; same Jaccard rule) and (answer 1, `swap_first_number(answer 1)`). Inputs:
`antwort_basis`, `antwort_variante`. `cluster_id` = article id.

**refusal, in-domain near misses (round 9 AI9-02).** Add 50 law-corpus near-miss refusal items from the
T4.1/T4.6 near-miss templates (a question about a § that is not in the corpus, or about a neighbouring law):
label 1 = one of the refusal paraphrases, label 0 = an in-domain hedged answer (`hard_type="hedged_answer"`).
These 50 are built in S7 together with `legal_hard` (they need the `full` split) and appended to `refusal.jsonl`
with `source="legal_near_miss"`.

**legal_hard (set 6, round 9 X3.1).** Seeded sample (seed 1234) of 200 answerable `full` cases (T4.7b), public
tenant only, no case whose inputs contain a registered canary. Base answers: the tier-2 A40 generator
(`apps/rag-demo/configs/rag.gpu.yaml`, T3.6), temperature 0; `kontext` = the chunks the generator used
(`used_in_prompt=True`, X3.14). **Positives (label 2)** are kept only if (a) deterministic checks pass (the gold
§ is cited and the case's `evidence_span` occurs in `kontext` after whitespace/hyphen normalisation) and (b) the
reviewer, the pinned **GitHub Models datagen model** of T4.2 (ADR-0019: family ≠ `qwen`, ≠ `gemma`, not under
calibration for any metric; X3.8: never the gating judge `gemma3:12b`, which must not pick its own positives),
says "supported and correct". Only public items are sent (public tenant, no canary; the `LLMClient` data guard
enforces it); the free-tier quota is handled by resumable cached batches. Discarded answers are
counted in `stats.json`.
**Three passes (DEV11-07, D246 as amended by ADR-0019)**: `build_legal_hard.py` takes `--pass
answer|review|build` (like T4.5's `--pass`) and resumes from its caches, in this **binding order**: (1) **day
pass** `--pass answer` (`switch-mode.sh day`, under the lock): rag-demo `rag.gpu.yaml` base answers →
`results/_inputs/rq2/legal_hard_answers.parquet`; (2) **review pass** `--pass review` (network, no GPU): the GitHub
Models reviewer judges every cached base answer and every edited negative →
`results/_inputs/rq2/legal_hard_review.parquet`; (3) **offline** `--pass build` (no GPU, no endpoint):
deterministic checks, validity filters, edits, down-sampling. Every later rebuild with both caches present is
`--pass build` only. The GPU pass runs under the shared lock
(`pruefstand-lock uv run python experiments/rq2/build_legal_hard.py --pass …`, lock file
`/var/lib/pruefstand/gpu.lock`, Y1.1/Y1.2); a pass whose endpoint is not up exits non-zero with a clear message. **Hard negatives** (`hard_negative=True`, deterministic edits of a kept positive,
`source_item_id` links them):
- `section_swap` (label 0, both metrics): the first cited `§ n` of law X → `§ n+1` of the same law, in answer
  text and citation;
- `party_swap` (label 0, both metrics): the first occurrence of a party term swapped from a fixed table
  (Arbeitgeber↔Arbeitnehmer, Vermieter↔Mieter, Käufer↔Verkäufer, Gläubiger↔Schuldner);
- `number_date_swap` (label 0, both metrics): `swap_first_number` (periods, amounts, deadlines);
- `sentence_drop` (correctness only, label 1 → binarised 0): delete the answer-bearing sentence (the one that
  overlaps `evidence_span` most); skip if the answer has one sentence;
- `unsupported_append` (faithfulness only, label 1 → binarised 0): append one sentence from a § of a
  **different** law that is not in `kontext`.
**Validity filters (round 11 AI11-11)**, applied before a negative is kept: `party_swap` only if the counterpart
term does not occur in the swapped role in the same sentence of `evidence_span`/`kontext` (norms binding both
parties are skipped); `section_swap` for faithfulness only if `§ n+1` of that law is **not** in `kontext`;
`section_swap` for correctness is labelled 1 (partial → binarised 0) and reported under its own `hard_type`
`section_swap_correctness`; the GitHub Models reviewer also checks each edited negative and flags "edit still correct",
those items are dropped (count in `stats.json`). T5.4 reports specificity per `hard_type` with Wilson CIs.
Inputs: faithfulness `antwort`, `kontext`; correctness `frage`, `antwort`, `referenz` (the case's reference).
`cluster_id` = the case's `cluster_id`. Target: 200 reviewed positives → ≥ 150 hard negatives per metric
(down-sample to 50 % positives, hard negatives kept first). Results are recorded in
`datasets/calibration/v1/legal_hard.jsonl` under the corpus' license config (ADR-0015; ODbL if OLDP-derived).
Judge arms of the reviewer's family (the GitHub Models datagen family) report **no** numbers on `legal_hard` (it
reviewed the positives).
