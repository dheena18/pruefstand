## Goal

A readable, deterministic Markdown PR comment rendered from a `GateReport`, a `gate.json` writer,
and a `GitHubPublisher` that edits its own comment instead of posting new ones and sets a commit status.

## Context

Output must match SPEC §7.6 in structure: hidden marker line; title line with status emoji — the
complete ui-spec §12.3 list: `✅ PASS`, `⚠️ WARN` (also UNSUPPORTED_CONFIG), `❌ FAIL`,
`◌ INSUFFICIENT DATA`, `⚪ NO BASELINE` (UI11-12) — and the number of blocking issues (hard fails +
gated FAIL decisions + gated absolute FAILs); baseline/candidate line (`Baseline: main@<sha7> · Candidate: pr-<n>@<sha7> ·
<n_cases> cases · <m>m <s>s · <usd> USD · <tokens> tokens · ~<gpu_s> GPU-s`); metric table for the
**gated `overall`** decisions with the 7 columns `Metric | Base | PR | Δ (95% CI) | δ | MDE | Status`;
gated slice decisions that are not PASS (incl. `perturbed_all`); one line "Notable slice drops
(informational): …" listing the `GateReport.notable_slices` entries **with `notable=True` only**
(they always have status PASS and never block; omit the line if there are none); absolute checks
(tier 2, block A: the `Absolute checks:` line lists the non-PASS rows; when every row is PASS it reads
`Absolute checks: all PASS (<n>)` — the ui-spec §11.1 surface rule, UI11-12); "Likely cause: `<code>` — `<CAUSE_MESSAGES[code]>`" (import
`CAUSE_MESSAGES` from `core.models.gate`; report may not import gate); "Insufficient data: …";
top failing cases; and the hard-fail section first when present. Display names come from `report/labels.py`
(a name → label table, e.g. `context_recall` → "Context recall"; unknown names shown as-is).
**Redaction (ADR-0005, D64):** the comment never contains chunk text or full canary tokens; only
case ids, metric names, numbers and the redacted hard-fail evidence. Numbers: 2 decimals, Unicode minus `−`,
explicit `+`. **Commit status (R13 P4.2):** the low-level `post_status(sha, state, description,
context="pruefstand/gate")` is the **only** method that calls the **commit status API**
(`POST /repos/{repo}/statuses/{sha}` with `{state, description, context}`); `state` ∈ `pending | success |
failure | error` (anything else → `ValueError`, nothing sent); it truncates `description` to 140
characters and adds nothing else. `set_check` is a thin **wrapper for gate results**: it maps
`(status, no_baseline, infra_error)` to `(state, description)` by the table below and calls
`post_status(sha, state, description)` once, with the default context. The executor (T6.2a) uses
`post_status` directly for `"pending"` and "executor unhealthy"; "not gated" is posted only by
`gate-router.yml`, never through this class. In the real gate the private executor calls both with the
`pruefstand-bot` App installation token (D64), in the Action self-test with `GITHUB_TOKEN`. The status → commit-state mapping is
exactly the interfaces §10 `set_check` table (R9 X4.6): WARN → `success` with description `"WARN: <summary>"` (WARN
never blocks unless `--fail-on-warn`); any non-FAIL status with `no_baseline=True` → `failure` "no baseline for
<fp>; run baseline-promote". **Infra errors (R11 D226, N6.1, DEV12-02):** `set_check(..., infra_error=True)`
overrides every other row: commit state `error` (never `failure`, never `success`), description
`"executor infra error: <summary>"`, whatever `status` and `no_baseline` are (R12 D264, D274). `set_check` adds
nothing else and keeps `summary` verbatim (only the 140-character truncation applies). The caller (T6.2a's executor)
builds the summary: `"<kind>: <detail>; retrying once"` after the first infra failure and
`"<kind>: <detail>; re-dispatch to retry"` after the second (R13 P1.2: there is no `run-gate`
label; a retry is a new `workflow_dispatch` of `gate-executor.yml` by the owner). Commit statuses are
public, so the caller keeps host names out of it. This task implements the parameter, its mapping row
and `post_status`; T6.2a calls them.

**Layout is fixed by `docs/design/ui-spec.md` §12** (it wins over this paragraph on layout and copy):
- **One table rule (ui-spec §11.1 = interfaces §9, X5.4):** `report/tables.py`
  `assign_table(decision, source)` (source = `decisions` | `absolute_checks` | `notable_slices`) returns
  exactly one of `GATED` (`gated and informational_reason is None`), `INFORMATIONAL`
  (`informational_reason is not None`) or `NOTABLE` (in `notable_slices`, not matched above); a decision
  matching none is returned as `INFORMATIONAL` with reason `–`, never dropped. `assign_block(decision,
  source, stack)` then lays rows out in the ui-spec §11.1 blocks (G, A/C, R, J, I, N) without moving a
  row to another table. Every section of the comment reads its rows through these two functions. The
  same code is used by T6.4 (it imports `report/tables.py`) and mirrored in TS by T8.2a. Reason codes
  are those of interfaces §9 (`applicable_clusters<30`, `refusal_outside_nightly_full`,
  `judge_uncalibrated`, `judge_degraded`, `judge_drift`, `tier1_judged`, `tier1_deterministic_only`,
  `tier1_injection_reported`, `judge_truncated`), with labels from ui-spec §10.4.3.
- **Two variants**, chosen by `cand.stack`: `a40` → tier-2 layout (§12.1, the table above); `live` →
  tier-1 layout (§12.2, X5.6, X3.11): title `## Prüfstand tier 1: …`, the notice line "Tier 1 decides on
  hard fails and the error rate only. Language, citation, refusal and injection results are reported. …",
  a **Check | Value | Max | Status** table (hard fails as one row with the count, then block C = gated
  `absolute_checks`, i.e. `error_rate`) that decides; a `<details>` table "Reported, does not decide at
  n = <n_cases>" = block R (Informational rows with reason `tier1_deterministic_only` — every paired
  metric —, `tier1_injection_reported` — `injection_success` — or `applicable_clusters<30`; columns
  Metric | Base | PR | Δ | MDE | Max | Reported because, Δ = `result.mean_diff` or `–`, no CI, no status
  word); the "Informational (does not block): …" line for block I (any other reason, e.g.
  `refusal_outside_nightly_full`, `judge_truncated`); and one line "Judged metrics (informational, does
  not block; <source>, <cand.judged_cases> cases)" for block J (`tier1_judged`), where `<source>` is
  the en label `judge_source.<cand.judge_mode>` ("GitHub Models" / "local judge (A40)"; ui-spec
  §10.4.2, UI11-14). Never compute a number in `report`.
- **No baseline run (Y7.4, UI11-08, ui-spec §11.1):** `base` is `RunManifest | None`. `None` iff
  `no_baseline`, or the baseline run is not available to the caller (store-only baseline on the
  executor, `pruefstand report --run` without the baseline dir). Then the refs line shows
  `Baseline: –` (or `report.baseline_run_id` in mono when it is set); Base and Δ come only from
  `SliceDecision` (`baseline_mean`, `result.mean_diff`), so the tables still render. Interfaces §10
  carries the `| None` signature (round-11 change); if the merged interfaces still says
  `base: RunManifest`, update it in this PR and flag it under **Interface changes**.
- Refs line (ui-spec §2.2, §10.2, UI9-14): ref label `pr-<n>` / `git_ref` / `–` + `@<sha7>` when
  `git_sha` is set; tokens = `cost.prompt_tokens + cost.completion_tokens`; `~<gpu_s> GPU-s` only when
  `stack == "a40"`. **Block and judged subset (UI13-19, ui-spec §12.3):** when `cand.block` is set (a
  nightly), the splits part of the refs line reads `<splits> block <k>` (e.g. `full block 1`); when
  `cand.judged_subset` is true, the judged caption / block-J lead-in says "judged subset (150 cases)"
  (tier 2: on the "Informational (does not block)" line before the judged rows; tier 1: inside the
  judged line). Both are copied from `run.json`, never computed.
- δ = `SliceDecision.max_drop`, absolute max = `SliceDecision.max_value` (interfaces §9, filled by
  `evaluate_gate` from `GatePolicy.metrics`); `None` → `–`. MDE on every gated row (W3.6).
- Judge notice quote lines (never silent), in order, each only when true: `cand.judge_mode == "skipped"`
  (values `github | local | skipped`), `cand.judge_fallback`, `cand.judge_degraded`, `cand.judge_drift`
  — texts from ui-spec §10.4 (en) / §12.2. The drift text is the D253 count rule (UI13-10):
  `Judge drift detected (5 or more of 50 anchor verdicts changed); judged metrics are informational until the flag clears.`
  (never the old "agreement … below 0.85 … until recalibration" wording). Tier 2: every decision with `informational_reason` is listed
  on the "Informational (does not block): …" line with its reason label.
- `GateReport.no_baseline == true` (then `baseline_run_id is None`, X5.5) → title
  `## Prüfstand: ⚪ NO BASELINE (nothing compared)` (tier 1: `## Prüfstand tier 1: ⚪ NO BASELINE (nothing compared)`),
  refs line with `Baseline: –`, the no-baseline quote line of ui-spec §12.3, hard fails if present, no
  metric tables, never ✅ (D103). The renderer never dereferences `report.baseline_run_id` when it is
  `None`.
- `Not applicable:` line from `GateReport.not_applicable_counts` (`metric (n cases)`), omitted when empty.
- Statuses uppercase in tables; hard-fail table format; `<details>` for sections with > 5 rows; footer
  `<sub>` with the "Full report" link only when `report_url` is set, otherwise "(full report in the
  private executor run)" (UI-19).
- `report/labels.py` also exposes `labels_document() -> LabelsDocument` (X5.3, UI9-09):
  `LabelsDocument(schema_version="1", metrics={code: label}, causes=CAUSE_MESSAGES,
  hard_fail_rules={code: label}, informational_reasons={code: label})`. The en labels are exactly the en column
  of ui-spec §10.4.3. This task creates `core/models/dashboard.py` with `LabelsDocument` only (interfaces
  §10.1; T8.1 adds the other dashboard models to the same file) and registers it for `make schemas`
  (`schemas/labels.schema.json`). T8.1's `export-dashboard` writes the document to `data/labels.json`,
  so the dashboard never re-types labels (UI-26). **`hard_fail_rules: dict[str, str]`** (R12 UI12-15, D273;
  interfaces §10.1): rule code → en label (`canary_leak` → "Canary leak", `tenant_leak` → "Tenant leak",
  `system_prompt_leak` → "System prompt leak", = ui-spec §10.4.3 `rule.*` en column). The dashboard's `/en`
  pages read these; `de` comes from `de.json` `rule.<code>`. The PR comment uses the same table.
