## Goal

`apps/dashboard` builds as a static site (`next build` with `output: "export"`) from **one validated
data tree per build** (`DASHBOARD_DATA_DIR`), loads it through a typed data layer whose TypeScript types
are generated from `schemas/`, ships a strict CSP, and has lint, typecheck and unit tests in CI.

## Context

Data source: a `data/` tree produced by `pruefstand export-dashboard --runs runs/ --out <dir>`. Its
layout is interfaces.md §10.1 / ui-spec §2.3: `runs/index.json` (`DashboardRunIndex` of
`RunIndexEntry`), per run `runs/<id>/{run,gate,slices}.json` (gate/slices only when the run has a gate
report), `runs/<id>/report.html` (T6.4 `render_html` on `sanitise_run` output, written **exactly** when
`gate.json` exists, W5.3, UI-06), `cases/<id>/<shard>.json` (`DashboardCases`, ≤ 500 `DashboardCase`
per shard, cases sorted `failing` desc then `case_id` asc so shard 0 holds every failing case — R4),
`labels.json` (`LabelsDocument` from `labels_document()`) and `manifest.json` (SHA-256 per file).
- **Size cap (N5.1, ui-spec §2.3):** the index and run dirs hold the **newest 200** runs
  (`created_at` desc, then `run_id` asc); `cases/<id>/` and `report.html` are written only for the
  **newest 20** of them (the case-published runs). Constants `MAX_INDEX_RUNS = 200` and
  `MAX_CASE_RUNS = 20` live in **`pruefstand.core.models.dashboard`** (UI13-01) and are imported by
  `report/dashboard_export.py`, T6.1's `push_dashboard_data` (which applies the same rule to the whole
  published tree on every push, R13 P5.1) and T8.5's `verify_dashboard_export.py`; no local copies, no
  new CLI flag (interfaces §15 unchanged). Older runs keep `run.json`, `gate.json` and `slices.json`.
- `report.html` (case-published gated runs only) is `render_html(report, base, cand)`. `base` is the baseline run from `--runs` when
  `gate.json.baseline_run_id` names a run that is there, else `None` (always `None` for `no_baseline`;
  Y7.4, UI11-08, ui-spec §11.1). The export never fails because a baseline run is missing.
- The export first applies `sanitise_run` (T6.1): no chunk text, canaries masked, held-out cases
  dropped. Nothing unsanitised ever reaches the dashboard. The registry comes from T6.1's
  `store/canary_source.py` `load_canary_registry()` (slice `corpus/*/canaries.public.json` + T2.6 registries +
  held-out via `PRUEFSTAND_HELDOUT_DIR`); no registry found → error, no export.
- It only reshapes, never computes new metrics (every field is copied from `run.json` / `gate.json` /
  the run's results).
- Models = **exactly** interfaces.md §10.1 in `core.models.dashboard` (X5.3): `RunIndexEntry` (incl.
  `no_baseline`, and — **interface change by this task, UI13-19** — `block: int | None = None` and
  `judged_subset: bool = False`, copied from `RunManifest.block` / `.judged_subset`, so the runs list
  can show `nightly · b<k>` and `pr · subset`), `DashboardRunIndex`, `DashboardSliceRow` + `DashboardSlices {schema_version, run_id,
  rows}`, `DashboardCase` (incl. `lang`, `citations`, `retrieved_chunk_ids`,
  `retrieved_chunk_tenant_ids`, `refused`, `expect_refusal`, `error` class only, `metric_values`,
  `metric_status`, `failing`), `DashboardCases {schema_version, run_id, shard, n_shards, cases}`,
  `LabelsDocument {schema_version, metrics, causes, hard_fail_rules, informational_reasons}`. Copy field
  names, types and optionality from interfaces.md; do not rename. Every model has an exported JSON Schema.
- `DashboardSliceRow.kind` follows ui-spec §11.1: `absolute_checks` → `absolute`; `notable_slices` and
  every entry with `informational_reason` → `informational`; other `decisions` → `decision`. Each
  `SliceDecision` of `gate.json` yields exactly one row. The CI fields (`mean_diff`, `ci_low`,
  `ci_high`) are `None` when `result` is `None`.
- `GateReport.baseline_run_id` is `None` iff `no_baseline` (X5.5); `RunIndexEntry.no_baseline` and
  `baseline_run_id` are copied from `gate.json` (`False` / `None` without a gate).
- `RunManifest.judge_mode` is `github | local | skipped`; `judge_fallback`, `judge_degraded`,
  `judge_drift`, `judged_cases` are separate fields (interfaces §2). The index copies them, and
  `block` / `judged_subset` (UI13-19).
- `run.json.infra_error` reaches the export already reduced to its kind by `sanitise_run` (T6.1,
  UI13-13); the export copies it and never re-adds detail.

Build (ui-spec §2.4, X1.2): `DASHBOARD_DATA_DIR` is required. `pnpm build` runs
`scripts/dashboard/validate_data.mjs "$DASHBOARD_DATA_DIR"` (every rule of ui-spec §2.4; exit 1 naming
the file and the rule), copies the tree to `public/data/` (git-ignored), runs `next build`, then the
post-build `scripts/dashboard/csp.mjs` and `check_csp.mjs` (ui-spec §7.4).
`scripts/dashboard/build_set.sh <populated|empty> [--out <name>]` builds a fixture set into
`apps/dashboard/.sets/<name>/` (default = the set; `--out` lets T8.4 build `populated-try*` with other
`NEXT_PUBLIC_*` env, UI11-07) and writes the header-free `serve.json` (`{"cleanUrls": false,
"trailingSlash": true}`). Invalid data fails the build; the site has no "bad data" panel and no
`S-BAD-SCHEMA` state.

Hosting (Y7.1, D243): the site is served by **GitHub Pages** at the **root** of the public repo's Pages
site, `https://dheena18.github.io/pruefstand/`; the docs live under `/pruefstand/docs/`. `docs.yml`
(T0.4) is the single Pages writer; T8.5 builds the dashboard artefact and dispatches it (ui-spec §2.1).
The export must therefore never contain a top-level `docs/` path. Pages
cannot send response headers (`frame-ancestors` and `nosniff` cannot be set), so this task writes **no**
`headers.json`, `_headers` or `vercel.json`; every policy is a meta tag (ui-spec §7.4). `basePath` comes
from `NEXT_BASE_PATH` (`/pruefstand` in production and in T8.3's `basepath-smoke` job, empty by
default) and prefixes every absolute path we write, incl. the `theme-init.js` `src` (UI11-11). There is
**no** `public/.nojekyll`: Jekyll never runs with the Actions deploy, and T0.4's `assemble_pages_site.sh`
writes the one `.nojekyll` at the site root (UI12-20).

Empty dynamic segments (Y7.2, UI11-02, UI12-08, ui-spec §2.1): **every page generates its own params**
(a `runs/[id]/layout.tsx`, if any, exports no `generateStaticParams`), and each falls back to the
placeholder `_empty` when its own set is empty: summary → `[{id: "_empty"}]` for an empty index; case
pages → `{id, caseId: "_empty"}` for a published run without failing cases; `dynamicParams = false`
everywhere. The placeholder page renders the `EmptyState` of ui-spec §2.1 with `noindex`. T8.1 adds the
`runs/[id]` page shell that renders the placeholder; T8.2a/T8.2b keep the rule for their pages.
`validate_data.mjs` rule 8 rejects a real id `_empty`.

UI scaffold (ui-spec §2.1, §3, §7, §10.1; X5.1):
- File tree exactly as ui-spec §2.1: pass-through `src/app/layout.tsx`; `src/app/page.tsx` = root
  redirect document (`<html lang="de">`, meta refresh to `de/`, visible link, footer, no script);
  `src/app/not-found.tsx` = the site 404 document (exported as `out/404.html`); `src/app/[locale]/layout.tsx`
  (`<html lang={locale}>`, `generateStaticParams` → `de`, `en`, `dynamicParams = false`);
  `src/app/[locale]/{not-found,error}.tsx`. No `public/404.html`. `trailingSlash: true`. If `next build`
  rejects this tree, stop and report (CLAUDE.md §1).
- Shell components (`AppHeader` with mobile sheet, `AppFooter` with the attribution line from
  `src/content/licences.json`, `LocaleSwitch`, `ThemeToggle` 3-state, skip link, `EmptyState`,
  `ErrorPanel`, `NotFoundView`, `Skeleton`) per ui-spec §5. The no-flash theme script is the file
  `public/theme-init.js` loaded with a blocking `<script src>` (never inline, X5.2).
- CSP (ui-spec §7.4, X5.2, Y7.1): `scripts/dashboard/csp.mjs` inserts, as the first child of `<head>`,
  the per-page CSP `<meta>` with the sha256 of each Next-emitted inline script, plus the referrer meta,
  and adds `connect-src <demo origin>` only when `NEXT_PUBLIC_DEMO_API_URL` is set. It never touches
  `out/data/**`: each `report.html` already carries its own CSP meta from `render_html` (T6.4,
  UI11-10). `check_csp.mjs` fails on any `style=` attribute, `<style>` element or unhashed inline
  script outside `out/data/`; on a page without exactly one CSP meta; on a `report.html` whose meta hash
  differs from the sha256 of its own inline script; and on any `headers.json` / `_headers` /
  `vercel.json` in `out/`.
- Tokens in `src/styles/tokens.css` = ui-spec §7.1 values; `scripts/dashboard/tokens_to_report.mjs`
  regenerates T6.4's `report/templates/_tokens.css` (drift check in CI).
- `scripts/dashboard/gen_licences.mjs`: `DATA_LICENSES.md` → `src/content/licences.json` **and**
  `packages/pruefstand/src/pruefstand/report/templates/_licences.json` (ui-spec §4.7, UI9-23),
  drift-checked in CI like `gen:types` (UI-07).
- "Try it" nav link only when `NEXT_PUBLIC_DEMO_API_URL` is set at build (UI-25).

Types: `json-schema-to-typescript` → `src/types/generated/*.ts`, regenerated by `pnpm gen:types`; CI
fails if regeneration produces a diff. Runtime validation of loaded JSON with `ajv` and the same JSON
Schemas (shared with `validate_data.mjs`); reject unknown `schema_version`. Node 22 LTS, pnpm, Next.js
App Router, Tailwind, Recharts (charts in T8.2b). Design tokens, typography, spacing and themes: ui-spec
§7 (not invented here).

Fixtures (ui-spec §14.1, X1.2): two sets, `apps/dashboard/fixtures/populated/` and
`apps/dashboard/fixtures/empty/`, each a complete data tree that passes `validate_data.mjs`.

## Interfaces (must match `interfaces.md` exactly)

