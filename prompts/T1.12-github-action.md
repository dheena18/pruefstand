## Goal

1. **Tier 1 live** (`live-e2e.yml`): on every PR and on `main`, GitHub-hosted runners start the **real**
   stack (Qdrant, rag-demo v0, llama.cpp CPU generator, CPU embeddings) on the real slice corpus, run
   `pruefstand run` on the 20-case `smoke_live` split of `slice_v1` (round-8 W1.1), gate it against the latest
   `main` baseline, deciding on **hard fails and the `error_rate` absolute check only** (round 9 X5.6/X3.11: language, citation and refusal-phrase results and the `injection_success` check are reported, not gating), and post **one** real PR comment. A scenario
   matrix runs the T1.11 deterministic bug-switch scenarios nightly and on PRs touching `apps/rag-demo/**`.
2. A reusable Docker container Action `./action` (`run` + `gate` + `report`) and `action-selftest.yml`
   proving the Action image works against the same real stack.

## Context — scope

The real A40 gate (tier 2) runs in the private executor repo (T6.2a/b) and posts `pruefstand/gate`;
none of that is touched here. These workflows must **never** set a commit status with context
`pruefstand/gate`. Required checks from this task: `live-e2e / gate` and `action-selftest / selftest`
(workflow `name:` + aggregator job id).

Judged metrics arrive in T5.2b. This task already wires the **judge mode** end to end so T5.2b only
adds metrics. Round-8 W1.4/W1.6 (binding): in tier 1 judged metrics are **informational only** (they never
decide `live-e2e / gate`); they are judged through GitHub Models (`models: read`; the non-qwen model chosen in
T0.6) on at most **10 judge calls per PR run** and **60 per nightly** (`budget.max_requests_per_run` only, D143; there is no `RunnerConfig` judge field),
and cached. The tier-1 `eval_fingerprint` has an **empty** set of gated judge models, so judge availability never changes it.
Fork PRs (no `models` permission) and quota exhaustion (`QuotaExhausted`, D9-07) → judged metrics skipped,
`judge_mode=skipped` in run.json and a line in the comment. There is **no CPU fallback judge** in tier 1.

**Tier-1 budget (W1.2).** Generator ≤ 2B params, GGUF Q4_K_M, thinking off (T1.13); RAG profile `live`:
`top_k: 4`, chunk text truncated to 256 tokens in the prompt, `max_tokens: 256`, `reranker: off`. One PR run
≤ 20 min wall time; `timeout-minutes: 30` on `live`.

## Context — security model (must be followed exactly)

- Triggers: `pull_request`, `push: main`, `schedule` (nightly `37 2 * * *`, off-minute), `workflow_dispatch`. `pull_request_target` is banned in every workflow except `gate-router.yml` (X2.2; T0.2 guard).
- Top-level `permissions: {}`. Run jobs: `contents: read`, `actions: read` (download the main baseline artefact), `models: read` (`live-e2e.yml` only; `action-selftest.yml` runs with judged metrics off and has no `models` permission, ci-cd.md §1.1, R9-15). Only the `comment` job gets `pull-requests: write`, and only for same-repo PRs: `if: github.event_name == 'pull_request' && github.event.pull_request.head.repo.full_name == github.repository`. Fork PRs get the report in `$GITHUB_STEP_SUMMARY`.
- The `comment` job does not build or run PR code: it downloads the `comment.md` artefact, checks it with `action/check_comment.py` **checked out from the base SHA**, and upserts it with a pinned `actions/github-script` reading the body from the file.
- **Baseline trust (round 9 X1.4, D9-02):** two tier-1 baseline artefacts exist. **`live-baseline`** is written **only** by `push: main` runs, which use the PR shape (`examples/live/pruefstand.yaml`, split `smoke_live`, 20 cases), so its `eval_fingerprint` equals every PR run's. **`live-baseline-nightly`** is written by the nightly `schedule` run (`pruefstand.nightly.yaml`, 40 cases, a different fingerprint) and is never read by PRs. A PR compares **only** to `live-baseline` of the most recent **successful `push` run on `main`**, located by `gh api 'repos/{repo}/actions/workflows/live-e2e.yml/runs?branch=main&status=success&event=push&per_page=1'` and downloaded by run id (the nightly's fingerprint would raise `GateInputError`, exit 3). Artefacts from PR runs are never used as baselines. If none exists (first run) the job runs the baseline itself from the base SHA's rag-demo config, gates against it, says so in the comment and exits 0 (ci-cd.md §1.1a "Baseline").
- All actions pinned by full commit SHA; `persist-credentials: false`; `timeout-minutes` on every job; no `${{ }}` interpolation of PR-controlled strings into `run:`. No repository secrets; `GITHUB_TOKEN` only.

## Subtasks

- [ ] S1 `action/Dockerfile` from the T0.3 template; `action/action.yml` (Linux only): `runs.using: docker`; inputs `config` (`pruefstand.yaml`), `tier` (`pr`), `baseline-run` (optional path), `fail-on-warn` (`false`), `output-dir` (`.pruefstand/out`); outputs `status`, `run-dir`, `comment-path`. `baseline-run` is required until T6.1 adds `--from-store` (empty → exit 2 with a message), and it must be a run of the same config/dataset (same `eval_fingerprint`). Entrypoint `action/entrypoint.py` (subprocess with argument lists, no shell): run → gate → report md/json, writes `$GITHUB_OUTPUT`, appends to `$GITHUB_STEP_SUMMARY`, exits with the gate exit code.
- [ ] S2 `.github/workflows/live-e2e.yml` (replaces the T0.2 skeleton; keep its `probe_quota` dispatch input from T0.6). `name: live-e2e`. Jobs:
  - `prepare`: restore `actions/cache` for `~/.cache/pruefstand/models` (key = SHA-256 list from `infra/models/*.yaml`) and for the Qdrant snapshot of the slice index (key = slice `corpus_version` + embedding model SHA + `hashFiles('apps/rag-demo/src/rag_demo/**')`, so an analyzer/indexer change in T3.3/T3.4 rebuilds the index instead of restoring a stale one; ci-cd.md §4); on miss run `scripts/models/fetch.py` and `make index-slice` (T1.13); build the rag-demo image with the gha layer cache (`cache-to: type=gha,mode=min`). Model and index caches are **saved only on `main`** (`actions/cache/save` guarded by `github.ref == 'refs/heads/main'`; PR jobs use `actions/cache/restore`), so PRs cannot evict them; the job summary prints `gh cache list --json sizeInBytes` total (target ≤ 7 GB, model files ≤ 4 GB; A8-24).
  - `live`: needs `prepare`; `docker compose --profile live up -d --wait`; resolve the baseline (security model); `pruefstand run --config examples/live/pruefstand.yaml --tier pr --out runs/` (split `smoke_live`; the nightly `schedule` run uses `--config examples/live/pruefstand.nightly.yaml` = the same file with splits `smoke_live` + `smoke` (all 40 cases) and `budget.max_requests_per_run: 60`; this task adds that file); `pruefstand gate`; `pruefstand report --format md > comment.md`; then the `live`-marked tests that need only the running stack: `PRUEFSTAND_TARGET_URL=http://localhost:8000 uv run pytest -m "live and not e2e and not gpu and not network" packages/pruefstand/tests apps/rag-demo/tests/live` (round 9 D9-16: `live`+`gpu` tests need the A40 endpoints and `live`+`network` tests spend the GitHub Models budget; T4.2, T4.5 and T5.1 add such tests) (T1.3 `test_contract_live`, T1.4 llm live tests, T1.8 `test_runner_live`, T1.13 `test_live_app`; no other job runs `-m live`); upload `comment.md`, `gate.json`, `run.json`; on `push: main` also upload the run dir as artefact **`live-baseline`**, on the nightly `schedule` as **`live-baseline-nightly`** (X1.4; retention 90 days each; the schedule run never uploads `live-baseline`). Exit code = gate exit code, except "first run without baseline" → 0.
  - `scenario-baseline`: runs the `good` baseline once per workflow run (splits `smoke_live` + `smoke`, all 40 fixtures, interfaces §2) and uploads it as an artefact that every matrix leg downloads (AI-02).
  - `scenarios`: matrix over the **5 deterministic** T1.11 scenarios (`good`, `tenant_filter_post_topk`, `shared_public_unfiltered`, `system_prompt_guard_off`, `injection_guard_off`; round-8 W1.5), one parallel job per scenario, `PRUEFSTAND_E2E_SCENARIO=${{ matrix.scenario }}` passed via `env:`, runs `pytest -m "e2e and live" packages/pruefstand/tests/e2e`; `fail-fast: false`; ≤ 20 min each, `timeout-minutes: 30`. Runs on the nightly `schedule`, `workflow_dispatch`, and on PRs that change `apps/rag-demo/**` (decided by a cheap first step; job still reports success when skipped). Scenarios assert only hard fails / absolute checks, so they are not flaky; statistical scenarios live in tier 2 (T6.5).
  - `comment`: as in the security model.
  - `gate` (aggregator job, required check `live-e2e / gate`): `needs: [prepare, live, scenario-baseline, scenarios]`, `if: always()`, fails unless all succeeded or `scenarios` was legitimately skipped.
  - Budget (W1.2): ≤ 20 min per PR run (cache-warm target ≤ 12 min), `timeout-minutes: 30` on `live`; ≤ 20 min per scenario job (`timeout-minutes: 30`); judge calls ≤ 10 per PR run, ≤ 60 per nightly (W1.6, checked against the T0.6 measured daily limit in ci-cd.md §1.1a); record wall times and judge-call counts in the job summary.
- [ ] S3 Judge-mode plumbing (W1.4): `PRUEFSTAND_JUDGE_MODE=skipped` when the PR head repo ≠ this repo (expression via `env:`), otherwise unset (judging through GitHub Models with `models: read`). On `QuotaExhausted` (T5.1 raises it for the exhausted GitHub Models quota) the runner stops judging and the run records `judge_mode=skipped` (or `github` if some judged values were produced before the quota ran out, with `counts.judge_skipped` and reason `judge_quota`; T1.8 S3c).
