## Goal

A reproducible **reduced** grid over 2 embeddings × 2 retrieval modes × 2 chunkings × compound split
on/off (16 configs, 12 effective) that reports the drop of `evidence_recall` (span-level, primary for the
chunking axis), `context_recall` and `answer_correctness` per perturbation type vs the unperturbed base
question, as CSV + heatmap + a "fix first" list.

## Context

**`evidence_recall` is owned by this task (round 9 X3.2, D162; interfaces §5).** It is an **experiment metric**:
it lives in `experiments/rq1/evidence_recall.py`, is **not** registered in `KNOWN_METRICS` / the
`MetricRegistry`, and is never gated. Definition: per case, 1 if any retrieved chunk's text contains the case's
gold `TestCase.evidence_span` (≤ 60 model tokens, the answer-bearing sentence(s) of the cited Absatz, emitted by
T4.2 S3) after whitespace/hyphen normalisation (collapse whitespace, join soft hyphen and line-break hyphenation,
NFC); 0 otherwise; `evidence_span is None` → `not_applicable` (count reported). It is computed from the run's
`responses.jsonl` chunk texts (the A40 run dirs, never published). T7.1a's M02 lists it under
`secondary_metrics`.

Embeddings (core): BGE-M3 (production) and multilingual-e5-large (SPEC §8 RQ1: 2 core models + optional third). Both go into `infra/gpu/models.yaml`
(catalogue ids `ollama/<tag>`, D221; served by **Ollama on GPU0** through the native `/api/embed` with the entry's
fixed catalogue `options`, the same values the preload uses, so no grid request triggers a reload, D219/D220; through
the VM tunnel; there is no TEI on the GPUs, round 10 Z3.
**Verify** that an Ollama tag of `multilingual-e5-large` exists with a licence on the allowlist and matches the
reference checkpoint (cosine ≥ 0.99 on 20 passages, like bge-m3 in T3.1b); if not, serve e5 on the **VM CPU** with
sentence-transformers in the same way as `rerank-cpu` (a second CPU service, within the VM's 24 GB CPU-model
budget) and record the choice). **e5 needs its prefixes (round 8 W3.10, D121):** the catalogue entry sets
`query_prefix: "query: "`, `doc_prefix: "passage: "`, `max_input_tokens: 512`; the rag-demo encoder applies
them and truncates passages to the model limit, logging `truncated_chunks` in the collection metadata. The
grid refuses to run an e5 config whose collection metadata lacks the prefixes, and `drops.csv` reports
`truncated_chunks` per config — without this the BGE-M3 vs e5 comparison is confounded by an integration bug.
Because e5 truncates per-§ chunks at 512 tokens while BGE-M3 does not, the e5 results are **also** reported on
the cases whose gold § chunk is ≤ 512 tokens, as a sensitivity row (SPEC §8 RQ1, AI9-23).

**Optional extension** (tier `optional`, only if GPU time allows after the core grid): a third,
German-specific embedder pinned by this task (best German retrieval on MTEB / GerDaLIR among models
≤ 3 GB in FP16, licence allows publishing results; served like e5 above), run with `--extended`. The core results and the
report never depend on it.

Grid axes:
- Retrieval: dense-only vs hybrid.
- Chunking: per-§ (the corpus chunks) vs fixed **512**-token sub-chunks (the one fixed size in this document; M02's
  256 is a separate regression mutation, AI9-23) via the rag-demo indexer option
  `chunking: {strategy: fixed_tokens, size: 512}` (T3.4). `corpus_version` is unchanged, so gold doc
  ids and the `run_eval` corpus precondition still hold. **Scoring (W3.11, D122):** sub-chunks inherit the
  § doc id, so doc-level `context_recall` counts any piece of the § as a hit, even the piece without the
  answer. The chunking axis is therefore scored with **`evidence_recall`** (definition above; the span is ≤ 60
  tokens, so a long Absatz no longer scores 0 by construction under fixed chunking, AI9-23); `context_recall` is
  secondary. **Equal text volume (round 13 P3.2, binding):** the chunking arms are compared at **equal total
  retrieved tokens**, not equal `top_k`: every config takes the ranked chunks until a fixed, pre-registered token
  budget (4 096 tokens, counted with the generator tokenizer, AI13-05) is reached (the last chunk cut at that budget),
  so per-§ and 512-token sub-chunks hand the same text volume to scoring and generation; `top_k` 8 results are a
  secondary sensitivity row.
- Compound split: analyzer on/off. This only matters for hybrid; dense-only rows mark it n/a, which
  leaves 12 effective configs (18 with `--extended`).

Each config gets its own collection `rq1_<config_hash>` (created by the orchestrator like a
PR-scoped index; the orchestrator takes `/var/lib/pruefstand/gpu.lock` once per run, X2.1/D211). **GPU-time plan
(AI11-13):** grid runs are dispatched only outside the night window 22:00–06:00 Europe/Berlin (D223), at most 4 per
weekday and the rest on weekends, never while `/var/lib/pruefstand/MAINTENANCE` exists; any direct GPU command of
this task runs as `pruefstand-lock <cmd>` (D212). The README records the estimated and the measured GPU hours. A run
that ends with `infra_error` (D226) is re-run, never analysed. Overrides are applied to
`rag.gpu.yaml` (X3.15). Collections are reused across reruns and deleted with `--cleanup`.

The drop per perturbation p is the mean over `cluster_id`s of (metric(perturbed) − metric(base)),
with a cluster bootstrap 95 % CI.
- `answer_correctness` drops are reported twice: on all cases, and excluding cases tagged
  `closed_book_answerable` (contamination control); the size of the retrieval-sensitive subset and its MDE
  are printed.
- Retrieval metrics need no judge and no generation: **every** `rq1` case (300 bases × their applicable
  perturbations) runs through the target's `POST /v1/retrieve` only. **Generation is limited to the correctness
  subsample** (round 13 P3.2, AI13-13): `/v1/query` + the A40 PR judge (W3.1, judge cache) run only on a fixed,
  pre-registered seeded subset of `rq1` bases × their perturbations (seed 1234, size from `budget.py --experiment
  rq1` with that count, listed in `results/_inputs/rq1/correctness_sample.json` before the first run; AI11-13);
  if T5.4 found no passing judge (`calibration_status.yaml`), the correctness table is labelled
  "judge uncalibrated" and the report treats it as secondary.
- **Multiplicity:** the "fix first" list applies Benjamini–Hochberg at q = 0.10 over all config ×
  perturbation × metric cells before ranking (`bh_adjust`, interfaces §9); `fix_first.md` says so.
