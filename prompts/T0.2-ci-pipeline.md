## Goal

Every push and PR runs the hosted CI tier (lint, types, architecture, tests with coverage gates,
security scans) on GitHub-hosted runners. The repo has a PR template, CODEOWNERS and Dependabot.
Workflow-level guards make it impossible to add `pull_request_target` (except the one documented
`gate-router.yml` exception, X2.2) or a self-hosted runner to a public workflow.

## Context

Every model and target in CI is **real** (ADR-0008: no simulated LLMs or targets). Hosted CI has two kinds of jobs: tier 0
(`ci.yml`: pure unit tests on real inputs, statistical validation of `gate.stats`, cassette tests replaying
responses recorded from real models, contract tests) and **tier 1 live** (`live-e2e.yml`: the real stack —
Qdrant, rag-demo, a llama.cpp CPU generator, a real judge via GitHub Models — on the real 5-law slice;
filled in by T1.12). This task creates the `live-e2e.yml` and `cassettes.yml` **skeletons** so the
permission rules are fixed early. The GPU
tier runs in a **separate private executor repo** (T6.2a/b) whose persistent runner lives on the TrueNAS VM
`pruefstand-exec` and reaches the A40s only through SSH tunnels to two Ollama servers on the cluster (round 10
Z1); it **pulls** work from this repo (tier 2 for a PR starts only when the owner dispatches the private `gate-executor.yml`, round 13 P1.2; there is no `run-gate` label); the public repo has **no executor secrets and no dispatch workflow** for
the gate (its only gate-related secret is the `pruefstand-bot` App key in environment `gate-router`, used by `gate-router.yml` alone, P1.1) and never has a self-hosted runner (ADR-0005, ci-cd.md §5/§7). Make targets are defined by T0.1 and CLAUDE.md
§3; this task calls them and does not redefine them. Jobs that will later be **required checks** must
run on every PR, with no path filters: use a cheap "nothing to do → exit 0" step inside the job instead.

Public workflow names (ci-cd.md §1.1): `ci.yml`, `ui.yml`, `docs.yml`, `security.yml`,
`action-selftest.yml`, `build-images.yml`, `live-e2e.yml`, `cassettes.yml`, `release-please.yml`,
`release.yml`, `dataset-release.yml`, `deploy.yml`. There is **no** `gate-dispatch.yml`. The private executor has
`gate-executor.yml`, `nightly.yml`, `baseline-promote.yml` (ci-cd.md §1.2).

**Required-check names** (ci-cd.md §5; T0.5 sets them): `ci / check`, `ui / check`, `docs / build`,
`security / scan`, `action-selftest / selftest`, `build-images / build`, `live-e2e / gate`, `pruefstand/gate`. So every
workflow ends in **one aggregator job** with that name (`needs:` all other jobs, `if: always()`,
fails if any needed job failed or was cancelled). Individual jobs keep their own names for logs.

## Subtasks

- [ ] S1 `.github/workflows/ci.yml` as in ci-cd.md §1. Triggers: `pull_request`, `push: main` (no `merge_group`: no merge queue is configured, and enabling one would need `merge_group` on every required workflow and executor support; A8-40). Runner `ubuntu-24.04`. Top-level `permissions: {}`; jobs get `contents: read`. Concurrency block from §6. Jobs, each calling one Make target:
  - `lint`, `typecheck`, `arch`, `file-size`
  - `test` (`make coverage`: unit + property + contract + coverage gates)
  - `test-slow` (`make test-slow`, i.e. `-n auto` via pytest-xdist; `timeout-minutes: 30`, D8-06; the statistical simulations run their **reduced PR grid** here, the full grids run nightly, W4.5), `test-integration` (Docker is available on hosted runners); there is no `e2e` job here (e2e runs in `live-e2e.yml`, T1.12)
  - `schemas-fresh`
  - `commitlint` (the PR title must be a Conventional Commit; pinned action)
  - `workflow-guards` (S3)
  - `check` — the aggregator (required check `ci / check`): `needs:` every job above, `if: always()`,
    one step that fails unless every `needs.*.result` is `success`.

  Other settings:
  - Jobs whose tests don't exist yet pass (pytest exit 5).
  - `timeout-minutes` ≤ 15 everywhere except `test-slow` (30).
  - A nightly `schedule` (`13 1 * * *`, off-minute) runs only the schedule-only jobs, which are **not** in `check`'s `needs:` (informational, hosted, free minutes; R9-13: these CPU jobs never run on the private A40 runner): `simulation-full` (`make test-slow` with `PRUEFSTAND_SIM_GRID=full`, the 4 000-sim grids of T1.6/T1.7, `timeout-minutes: 120`), `hypothesis-full` (`HYPOTHESIS_PROFILE=nightly`, `timeout-minutes: 60`) and `mutmut` (`gate/`, `metrics/`; exits 0 with a message until those packages have code; `timeout-minutes: 300`). On `pull_request`/`push` these jobs are skipped (`if: github.event_name == 'schedule'`), and on `schedule` the PR jobs are skipped. PR and push runs use the reduced grid (default `PRUEFSTAND_SIM_GRID=reduced`). A nightly failure shows on the commit and in the Actions tab.
  - Every job installs with `make install` (`uv sync --all-packages --all-extras`, D9-23: the doctest run imports optional-extra modules).
  - Use `astral-sh/setup-uv` with `enable-cache: true`, plus the Hypothesis DB cache from §4.
  - `actions/checkout` with `persist-credentials: false`.
