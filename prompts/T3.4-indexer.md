## Goal

`rag-demo index --corpus corpus/<version>` reads the tenant chunk files (validated against
`schemas/chunk.schema.json`, without importing `pruefstand`), computes dense (tier 2: `bge-m3` via
**Ollama on GPU0** through the VM tunnel; tier 1: the small CPU model via TEI CPU) and sparse vectors, and
upserts them into **one** Qdrant collection (on the VM) with a keyword payload
index on `tenant_id` (`is_tenant=true`), idempotently, recording `corpus_version` for `/v1/info`.

## Context

**This task extends rag-demo v0 (T1.13)**: the module already exists in minimal form and is used by tier-1 CI. Upgrade it in place, keep every bug switch from T1.13 working (their tests must stay green) and keep the CPU `live` profile working. No new parallel module, no stub/simulated classes (ADR-0008); tests use the real services (Testcontainers Qdrant, TEI CPU, llama.cpp from compose `live`) or cassettes recorded from them.

- Collection name = index fingerprint: `chunks__<corpus_version>__<analyzer_hash8>__<embed_model_slug>`;
  alias `chunks_active` points to the current one (switch alias atomically after a full build). A
  `rag*.yaml` change that affects indexing (analyzer, embed model, chunking) ⇒ new collection.
- PR-scoped collections (D39): `rag-demo index --collection pr_<N>_<shortsha> --no-alias` builds a
  collection that only that PR's gate job reads (`index.collection` override in the PR's `configs/rag.gpu.yaml`, the tier-2 profile the executor reads, X3.15); the
  executor deletes it after the job (`rag-demo index --drop pr_<N>_<shortsha>`). PR jobs never
  write to `chunks_active`.
- Vectors: named `dense` (size from model, cosine) + sparse `sparse` (`modifier=idf`).
- Payload: `tenant_id` (from `Chunk.tenant`), `doc_id`, `chunk_id`, `citation_key`, `section`,
  `lang`, `text`, `source`, `is_attack`, `version_date`. Point id = uuid5(namespace, chunk_id).
- `DenseEncoder` implementations (both real HTTP clients, batch 32, timeout, retries): **`TeiDenseEncoder`** for
  **tier 1** (TEI CPU in compose `live`, unchanged from T1.13) and **`OllamaDenseEncoder`** for **tier 2**
  (native **`POST <url>/api/embed`** only, never `/v1/embeddings` (Y3.1, D219); `<url>` from `embed.endpoint_env`:
  `OLLAMA_GPU0_URL` in the dev stack, `LLM_PROXY_URL=http://llm-proxy:11500` in gate runs (D242);
  body `model` = the **bare** tag `bge-m3` (the config holds `catalogue_id: ollama/bge-m3`, D221), `input` = list of
  texts, `truncate: true`, `options` = exactly the catalogue entry's `options` (`num_ctx` = `max_input_tokens` = the
  max chunk tokens, e.g. 1 024–2 048, never the model's 8 192 default: round 12 AI12-08, the KV is allocated
  `NUM_PARALLEL` times on GPU0 next to the generator; chunks longer than that are counted in `truncated_chunks`;
  `llm-proxy` enforces `num_ctx` anyway, N2); never `keep_alive`). **Bearer key (Y2.1, D216; owned by
  this task):** when the variable named by `embed.api_key_env` (default `PRUEFSTAND_CANDIDATE_API_KEY`) is set and
  non-empty, every request carries `Authorization: Bearer <value>`; unset or empty → no header (tier 1 and the
  dev stack); the value is read once at construction and never logged, put in an exception or a cassette
  (cassette recording redacts the header). Selected by `embed.engine` (T3.2). There is
  **no TEI or vLLM on the GPUs** (round 10 Z3). Ollama does not report per-input truncation: count
  `truncated_chunks` by a token count with the model's tokenizer against `max_input_tokens`. **Tokenizer
  dependency (DEV11-21):** the HF `tokenizers` package (pinned in `apps/rag-demo/pyproject.toml`, decision row with
  the reason) and the model's `tokenizer.json` of the pinned revision, **baked into the image at build time**
  (the candidate has no internet at runtime) and in the repo's test fixtures for CPU tests; no `transformers`. **Prefixes and truncation (round-8 W3.10):** per-model `query_prefix`, `doc_prefix`, `max_input_tokens` come from `infra/models/live-models.yaml` (tier 1) and `infra/gpu/models.yaml` (tier 2); e5-family models (`multilingual-e5-small` in tier 1, `multilingual-e5-large` on the RQ1 axis) use `query: ` / `passage: `, BGE-M3 none. Every request sends `truncate: true`; passages longer than `max_input_tokens` are counted, logged and stored as `truncated_chunks` in the collection metadata (index-time count; it is **not** part of `/v1/info.serving`, which holds static fields only, round 9 X3.13/D9-14; the runtime prompt-truncation counter is `/v1/health.stats.truncated_chunks`). Tests use the real
  TEI CPU service from compose `live` (small multilingual model pinned in T1.13) or TEI responses recorded
  from it (cassettes); tier 2: Ollama `bge-m3` on GPU0 through the tunnel (cassettes recorded from it on the VM).
- Integration tests use **Testcontainers** Qdrant (pinned image digest), marker `integration`.

## Constraints and non-goals

- Never import `pruefstand`; the schema copy is the contract.
- Qdrant API key from env; no default credentials in compose for non-dev profiles.
- Nothing runs on or is written to the cluster; Qdrant storage stays on the VM disk (`$PRUEFSTAND_HOME/qdrant`), never in the data root (gpu-cluster.md §9). Read the corpus from the data root (`$PRUEFSTAND_DATA_ROOT/corpus/`, VM disk).
