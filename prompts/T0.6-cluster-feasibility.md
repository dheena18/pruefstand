- [ ] S2 `infra/cluster/feasibility/tunnel_check.sh` (runs on the VM or WSL, **not** on the cluster). On the VM, where `pruefstand-tunnel.service` already forwards `127.0.0.1:11434` (setup log §3), `--use-existing-tunnel` probes `http://127.0.0.1:11434` and opens no forward (`fwd` = PASS "existing tunnel"). Otherwise it opens **one** forward `ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:${PROBE_PORT0:-21434}:localhost:11434 cairo-s101lp` in the background (killed by `trap`; ADR-0018: no second port). The **temporary local port 21434** (round 11 Y1.4, DEV11-05) never clashes with the tunnel on `127.0.0.1:11434`. If it is busy, the script prints `CHECK fwd FAIL local port <n> in use (set PROBE_PORT0)`, not a misleading "forwarding forbidden". Then it prints `CHECK` lines:
  - `fwd` (port forwarding allowed, or the existing tunnel);
  - `api-tags` (`GET /api/tags` 200; lists `qwen3.8:27b-q8_0` with the digest of setup log §3, else WARN);
  - `api-chat-nothink` (native `/api/chat` with `"think": false`, `options.num_ctx: 8192`, German prompt "Sag in einem Satz Hallo." → German text, no thinking content, no `<think>`);
  - `api-ctx` (native `/api/chat` with a ≈ 7 000-token German prompt and `options.num_ctx: 8192` → PASS iff the response's `prompt_eval_count` ≥ 6 900; AI11-01 evidence that the native API applies `num_ctx`);
  - `api-openai` (**informational**: `/v1/chat/completions` with the same long prompt; records `usage.prompt_tokens` to document why tier 2 never uses `/v1/*`, round 11 Y3.1);
  - `api-embed` (`/api/embed` with `bge-m3` → WARN if not pulled yet);
  - `detached-survives-logout` (round 11 Y5.4, A11-11): a first, **non-interactive** SSH connection runs `setsid nohup sleep 900 >/dev/null 2>&1 < /dev/null & echo $!` and exits; after 5 s a **second** SSH connection runs `kill -0 <pid>` → PASS if alive, then `kill <pid>`; FAIL otherwise.

  It never pulls, loads other models or changes `keep_alive` beyond the default. `--print-cmd` prints the SSH commands without running them (for the unit test).
- [ ] S3 `infra/cluster/feasibility/summarise.py` (stdlib only): reads probe + tunnel output from stdin, prints a Markdown table (id, status, detail) and the verdict: **go** iff `gpu`, `ollama`, `detached-survives-logout`, `models-space`, `net`, `fwd`, `api-tags`, `api-chat-nothink`, `api-ctx` PASS. **go-with-conditions** if additionally only WARNs exist, with one condition line per WARN (e.g. `model-load WARN` → "first model load ≈ <n> min; excluded from budgets"; `models-space WARN` → "free space on /data first (swap rule, ADR-0019)"; `ollama-list WARN` → "generator tag missing: pull it (T3.1a S2b)"; `ollama-store WARN` → "server env differs from setup log §7: fix ~/start-ollama.sh (owner step, runbook §2a)"; `gpu-procs WARN` → "VRAM held by another process"; `port-11434 WARN` → "port held by <x>: stop it or use free ports"; `ollama-provenance WARN` → "local-only tag: back up blobs + manifest (T3.1a S2b)"). Any FAIL among the go checks → **no-go**. `docker`, `vllm`, `tmux`, `logind`, `local-disk`, `api-openai` never change the verdict. A `detached-survives-logout` FAIL is **no-go** with the condition "servers die at SSH logout (KillUserProcesses=<value from logind>): the admin must allow detached processes or enable linger".
