## Goal

An evidence-based **go / no-go** for serving all tier-2 models with **two Ollama servers on
`cairo-s101lp`** (models on the NAS, reached from the VM through SSH tunnels), recorded in
`gpu-cluster.md` §0.2 rows C1–C8, **and** measured free-tier quotas of GitHub Models (C9). VM checks

## Context

Known (round 10, 2026-10-31): plain SSH to `cairo-s101lp`, 2 × A40 idle, `/` 7 GB and `/data` 14 GB
free (so **nothing** may be written outside the NAS mount `/data/dheena/truenas-ollama`), Ollama installed
with `qwen3.8:27b-q8_0` (29 GB), Docker/vLLM assumed absent, `Linger=no`. This task confirms what is
still open: Ollama version and model metadata (family, licence, context, digest, provenance), whether a
**detached process survives logout** (round 11 Y5.4: Ollama is started with `setsid nohup`, not `tmux`; if
the site kills user processes at logout, the design is a no-go), who holds port `:11434`, NAS mount type,
free space and **read throughput** (it sets the first-load time of a 29 GB model), SSH port forwarding,
the Ollama API through a tunnel with thinking off, and outbound HTTPS for model pulls.

The owner cannot copy files to the cluster. The probe is therefore **piped over SSH**, never copied:
`ssh cairo-s101lp 'bash -s' < infra/cluster/feasibility/probe.sh > probe.out` (run from the VM checkout or
WSL; **verify** that piping works, else paste the script into the SSH session). Output comes back on
stdout. The probe is **read-only**, except one temp dir under the NAS root (`mktemp -d`), removed by a
`trap`.

On the VM, the only cluster key belongs to the service user `pruefstand` (round 11 Y1.1, created by T0.7):
run both scripts there as `sudo -u pruefstand …` (the owner types the commands; the key is never copied).
Before T0.7 has created the key, run them from WSL with the owner's interactive SSH login instead.

## Subtasks

- [ ] S1 `infra/cluster/feasibility/probe.sh` (bash, `set -euo pipefail`, shellcheck clean). Each check prints `CHECK <id> <PASS|FAIL|WARN> <detail>` and never aborts the script. `NAS_ROOT` defaults to `/data/dheena/truenas-ollama`. Checks:
  | id | What | Command (guide) |
  | --- | --- | --- |
  | `os` | distro, kernel | `cat /etc/os-release`, `uname -r` |
  | `gpu` | 2 × A40 visible, memory used ≈ 0, driver version | `nvidia-smi --query-gpu=index,name,memory.total,memory.used,driver_version --format=csv` |
  | `gpu-procs` | who holds VRAM (an already running Ollama?) | `nvidia-smi --query-compute-apps=pid,used_memory --format=csv`; `ps -o user=,pid=,args= -C ollama` |
  | `ollama` | binary + version | `command -v ollama; ollama --version` |
  | `ollama-models` | `ollama list`; for each model `ollama show <tag>` (architecture, parameters, context length, quantisation, licence first line); WARN if `qwen3.8:27b-q8_0` is missing or its architecture is not a Qwen one | `ollama list`, `ollama show` |
  | `ollama-store` | where the current server stores models (default `~/.ollama/models` on the full local disk vs the NAS) | `ls -d ~/.ollama/models`, `du -sh` (read-only), `tr '\0' '\n' < /proc/<pid>/environ \| grep OLLAMA_` if the server is the user's own |
  | `ollama-provenance` | where the generator tag comes from (AI11-08): registry tag or built locally | `ollama show --modelfile qwen3.8:27b-q8_0 \| head -5` (FROM line); registry manifest probe `curl -sS -o /dev/null -w '%{http_code}' https://registry.ollama.ai/v2/library/<name>/manifests/<tag>`; WARN "local-only tag: copy blobs + manifest to the NAS and `backups/models/` (T3.1a S2b)" if the registry does not have it |
  | `port-11434` | who holds `:11434` / `:11435` (a distro `ollama.service` would collide with `ollama-gpu0`; DEV11-14, AI11-06) | `ss -ltnp \| grep -E ':1143[45]'`; `systemctl status ollama --no-pager` (read-only); WARN "port held by <owner/unit>: the admin stops it, or we pick free ports (e.g. 11534/11535) in `.env` + docker.md §3" |
  | `logind` | record `Linger` and `KillUserProcesses` (informational; explains a `detached-survives-logout` FAIL) | `loginctl show-user "$USER" -p Linger -p KillUserProcesses`; `grep -i KillUserProcesses /etc/systemd/logind.conf` |
  | `tmux` | informational only (serving no longer uses tmux, Y5.4) | `command -v tmux` |
  | `nas-mount` | NAS mounted, type, options | `findmnt -T "$NAS_ROOT"`; `mountpoint -q` |
  | `nas-space` | free space on the NAS dataset | `df -h "$NAS_ROOT"` |
  | `nas-write` | writable (needed for `ollama pull` into `ollama-models/`) | write and delete 1 file in `mktemp -d "$NAS_ROOT/.probe.XXXX"` |
  | `nas-read` | sequential read MB/s of an existing large file (model blob), 4 GiB, read-only | `dd if=<largest blob> of=/dev/null bs=16M count=256 iflag=direct status=progress` (WARN < 200 MB/s: first load of 29 GB > 2.5 min; FAIL < 30 MB/s) |
  | `nas-latency` | metadata latency | `time ls -l "$NAS_ROOT/ollama-models/blobs"` (or the current store) |
  | `local-disk` | confirm local disk is full (informational, documents "nothing on the cluster") | `df -h / /data` |
  | `net` | outbound HTTPS for pulls | `curl -sS -o /dev/null -w '%{http_code}' https://registry.ollama.ai/v2/ https://huggingface.co` |
  | `docker` / `vllm` | informational only (assumed absent, Z1) | `command -v docker podman apptainer` |
- [ ] S2 `infra/cluster/feasibility/tunnel_check.sh` (runs on the VM or WSL, **not** on the cluster): opens `ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:${PROBE_PORT0:-21434}:localhost:11434 -L 127.0.0.1:${PROBE_PORT1:-21435}:localhost:11435 cairo-s101lp` in the background (killed by `trap`). The **temporary local ports 21434/21435** (round 11 Y1.4, DEV11-05) never clash with T0.7's `pruefstand-tunnel.service`, which already holds `127.0.0.1:11434/11435` when this task runs. If a temporary port is busy, the script prints `CHECK fwd FAIL local port <n> in use (set PROBE_PORT0/1)`, not a misleading "forwarding forbidden". Then it prints `CHECK` lines:
  - `fwd` (port forwarding allowed);
  - `api-tags` (`GET /api/tags` 200 on the GPU0 forward; GPU1 forward → WARN if no second server yet);
  - `api-chat-nothink` (native `/api/chat` with `"think": false`, `options.num_ctx: 8192`, German prompt "Sag in einem Satz Hallo." → German text, no thinking content, no `<think>`);
  - `api-ctx` (native `/api/chat` with a ≈ 7 000-token German prompt and `options.num_ctx: 8192` → PASS iff the response's `prompt_eval_count` ≥ 6 900; AI11-01 evidence that the native API applies `num_ctx`);
  - `api-openai` (**informational**: `/v1/chat/completions` with the same long prompt; records `usage.prompt_tokens` to document why tier 2 never uses `/v1/*`, round 11 Y3.1);
  - `api-embed` (`/api/embed` with `bge-m3` → WARN if not pulled yet);
  - `detached-survives-logout` (round 11 Y5.4, A11-11): a first, **non-interactive** SSH connection runs `setsid nohup sleep 900 >/dev/null 2>&1 < /dev/null & echo $!` and exits; after 5 s a **second** SSH connection runs `kill -0 <pid>` → PASS if alive, then `kill <pid>`; FAIL otherwise.

  It never pulls, loads other models or changes `keep_alive` beyond the default. `--print-cmd` prints the SSH commands without running them (for the unit test).
- [ ] S3 `infra/cluster/feasibility/summarise.py` (stdlib only): reads probe + tunnel output from stdin, prints a Markdown table (id, status, detail) and the verdict: **go** iff `gpu`, `ollama`, `detached-survives-logout`, `nas-mount`, `nas-write`, `nas-read`, `net`, `fwd`, `api-tags`, `api-chat-nothink`, `api-ctx` PASS. **go-with-conditions** if additionally only WARNs exist, with one condition line per WARN (e.g. `nas-read WARN` → "first model load ≈ <n> min; excluded from budgets"; `ollama-models WARN` → "generator must be re-pulled into ollama-models/ (T3.1a)"; `gpu-procs WARN` → "VRAM held by another process"; `port-11434 WARN` → "port held by <x>: stop it or use free ports"; `ollama-provenance WARN` → "local-only tag: back up blobs + manifest (T3.1a S2b)"). Any FAIL among the go checks → **no-go**. `docker`, `vllm`, `tmux`, `logind`, `local-disk`, `api-openai` never change the verdict. A `detached-survives-logout` FAIL is **no-go** with the condition "servers die at SSH logout (KillUserProcesses=<value from logind>): the admin must allow detached processes or enable linger".
