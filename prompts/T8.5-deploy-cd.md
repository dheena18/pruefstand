## Goal

Two independent deploys, each gated by verification, followed by smoke checks and a defined rollback:
- the static **dashboard on GitHub Pages** at the **site root** `https://dheena18.github.io/pruefstand/`
  (`basePath` `/pruefstand`; the docs live at `/pruefstand/docs/`), built from **sanitised, validated**
  run exports with a digest manifest and the ui-spec §7.4 meta CSP; `deploy.yml` builds the artefact
  `dashboard-site`, and `docs.yml`, the single Pages writer (D243), deploys it on `workflow_run` (N5.2);
- the **optional demo API on the VM** behind a free Cloudflare Tunnel: a clean leak-probe run in
  **`demo-ready.yml`** (a separate public workflow on `workflow_run` of `release.yml`) marks the release image digest
  **demo-ready** by uploading the release asset **`demo-ready.json`**, and a private nightly job
  `demo-deploy` reads the latest release with **one** anonymous API call, pulls exactly that public GHCR
  digest anonymously, verifies it and runs it, followed by the nightly `demo-e2e` (D244, N5.3, R13 P5.3).
  `deploy.yml` is **dashboard-only**: a leak (a designed outcome) or any demo failure can no longer fail
  the run that carries the fresh `dashboard-site` (UI13-06).

Nothing is ever deployed from "the latest artefact with this name". Vercel and Fly.io are dropped
(Y7.1, Y7.5); no paid hosting; no `demo` or `preview` GitHub environment.

## Context

### Dashboard (public repo, `deploy.yml` → `docs.yml` by `workflow_run`)

**One Pages site, one writer (D243, ADR-0017).** A repo has one Pages deployment. `docs.yml` (T0.4) is
the **only** workflow with `pages: write`; it deploys **one** artefact: the dashboard export at the site
root and the mkdocs site under `docs/`. This task owns the **dashboard half**:
- `deploy.yml` builds the dashboard and uploads its `out/` as artefact **`dashboard-site`**
  (`retention-days: 90`). `out/BUILD.json` = `{data_sha, deploy_run_id, git_sha}` is part of it. It
  **dispatches nothing** and has `contents: read` only (no `actions: write`, no `pages: write`; it has no
  demo jobs any more, UI13-06).
- `docs.yml` (T0.4's `deploy` job, extended here) runs on **`workflow_run`** of a successful
  `deploy.yml` (N5.2): provenance check (the triggering run is this repo's `.github/workflows/deploy.yml`,
  `head_branch == main`, event `push`/`schedule`/`workflow_dispatch`, conclusion `success`; otherwise
  the job **fails without deploying** and writes the reason to the summary, UI13-09; the placeholder is
  deployed only when that run is valid but has no `dashboard-site`, pre-data bootstrap), then
  `actions/download-artifact` with
  `name: dashboard-site` and **`run-id: ${{ github.event.workflow_run.id }}`** (no dispatch input, no
  run-id search), `scripts/deploy/assemble_pages_site.sh` (T0.4; dashboard `out/` at the root, mkdocs
  `site/` built from `workflow_run.head_sha` under `docs/`, `.nojekyll`; fails if the dashboard export
  already has a `docs/` path; **fails when the assembled site is > 800 MB**, N5.1; writes
  **`build-id.txt`** = `<workflow_run.head_sha>-<workflow_run.id>`, R13 P5.5), then
  `actions/upload-pages-artifact` + `actions/deploy-pages` (environment `github-pages`; job-level
  concurrency group `pages`, N4.5; workflow-level group keyed by `github.event_name` + PR/ref, so a
  `push: main` build run never replaces a pending deploy or rollback run, UI13-07).
- This task adds job **`post-deploy-smoke`** to `docs.yml` (`needs: deploy`, same `if:`): the read-only
  Playwright smoke below. A failure fails the `docs.yml` run (and so marks that `dashboard-site` as not
  good) and the owner rolls back (below).
- The dashboard's own `out/404.html` is the site-root `404.html` (Pages serves it for every unknown path);
  its links go to `/pruefstand/de/`, `…/en/` and the docs home `/pruefstand/docs/` (ui-spec §4.8).

**Triggers of `deploy.yml`:** `push: main` (so docs-only and dashboard changes reach Pages through
`docs.yml`'s `workflow_run`), `workflow_dispatch` (optional input `data_sha`), and the daily cron
`47 6 * * *` (data refresh only). No `workflow_run` of `release.yml` any more: the release commit is on
`main`, so its `push: main` run already refreshes the site, and the demo-ready jobs live in
`demo-ready.yml` (UI13-06). Concurrency group `deploy-dashboard`, `cancel-in-progress: false`.

**Jobs:** `fetch-data` → `build-dashboard` (uploads `dashboard-site`). No secrets: the data repo is
public, Pages deploys with the OIDC token inside `docs.yml`.

**Dashboard data (W2.9):** the private executor's `baseline-promote.yml`/`nightly.yml` push a
sanitised export (`pruefstand baseline export-public` → `pruefstand export-dashboard`, layout
interfaces §10.1 / ui-spec §2.3, **size-capped**: newest 200 runs, case shards + `report.html` for the
newest 20, N5.1) with a `manifest.json` listing every file's SHA-256 to the **public** repo
`dheena18/pruefstand-dashboard-data` via `pruefstand baseline publish-dashboard` (T6.1, token from the
private-repo secret `DASHBOARD_DATA_PAT`, D145). **Pruning is T6.1's (R13 P5.1, UI13-01):**
`push_dashboard_data` clones the data repo, adds the new run's files, rebuilds `runs/index.json` from
**all** `runs/*/run.json` in the repo (not from the VM's run dirs), then rewrites the **whole** published
tree from that index: the newest 200 runs (`MAX_INDEX_RUNS`), `cases/<id>/` + `report.html` only for the
newest 20 (`MAX_CASE_RUNS`; both constants in `pruefstand.core.models.dashboard`, shared with T8.1's
export), a fresh `manifest.json`; everything else is deleted, so old data is pruned on every push.
`sanitise_run` reduces `run.json.infra_error` to its kind (UI13-13). This task only **verifies** the tree
(below) and never prunes in the build (UI13-20). `fetch-data`, pinned to a commit SHA of that repo (`inputs.data_sha` or the current
`main` head, resolved once and recorded in the job summary and in `BUILD.json`):
1. fetches the data repo at that SHA (public, no token);
2. `scripts/deploy/verify_dashboard_export.py`: every file hash against `manifest.json`; re-checks that
   no file (incl. `report.html`) contains `CANARY-` or chunk text; fails when the index has > 200 runs or
   more than 20 runs have `cases/` (N5.1);
3. hands the tree **as is** to `build-dashboard` (no pruning, no filtering; UI13-20), which builds with `DASHBOARD_DATA_DIR=<checkout>`,
   `NEXT_BASE_PATH=/pruefstand` and `NEXT_PUBLIC_DEMO_API_URL=${{ vars.DEMO_API_URL }}` (a repo
   **variable**, not a secret; empty → no Try-it link; UI12-19) (ui-spec §2.1, §2.4): `validate_data.mjs`,
   `next build`, `csp.mjs`, `check_csp.mjs`, then writes `BUILD.json` and prints `du -sb out`.

On any mismatch it stops, and nothing is uploaded.

**Hardening (ui-spec §7.4, Y7.1):** GitHub Pages sends no custom headers, so `frame-ancestors`,
`X-Content-Type-Options` and a CSP header cannot be set. The only policies are T8.1's per-page CSP
`<meta>` (hashes of Next's inline scripts, `style-src 'self'`, `connect-src 'self'` plus the demo API
origin **only** when `NEXT_PUBLIC_DEMO_API_URL` is set for the build), the referrer meta, and the
`report.html` meta that `render_html` writes. This task writes no header file, invents no policy, and
records the accepted risks in `docs/engineering/security.md`: no clickjacking header on a read-only
static site, and the **shared origin** `https://dheena18.github.io` (every Pages site of the owner is
"same origin" for `'self'` and is allowed by `DEMO_ALLOWED_ORIGIN`; UI12-19). Without the demo API the
"Try it" link is absent (ui-spec §2.2).

**Post-deploy UI smoke (ui-spec §14.3):** a read-only Playwright spec
`apps/dashboard/e2e/smoke.deployed.spec.ts`, run by `docs.yml` job `post-deploy-smoke` against
`BASE_URL=https://dheena18.github.io/pruefstand` with
`EXPECTED_BUILD_ID=<workflow_run.head_sha>-<workflow_run.id>`. **Step 0 (R13 P5.5, UI13-05):** poll
`${BASE_URL}/build-id.txt?nocache=<github.run_id>-<attempt>` every 15 s until its content equals
`EXPECTED_BUILD_ID` (timeout `BUILD_ID_TIMEOUT_S`, default 600; on timeout fail with "Pages still serves
an older build"); only then run the checks. **Every** page request of the smoke appends the
cache-busting query `?nocache=<github.run_id>` (the dashboard ignores unknown query keys; query-driven
pages default without them), so the CDN (`max-age=600`) cannot serve the previous build or a mix.
Checks: `/` redirects to `de/`; runs list renders in `de` and `en`; the first gated **case-published**
run's summary, its cases list and its `report.html` render (when the published index has **no** gated
case-published run, e.g. the first deploys or only `S-PARTIAL`/ungated runs among the newest 20: assert
the runs list or `L-EMPTY` instead and skip the run checks with a test annotation recorded in the job
summary, UI13-17); `de/licences/` renders; an unknown path returns the 404 page (status 404, `NotFoundView` text, docs
link `/pruefstand/docs/`); the docs home `/pruefstand/docs/` still returns 200; the footer attribution
is present on each; axe 0 serious/critical on each; no `securitypolicyviolation`, exactly one CSP
`<meta>` and no CSP response header per document; on success it writes `BUILD.json`'s `data_sha` and
`deploy_run_id` (fetched with the cache-busting query) and the matched build id to the job summary.
**Placeholder deploys** (`deploy` job output `placeholder=true`, UI13-09): the smoke polls
`build-id.txt`, then checks only `/` and `/docs/`.

**"Last good" and rollback (one rule, UI12-07; ui-spec §2.1):** the last good dashboard is the
`dashboard-site` of the `deploy.yml` run `workflow_run.id` of the newest `docs.yml` run (event
`workflow_run`) whose `post-deploy-smoke` concluded `success` (deterministic: the id is in that `docs.yml`
run's event payload, never re-read from a served `BUILD.json`; UI13-05); that artefact's `BUILD.json`
gives `data_sha` and `git_sha`. Rollback has **two cases** (runbook §9, UI13-08):
- **data-caused** (the code is fine, the newest data breaks the site): `gh workflow run deploy.yml -f
  data_sha=<last good data_sha>`; the new `deploy.yml` run reaches Pages through the normal
  `workflow_run` path;
- **code-caused** (a dashboard regression merged to `main` that passed the fixture matrix but fails on
  production data): a **revert PR** of the offending commit through the normal checks; its `push: main`
  run of `deploy.yml` redeploys. A `data_sha` rollback cannot undo this case, because it rebuilds
  today's `main` code. There is no "redeploy an old artefact" input (so no extra permission).
No workflow searches run ids, and no workflow dispatches another. There is no preview deploy (Pages has
none); PRs are covered by T8.3's `playwright` and `basepath-smoke` jobs.

**Demo-ready (public `.github/workflows/demo-ready.yml`, UI13-06; X2.8, ADR-0012, security.md D2):**
triggered by `workflow_run` of `release.yml` (`types: [completed]`); every job has
`if: github.event.workflow_run.conclusion == 'success' && github.event.workflow_run.event == 'push' && startsWith(github.event.workflow_run.head_branch, 'v')`,

- `release-demo-ready` (`needs: [fetch-artefacts, pre-deploy-leak-probes]`; no checkout, runs no
  repository code and no image; job-level `contents: write`, the guard's second allowlist entry for
  this workflow (T0.2 `check_workflows.py` lists `demo-ready.yml` / `release-demo-ready`, D318; `deploy.yml` has none), reason "uploads the `demo-ready.json` release asset"; used only for
  `gh release upload <tag> demo-ready.json -R dheena18/pruefstand`): uploads the release asset
  **`demo-ready.json`** = `{"tag": "<tag>", "digest": "sha256:…", "release_run_id": <workflow_run.id>}`

  run, never a dashboard refresh or the release itself (UI13-06).

**Nightly deploy + e2e (private executor; D244, N5.3):** `infra/gate-executor/workflows/demo-nightly.yml`
on the persistent runner (user `pruefstand`), cron for 06:15 Europe/Berlin (two UTC entries + local-time
guard, like the night window; it never runs inside 22:00–06:00), `workflow_dispatch` with input
`mode` (`deploy` default | `pin` | `unpin` | `disable` | `enable`) and optional input `tag` (UI13-11;
the input name of the ci-cd row):
- job **`demo-deploy`** (no token, no artefact download; R13 P5.3):
  1. **exactly one** anonymous REST call per night: `GET https://api.github.com/repos/dheena18/pruefstand/releases/latest`
     (with `inputs.tag`: `GET …/releases/tags/<tag>` instead, still one call); on 403/429 or a network
     error → exit 0 with a job-summary note, deployed digest unchanged (the 60/h anonymous limit can
     never starve the job, UI13-03). From the response it takes `tag_name` and the `browser_download_url`
     of the assets `demo-ready.json` and `image-digests.json` and downloads both through those URLs
     (`github.com/…/releases/download/…`, not the API). No `demo-ready.json` asset → "latest release is
     not demo-ready", exit 0, deployed digest unchanged. The digest is accepted only when
     `demo-ready.json.tag == tag_name` and its `digest` equals the rag-demo digest in
     `image-digests.json`;
  2. **pin** (UI13-11): if `/var/lib/pruefstand/demo/pin.json` `{digest, tag, until}` exists and `until`
     is in the future, that digest is used instead (logged). The file is written and removed only by
     this workflow's `mode: pin` / `mode: unpin` dispatch (pin = the previous digest from
     `deployed.json`'s history, `until` = now + 14 days), never by hand (CLAUDE.md §1 rule 8);
  3. exits 0 if the digest equals the deployed one (`/var/lib/pruefstand/demo/deployed.json`, written only
     by this job);
  4. runs the pinned `cosign verify` (release identity at that tag) on
     `ghcr.io/dheena18/rag-demo@<digest>` before any use; pulls **by digest** from the public GHCR
     package anonymously; swaps `rag-demo` in `pruefstand-demo`; (re)starts `cloudflared`; runs
     `infra/deploy/smoke.sh` against `https://demo.<domain>`; on failure restores the previous digest
     from `deployed.json`;
  5. no release yet (404) → exit 0 with a job-summary note, deployed digest unchanged. Nothing
     expires: the mark is a release asset, not an artefact.
- **kill switch** (UI13-11): dispatch `mode: disable` runs `docker compose -p pruefstand-demo exec
  rag-demo touch /run/demo/disabled` as `pruefstand` (the public API answers `demo_disabled` 503 at
  once, no restart); `mode: enable` removes the file. Changing `DEMO_ENABLED` needs a container restart
  and is not the kill switch.
- job **`demo-e2e`** (`needs: demo-deploy`, also when `demo-deploy` exited early; `timeout-minutes: 45`):
  checks out trusted `main` and runs T8.4's `scripts/demo/try_e2e.sh` (one e2e instance `rag-demo-e2e`
  with `TRUSTED_PROXY_HOPS=0` and `DEMO_TEST_RESET=1`, sequential, restarts between groups; before each
  test (row × combination) the script resets the limits **from inside the container**,
  `docker compose -p pruefstand-demo exec -T rag-demo-e2e curl -fsS -X POST http://localhost:8000/v1/_test/reset`,
  so the peer really is loopback (R13 P5.4); build and Playwright inside the pinned Playwright image, so
  `pruefstand` needs only Docker; UI12-12). It never touches the public `rag-demo`. Informational: a failure opens/updates one
  issue, it gates nothing.

If T8.4 is not done, none of the demo files, jobs or tunnel exist, `demo-ready.yml` does not exist,
and `vars.DEMO_API_URL` stays empty.
