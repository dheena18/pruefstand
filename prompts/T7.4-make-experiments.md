## Goal

`make experiments` reproduces every table and chart from scratch (given runs or with `FROM_SCRATCH=1`),
and nightly `mutmut` proves the gate and metrics tests kill code mutants.

## Context

Two modes: `make experiments` re-analyses from the committed aggregated inputs
`results/_inputs/<rq>/*.parquet` (CPU, minutes, no GPU, no private data: aggregated per-case values
only, < 1 MB each). `make experiments FROM_SCRATCH=1` re-runs on the executor (GPU, hours) and rewrites
those inputs. It follows the round-11 GPU rules (`docs/planning/reviews/round11-resolution.md` Y1.2, Y4.3; D212,
D223, AI11-13): bench dispatches go through the executor's lock `/var/lib/pruefstand/gpu.lock`, any direct GPU
command runs as `pruefstand-lock <cmd>`, nothing is started inside the night window 22:00–06:00 Europe/Berlin or
while `/var/lib/pruefstand/MAINTENANCE` exists, and the GPU-hour estimate and run calendar of T7.2/T7.3 are printed
before the first dispatch (`--dry-run` prints only the plan). Inputs from the `legal_hard` two-pass caches
(`results/_inputs/rq2/legal_hard_{answers,review}.parquet`, T5.3) are reused; `FROM_SCRATCH=1` never runs the
`datagen` pass itself (a manual weekend job). `results/MANIFEST.json` records, for each output file:
- the producing script, seed and input files;
- the input run ids with their `target_fingerprint` and `serving` block (model revisions, quantisation,
  engine versions, from `run.json`) and the `judge_serving` string (engine, version, quantisation, digest[:12],
  AI11-09); runs with `infra_error` or `judge_fallback=True` are never inputs (D224, D226);
- the git SHA and sha256.

That makes infra changes visible. A check compares regenerated
outputs to committed ones (CSV byte-equal; PNG compared via the CSV that produced them, not pixels).
Exception: the `label_set = faithfulness_memerag` rows of `results/rq2/calibration.csv` come from download-only data that is
not in `results/_inputs/` (T5.4); the hosted check regenerates and compares all other rows and keeps those rows as committed.
Code mutation testing (`mutmut`) on `pruefstand.gate` and `pruefstand.metrics` runs nightly as job `mutmut`
of the **public `ci.yml`** on its nightly schedule (`13 1 * * *`, extended jobs only; hosted runner, `timeout-minutes`
set), **never** in the private `nightly.yml` (round 9 R9-13: CPU-only work does not occupy the single A40 runner;
ci-cd.md §1.1/§1.2), informational until M7 (testing-strategy.md §3.11). Target mutation score ≥ 80 %. `experiments-check` is a job in `ci.yml` that always runs and
exits early with success when `experiments/`, `results/` and `packages/pruefstand/src/pruefstand/gate/`
are untouched, so it can be a required check.
Round 8/9 inputs the reproduction must cover (binding): T6.3's `mde.csv` with `sigma_d_noop` (no-op changes with
regeneration, X3.5; replay), `sigma_d_churn` (MDE sizing, AI9-09) and `sigma_d_repeat` (floor); T7.2's per-**tier**
(PR table, nightly table; X3.10) and per-**stratum** rows (`deterministic` / `statistical` / `normaliser`), both
replay arms and the tier-2 dose-response inputs; T5.4's per-stratum `calibration_table` rows with hard-negative
specificity + Wilson lower bound (X1.1; κ only on the `all` stratum), `calibration_status.yaml` with `judge_epoch`
(X3.3) and the `legal_hard` rows (T5.3, X3.1; inputs `results/_inputs/rq2/`); T7.3's `evidence_recall` rows
(X3.2) incl. the e5 ≤ 512-token sensitivity row. All committed inputs live under `results/**`, which the raw-data
guard allowlists (X1.3). Tests import experiment code in-process as `from <rq>.<mod> import …` (e.g.
`from rq3.score import …`; `experiments` is on the one root `pythonpath`, X4.2 / D129; no `sys.path` edits).
