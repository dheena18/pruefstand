## Goal

`pruefstand report --format html` writes a single self-contained `report.html`, and
`--format evidence` writes `evidence.json` — a release evidence record with everything needed to
re-run and audit a gate decision.

## Context

HTML: one file, inline CSS, no external requests (works as a CI artefact offline), no JS required for
content (small optional JS for table sorting). Sections: header (status, refs, cost, duration), metric
table with Δ and CI, slice table (sortable), hard fails with redacted evidence, top failing cases with
question/answer/chunks (escaped), run metadata. Autoescape on in Jinja2. Evidence record = Pydantic
`EvidenceRecord` (schema exported): schema_version, created_at, gate status, dataset name/version,
corpus_version, eval/target fingerprints, git SHAs, config hash, model ids, judge ids + prompt versions,
metric versions, thresholds used, per-metric results with CIs, security results (leaks, injection rate),
reviewer (optional), and SHA-256 hashes of both runs' `run.json` and the candidate's `gate.json` (the
baseline run has no `gate.json`). `build_evidence_record` only receives manifests, so it leaves the hash
field empty and `cli/report.py` fills it from the files (`record.model_copy(update=…)`). The same holds for
"thresholds used": neither `GateReport` nor `RunManifest` carries the policy, so `--format evidence` requires
`--config <pruefstand.yaml>` (new flag of `pruefstand report`; exit 2 if the loaded config's hash ≠
`RunManifest.config_hash` — compute it by calling the same function `pipeline/run.py` (T1.10) uses to fill
`config_hash`, never a separate hash of the file bytes) and the CLI fills `thresholds` from `cfg.gate`; flag the flag under "Interface changes". Wording: "supports
documentation for accuracy, robustness and record-keeping"; never "compliant".
Public vs private: the full HTML (with chunk text) stays in the private executor's artefacts. Any
HTML or evidence file published publicly is rendered from `sanitise_run(...)` output (T6.1); there is
no separate redaction code path in `report`. `render_html` also shows the MDE per gated metric and marks
non-gated slices as informational.

**Layout (ui-spec §13, binding):** header (status badge with icon + word — `⚪ NO BASELINE` when
`no_baseline`, X5.5 —, Tier 1|2 from `cand.stack`, blocking count, likely cause, ref labels (ui-spec
§2.2), splits (followed by `block <k>` when `cand.block` is set, UI13-19), cases, duration, cost, tokens = prompt + completion, GPU-s only for tier 2, created UTC);
banners for `complete == false`, `GateReport.no_baseline`, tier 1 (notice: hard fails and the error
rate decide; language, citation, refusal and injection are reported — X5.6), `judge_mode ==
"skipped"`, `judge_fallback`, `judge_degraded`, `judge_drift` (the D253 text of ui-spec §10.4.1:
"Judge drift detected (5 or more of 50 anchor verdicts changed); judged metrics are informational until
the flag clears.", UI13-10), and "supports documentation, not a compliance certificate"; in-page TOC; sections in §13 order. Every `SliceDecision` goes to exactly one
table (Gated / Informational / Notable) through T1.9's `report/tables.py` `assign_table` and is laid
out by `assign_block` (ui-spec §11.1, X5.4): tier 2 shows block G (7 columns, `overall`; all dimensions
in the slices section, insufficient rows greyed), A, I (all reasons), N; tier 1 shows the hard-fail row
+ block C (`error_rate`), block R (`tier1_deterministic_only`, `tier1_injection_reported` for
`injection_success`, `applicable_clusters<30`; X5.6, X3.11), then I and J. Judge truncation (X3.9):
the Informational section states `counts["judge_truncated"]` and lists the truncated case ids. δ / max from `SliceDecision.max_drop` / `max_value`; "Not applicable" from
`GateReport.not_applicable_counts`; `no_baseline` → no metric tables. Top failing cases capped at 20,
each card with question and answer (`lang` = the case's language), `citations` (`lang="de"`), chunk
list (private render: chunk text in `<details>` and "not used in prompt" when the chunk's
`used_in_prompt == false`, X3.14). Footer = `footer_line.en` and the sources list from
`report/templates/_licences.json` (package data; the same JSON the dashboard footer uses, ui-spec §4.7,
UI9-23 — `render_html` never reads `DATA_LICENSES.md`; this task ships a first copy by hand and T8.1's
`gen_licences.mjs` later generates it with a drift check). CSS: inline, built from
`report/templates/_tokens.css` (copy of ui-spec §7.1 values; T8.1 later generates this file from the
dashboard `tokens.css` and adds a drift check); `@media print`; `<caption>` and `scope` on every table;
sortable headers are `<button>`s with `aria-sort`; `<html lang="en">`. **CSP (ui-spec §7.4 item 2, Y7.1,
UI11-10):** GitHub Pages sends no headers, so `render_html` writes the report's own policy as the
first child of `<head>`: `<meta http-equiv="Content-Security-Policy" content="default-src 'none';
style-src 'unsafe-inline'; script-src 'sha256-<hash>'; img-src data:; base-uri 'none'; form-action
'none'">`, where `<hash>` is the base64 sha256 of the exact `_sort.js` bytes it inlines (computed at
render time, so every report carries the hash of its own script, whatever version rendered it). The
only `<script>` in the file is the content of `report/templates/_sort.js`, inlined byte for byte; no
`<link>`, no `src=`, no event-handler attributes, no external fonts or images.
**No baseline run (Y7.4, UI11-08, ui-spec §11.1):** `base` is `RunResults | None` (`None` iff
`no_baseline`, or the baseline run is not available, e.g. `export-dashboard` with the baseline outside
`--runs`). Then the header shows `Baseline: –` (or `baseline_run_id` in mono), Base/Δ come only from
`SliceDecision`, case cards have no baseline answer, and Run metadata shows `–` for the baseline
manifest. Judged section heading `{source}` = en `judge_source.<judge_mode>` (UI11-14), followed by "judged subset
(150 cases)" when `cand.judged_subset` (UI13-19). `render_html` is pure (no file writes): T8.1's `export-dashboard` calls it on
`sanitise_run` output to publish `runs/<id>/report.html` next to the dashboard data (W5.3, UI-06), so
the sanitised render must contain no chunk text and no `CANARY-`.
