## Goal

`pruefstand mcp` starts an MCP server (stdio; optional streamable HTTP on localhost) exposing three
tools so an AI agent can run the gate and read results.

## Context

New top-level module `pruefstand.mcp` sits at the `cli` layer (it orchestrates via `pipeline`, never
reaches into lower modules directly) — add it to the import-linter contract. Tools:
`run_eval(config_path: str, tier: "pr"|"nightly") -> {run_id, status_path}` (long-running: returns after
completion; progress notifications), `get_report(run_id: str, format: "md"|"json") -> str`,
`compare_runs(baseline_run_id: str, candidate_run_id: str, config_path: str) -> GateReport JSON` (`run_gate`
needs a `PruefstandConfig` for the gate policy; the config path follows the same workspace-root rule; the test
uses `examples/live/mini.yaml`). Safety: config paths must
be inside the workspace root (no path traversal), budget from config enforced, no secrets in outputs,
read-only for `get_report`/`compare_runs`. Use the official Python MCP SDK (pin version).
