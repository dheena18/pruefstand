## Goal

`generate_qa` samples chunks per tenant and category, asks the datagen model (role `DATAGEN`) for a
realistic German user question, a reference answer and the exact citation, and returns
`QACandidate`s with `prompt_version` — reproducible from seed + cached LLM responses.

## Context

- Prompt files (immutable once merged) in `dataset/prompts/`:
  `qa_factual_de_v1.txt`, `qa_multi_hop_de_v1.txt` (two chunks: two §§ of one law, or a § + a
  decision citing it via the citation graph), `qa_comparison_de_v1.txt`,
  `qa_cross_lingual_de_v1.txt` (DE chunk + EN parallel chunk (same `parallel_id`) → EN question with DE gold citation, and vice versa).
- Output JSON schema (validated with `complete_json`): `{"question": str, "answer": str,
  "citation": str | null, "evidence": str, "style": "laie" | "fachlich"}`. `evidence` = the answer-bearing sentence(s) of the cited Absatz, copied **verbatim** from the chunk (the no-copy rule below applies to question and answer only). Instruct ≥ 60 % layperson style
  ("Wann darf mein Chef mich rauswerfen?"), no copying of phrases ≥ 6 words from the chunk, no
  mention of "der Text"/"der Abschnitt". **Hard-negative-friendly references (round-8 W3.8/W3.11):** the reference answer is one or two sentences supported by **one Absatz** of the source chunk, states the concrete number, period, date or § the Absatz contains, and `citation` is at Absatz level when the § has Absätze. This lets T5.3 build same-paragraph wrong-span, number/date-swap, negation-flip and partially-correct hard negatives deterministically.
- **`evidence_span` (round 9 AI9-06, X3.2; interfaces §2 `TestCase.evidence_span`, pre-approved addition here):** `QACandidate.evidence_span: str | None` and `to_test_case` copies it. It is the model's `evidence` if, after whitespace and soft-hyphen normalisation, it is a substring of the source chunk's text, lies inside the cited Absatz (when the citation names one) and is ≤ 60 model tokens; otherwise `None` and `counts["evidence_invalid"]` is incremented (never repaired by hand). `evidence_recall` (T7.3, RQ1 primary metric) reads it; cases without it are `not_applicable` there.
- **When datagen runs (round 9 X3.12):** the 70B `llama` datagen model runs only as a **manual weekend job** in `datagen` mode (`make gpu-large-up` = `pruefstand-lock … switch-mode.sh datagen`, T3.1a), outside the 22:00–06:00 night window (D223); `scripts/generate_qa.py` refuses to start (exit 2, clear message) when the datagen endpoint is not up instead of starting it.
- **Two passes (R11 Y6.2, like T4.5 and T5.3):** pass 1 (`--pass generate`, datagen weekend) generates and caches candidates with the 70B model (no judge and no generator are served); pass 2 (`--pass validate`, day mode, after `make gpu-up`) runs every check that needs the PR judge or the day generator from the cache (no 70B call). `--pass both` only for cassette recording when both endpoints answer.
- **Serving (round 10 Z3, D198):** the datagen model is a `llama` 70B-class `Q4_K_M` **Ollama tag** (catalogue role `large`, pinned by digest in T3.1b), served in `datagen` mode by the cluster's one Ollama server (ADR-0018), split over both A40s by Ollama (all day models are unloaded, so **no judge and no generator are available** during the job). The script runs **on the VM** and calls it as `ollama/<tag>` (LiteLLM `ollama_chat`, native `/api/chat`, never `/v1`; R11 D219/D221) through the tunnel at `OLLAMA_GPU0_URL` (port 11434, the one server; in datagen mode only the llama model is resident, ADR-0018), with exactly the catalogue `options` of the `large` entry (`num_ctx` 8192 etc., D220) and no `keep_alive` (loading is `switch-mode.sh datagen`). **`MAINTENANCE` (R11 Y6.2, D230):** `switch-mode.sh datagen` creates `/var/lib/pruefstand/MAINTENANCE` itself (nobody touches the file by hand, CLAUDE.md §1.8; no `$PRUEFSTAND_HOME/MAINTENANCE`, no `--force`); while it exists only datagen is allowed and the orchestrator skips gated work; `make gpu-up` (day) removes it at the end of the weekend. `scripts/generate_qa.py` checks that the file exists and that `GET $OLLAMA_GPU0_URL/api/ps` shows the `large` tag, else exit 2 with the message "run make gpu-large-up first". Outputs are written on the VM disk, then copied once to `$PRUEFSTAND_DATA_ROOT/datasets/` if they must be shared (write-then-rename). `PRUEFSTAND_DATAGEN_URL` (cassette recording) is that same Ollama URL.
- Sampling: seeded `Generator`, stratified by tenant and source; skip chunks < 40 tokens and attack/private chunks (`is_attack`, `source="private"`).
- Unanswerable cases are NOT generated here (from GermanRAG + T4.6). Leak/injection cases: T4.6.
- Single-chunk categories (factual, comparison) use `generate_qa`; two-chunk categories (multi_hop,
  cross_lingual) use the pre-approved addition `generate_qa_pairs` (add to interfaces §14 in this PR).
- Candidates → `TestCase` conversion happens in T4.7a orchestration after filtering (T4.3); this task
  provides the `to_test_case(c, chunk, category, ...)` helper, which sets `cluster_id` = the source
  chunk's `doc_id` (first chunk for pairs; the DE doc for cross-lingual pairs) and `license_config`
  from the chunk (`laws_eurlex`; a law + decision pair → `oldp_derived`, since laws are § 5 UrhG
  public-domain works; any pair that would mix `germanquad_derived` with `oldp_derived` is dropped).
- Cost: log tokens/cost per call via `CallRecorder`; budget cap from config (`BudgetExceeded` stops cleanly, writing partial output).
