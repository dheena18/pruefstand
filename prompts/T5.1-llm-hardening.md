## Goal

The real LLM layer from T1.4 (`LiteLLMBackend` for llama.cpp, the A40 Ollama servers and GitHub Models; `Budget`;
`CallRecorder`; `PromptRegistry`; cassettes) becomes production-grade: A40 endpoints (Ollama via the VM tunnels), a disk cache,
tuned retries with a GitHub Models 429 fallback, robust JSON output, the **free-only provider
policy**, the **external-provider data guard**, request/token accounting, and the family lookup used
by the judge-family rule. There is no test-double backend anywhere.

## Context

- T1.4 already ships `LiteLLMBackend` (the only `litellm` importer, `pruefstand/llm/backends/litellm.py`),
  live tests against the llama.cpp container (`live` marker) and recorded real responses under
  `packages/pruefstand/tests/cassettes/llm/` (`make cassettes`). This task **extends** them.
- The cache key is defined only in `interfaces.md` (LLMClient cache); if T1.4's key differs,
  interfaces.md wins and you fix T1.4's code.
- **A40 serving is Ollama** (round 10 Z3): two servers on the cluster, reached only from the VM through the
  `autossh` tunnels: `OLLAMA_GPU0_URL` (generator, `bge-m3`) and `OLLAMA_GPU1_URL` (PR judge by day, gemma
  nightly judge at night). **One model id format (round 11 Y3.3)**: configs, `endpoints.yaml.model_id` and the
  catalogue `id` use **`ollama/<tag>`** (round 10 D209; local for the data guard); the bare `<tag>` (e.g.
  `qwen3.8:27b-q8_0`) appears only in Ollama API bodies, pinned by manifest digest in `models.yaml`. **Native API
  only (Y3.1)**: `LiteLLMBackend` translates `ollama/<tag>` to LiteLLM's `ollama_chat/<tag>` **inside
  `llm/backends/litellm.py` only** and calls `/api/chat` (and `/api/embed`) on the endpoint's base URL; it never
  uses `/v1/*` or `openai/<tag>` for an A40 endpoint, because Ollama ignores `options` there. **Catalogue options
  (Y3.2)**: every A40 request carries the per-model fixed `options` from `infra/gpu/models.yaml` (`num_ctx`,
  `num_predict`, `temperature`, `seed`, `top_p`; generator `num_ctx` 8192, both judges 12288 (D306; lower only if T3.1b's VRAM
  measurement failed)), exactly the values the preload in `switch-mode.sh` uses, so no request forces a reload; a caller's
  differing value is replaced by the catalogue value (logged at DEBUG). The judge input cap (X3.9) = `num_ctx − 1024`.
  `LLMClient` never sends `keep_alive` (mode switching is T3.1a's `switch-mode.sh`; `llm-proxy` strips it for the
  candidate, T6.2a).
- Providers (prefix → source): `ollama/…` (A40 Ollama endpoints from `infra/gpu/endpoints.yaml`, `base_url_env` → `OLLAMA_GPU0_URL` / `OLLAMA_GPU1_URL`; no `PRUEFSTAND_VLLM_*` or `VLLM_API_KEY`, Ollama has no API key),
  `openai_compatible_local/…` (llama.cpp server in CI and on laptops), `github/…` (GitHub Models free
  tier; in Actions authenticated by `GITHUB_TOKEN` with `permissions: models: read`, locally by
  `gh auth token`). Optional free tiers (Mistral "Experiment", Gemini free, Groq free, OpenRouter
  `:free`) are opt-in through `allowed_providers`. **No paid provider is enabled**; a paid provider
  would need `allow_paid: true`, which is off by default and not used by this project.
- `budget.max_usd_per_run = 0`. Budgets are enforced on **requests and tokens** per provider (free
  quotas), not only USD. GPU-seconds for `ollama` = latency × GPUs of the endpoint's server (`gpu0`/`gpu1` = 1, `all` = 2; an upper
  bound, documented as one).
- GitHub Models free quotas (requests/min, requests/day per model) are measured in T0.6 and written to
  `docs/engineering/ci-cd.md`; this task reads them from `llm/quotas.yaml`.
- **Cache key (round 8 W3.2, D113; interfaces §8)**: `stable_hash(model, model_version, prompt_id,
  prompt_version, rendered messages, temperature, max_tokens, seed, response_format)`. The rendered messages
  contain question, answer, every context chunk (chunk id + text hash) and reference, so all judge inputs are
  in the key. `model_version` is the provider-reported version, resolved once per run from the first
  uncached response (Ollama: tag + manifest digest from `GET /api/tags`, cross-checked with `models.yaml`; GitHub Models: the `model` field of the
  response; llama.cpp: GGUF file sha from `/props`), suffixed with the judge's **cache epoch** (`#e<N>`, S13) so
  a `judge_drift` invalidates every cached verdict of that judge. It is **never**
  "answer hash" alone: same answer + different context must miss.
- **Cache epoch ≠ `judge_epoch` (round 9 X3.3)**: the per-model *cache epoch* in `cache_epochs.json` is a cache-key
  suffix only. `eval_fingerprint` carries the judge **serving version** (engine + engine version + quantization + model digest[:12], round 11 AI11-09,
  static: `infra/gpu/models.yaml` / `/v1/info.serving`; GitHub Models: the pinned model id) and the integer
  **`judge_epoch`**, which only a successful re-calibration bumps (T5.4). Drift **never** changes the fingerprint: it
  bumps the cache epoch (cache invalidated) and marks judged metrics informational (`judge_drift`) until T5.4's
  re-calibration bumps `judge_epoch`. This task computes neither fingerprint field (T1.1/T5.4) and never feeds
  `model_version`, the cache epoch or a run-time flag into `eval_fingerprint`.
- **Tier-1 judging is informational and budgeted (W1.4, W1.6)**: at most 10 judge calls per PR run and 60 per
  nightly run (`budget.max_requests_per_run` for the `github/…` judge in `examples/live/pruefstand.yaml`),
  cached. When the GitHub Models quota is exhausted the remaining judged metrics are **skipped**
  (`RunManifest.judge_mode = "skipped"`), never handed to a CPU judge: the CPU fallback judge is removed from
  tier 1. An uncalibrated judge never decides a required check.
- **Family plan (W3.1)**: generator = `qwen`; PR judge (A40) = `mistral` (or `gemma` if mistral fails T5.4
  calibration); nightly judge (A40 GPU1, 27B-class `Q4_K_M`, Ollama) = `gemma` (D141, D205); datagen = `llama` 70B-class (≠ generator and ≠ every judge family);
  tier-1 informational judge = a GitHub Models model of a non-`qwen` family. Exact versions are pinned by
  T1.13/T3.1b; the plan lives in `core/data/model_families.yaml` (`plan:` block, T1.2) and `gpu-cluster.md`.
- **Qwen3 thinking off (W1.2)**: every request to a `qwen3*` model (generator, or any datagen/perturb call)
  sets thinking off for its engine: llama.cpp `chat_template_kwargs: {enable_thinking: false}` (`--jinja` + `/no_think`);
  Ollama `"think": false` on `/api/chat` (native API only, Y3.1; no `/no_think` marker path); a leading
  `<think>…</think>` block is stripped defensively by `strip_think(text) -> tuple[str, bool]` and counted by the
  pipeline in `RunManifest.counts["think_stripped"]` (round 9 D9-21; not a recorder column).

      `datagen: llama`, `judge_tier1: <non-qwen GitHub Models family>`; D141) and a loader check: every
      `role: generator` entry in `infra/gpu/models.yaml` has family `qwen`; no judge/datagen entry has family
      `qwen`; the tier-1 judge family ≠ `qwen`. Violations → `ConfigError`.
- [ ] S9 `CallRecorder.to_parquet` with the exact `llm_calls.parquet` columns, including **zero rows** (typed
      empty frame, not polars `Null` dtypes).

- [ ] S11 Re-record the affected cassettes with `make cassettes` (real calls) and commit them.
- [ ] S12 **Judge failure accounting (W3.9; one owner = the runner, round 9 D9-07)**: a judge call that ends in
      `LLMError` (after retries, timeout, `PolicyViolation`) is recorded with `error` and re-raised to the metric
      (T5.2b turns it into `status="error", value=None`, left out of that metric's pairing, never worst-filled). The
      **runner** (T1.8) counts it in `counts["judge_error"]` and sets `RunManifest.judge_degraded` (judged cases with
      ≥ 1 judge error ÷ `judged_cases` > 0.05). `pipeline/judge_mode.py` **only reads** the runner's counts and flag
      (no recomputation from recorder rows) and passes `informational={m: "judge_degraded"}` for every judged metric
      to `evaluate_gate`. Keys are exactly `counts["judge_error"]` and `counts["judge_skipped"]`; detail reasons
      `judge_quota` / `judge_cap`. `BudgetExceeded` is not a judge failure. The request cap uses `Budget.reserve()` /
      `release()` under an `asyncio.Lock` (round 9 X4.5, T1.4/T1.8): the runner reserves before each judge call; a
      refused reservation → reason `judge_cap`, so the cap never races into `BudgetExceeded`.
- [ ] S13 **Judge cache invalidation for drift (W3.3, D114, round 9 X3.3/X3.4)**: the anchor re-judge itself
      (50 anchors; drift = agreement < 0.85 **and** 95 % lower bound < 0.80) and `judges/drift.py anchor_agreement`
      are T5.4 (run by the nightly). Drift never touches `eval_fingerprint` or `judge_epoch`. This task provides the
      LLM-layer half:
      `llm/cache_epochs.py` `invalidate_judge(cache_dir: Path, model: str) -> int` bumps that model's epoch in
      `cache_epochs.json` (the epoch is part of `model_version` in the key, so every cached verdict of that
      judge misses afterwards) and `clear_drift(cache_dir, model)`; `pipeline/judge_mode.py` reads
      `judge_drift.json {model, agreement, epoch, ts}` (written by T5.4's nightly step) and sets
      `RunManifest.judge_drift = True` for a run whose judge is flagged, and the pipeline passes
      `informational={m: "judge_drift"}` for that judge's metrics.

## Interfaces (must match `interfaces.md` exactly)

Shared types live in `core`: `LLMRequest`, `LLMResponse`, `Message`, `LLMRole`, `PromptTemplate` in
`core.models.llm`; `LLMBackend`, `KVCache` in `core.protocols`; `ModelRef`, `BudgetConfig` in
`core.config`. `pruefstand.llm` only implements them.

```python
class LLMBackend(Protocol):
    async def acomplete(self, req: LLMRequest) -> LLMResponse: ...
class LLMClient:
    def __init__(self, backend: LLMBackend, cache: KVCache | None, budget: Budget, recorder: CallRecorder,
                 policy: LLMPolicy, *, fallback: LLMBackend | None = None) -> None
    async def complete(self, req: LLMRequest) -> LLMResponse
    async def complete_json(self, req: LLMRequest, schema: type[T]) -> T
class LiteLLMBackend(LLMBackend)
class Budget:  def __init__(self, max_usd: float | None, max_tokens: int | None, max_requests: int | None = None) -> None; def charge(self, r: LLMResponse) -> None
class CallRecorder: def record(self, req: LLMRequest, resp: LLMResponse | None, error: str | None) -> None; def to_parquet(self, path: Path) -> None
# already in interfaces.md (no interface change): build_backend is from T1.4 (extended here), family_of is implemented here
def build_backend(ref: ModelRef, *, policy: LLMPolicyConfig) -> LLMBackend
def family_of(model_id: str) -> str
# BudgetConfig.max_requests_per_run: int | None (interfaces §15)
# uses LLMPolicyConfig (interfaces §15): allowed_providers, allow_paid = False, fallback_judge
```

`llm_calls.parquet` columns (interfaces §3, 13 columns): `ts, role, model, provider, prompt_id, prompt_version, prompt_tokens,
completion_tokens, cost_usd, latency_ms, cached, fallback, error`.
