## Goal

A Linux dev environment **on the TrueNAS VM `pruefstand-exec`** (Ubuntu 24.04, reached from VS Code on
Windows through Remote-SSH, round 10 Z7) with every tool the prompts assume, an empty public GitHub repo,
and the approved planning pack as its first commit (LF line endings), so T0.1 can start in a real git repo.
WSL2 Ubuntu 24.04 on the laptop is an optional second environment with the same steps.

## Context

Every command in the prompts is POSIX (`make`, bash, `/tmp`). Your laptop runs Windows (10 22H2 or 11)
with VS Code; **all work happens on the VM `pruefstand-exec`** (Ubuntu 24.04 server, 64 GB RAM, created
in T0.7 S1) through the VS Code **Remote-SSH** extension (Z7). The VM is also the later executor host
(T0.7, T6.2a), so the repo checkout, Docker and Claude Code live there. The repo lives on the VM's local
disk (`~/code/pruefstand`), **never in the data root `/mnt/pruefstand`** (no git working trees there,
`gpu-cluster.md` §9). Claude Code is started from the VS Code Remote-SSH terminal in the repo root. The git
remote uses **HTTPS** with the GitHub CLI as credential helper, so no SSH key to GitHub is needed (the
VM→cluster SSH key is T0.7's job). Never paste tokens into a chat.

*Alternative (optional):* the same steps inside **WSL2 Ubuntu 24.04** on the laptop (S1-alt). Then the
repo lives in the Linux file system (`~/code/pruefstand`), **never under `/mnt/c`** (slow file watching,
wrong permissions, CRLF trouble). Tier-2 work from WSL needs a manual tunnel
(`ssh -N -L 11434:localhost:11434 cairo-s101lp`; one Ollama server, ADR-0018; `gpu-cluster.md` §6).

## Subtasks

Each step has a check. Run it before going on.

- [ ] S1 VM + Remote-SSH: the VM `pruefstand-exec` exists (T0.7 S1: TrueNAS UI, Ubuntu 24.04 server, 64 GB RAM,
  ≥ 8 vCPU, ≥ 200 GB disk, OpenSSH, your Windows public key in `~/.ssh/authorized_keys`). On Windows install
  VS Code + the "Remote - SSH" extension, add a `Host pruefstand-exec` entry to `%USERPROFILE%\.ssh\config`,
  "Connect to Host", open a terminal. All later steps run in that terminal.
  Check: `lsb_release -rs` → `24.04`; `hostname` → `pruefstand-exec`; `free -g` shows ≥ 60 GiB total.
  - S1-alt (optional, WSL): in an admin PowerShell `wsl --install -d Ubuntu-24.04`, reboot, open "Ubuntu 24.04",
    create your Linux user. Check: `lsb_release -rs` → `24.04`; `wsl.exe -l -v` shows `VERSION 2`.
- [ ] S2 Base packages: `sudo apt update && sudo apt install -y git make curl jq unzip build-essential graphviz shellcheck`.
  Check: `git --version` (≥ 2.43), `make --version`, `jq --version`.
- [ ] S3 git defaults:
  ```bash
  git config --global user.name "Your Name"
  git config --global user.email "you@example.com"
  git config --global init.defaultBranch main
  git config --global core.autocrlf input
  ```
  Check: `git config --global core.autocrlf` → `input`.
- [ ] S4 uv + Python 3.12:
  ```bash
  curl -LsSf https://astral.sh/uv/install.sh | sh
  source "$HOME/.local/bin/env"
  uv python install 3.12
  ```
  Check: `uv --version` (≥ 0.5); `uv python find 3.12` prints a path.
- [ ] S5 Node 22 LTS + pnpm via fnm + corepack:
  ```bash
  curl -fsSL https://fnm.vercel.app/install | bash
  echo 'eval "$(fnm env --use-on-cd --shell bash)"' >> ~/.bashrc
  exec bash -l
  fnm install 22 && fnm default 22
  export COREPACK_ENABLE_DOWNLOAD_PROMPT=0
  echo 'export COREPACK_ENABLE_DOWNLOAD_PROMPT=0' >> ~/.bashrc
  corepack enable && corepack prepare pnpm@9 --activate
  ```
  Check: `node -v` → `v22.*`; `pnpm -v` → `9.*`.
- [ ] S6 Docker Engine on the VM (docs.docker.com/engine/install/ubuntu, apt repo, Compose plugin; **rootful**, not
  rootless: round 11 Y1.3 / D213), then `sudo usermod -aG docker "$USER"`, log out and reconnect Remote-SSH.
  Group `docker` ends up with exactly two members, the owner and the service user `pruefstand` (added in T0.7);
  membership is root-equivalent on this dedicated VM (accepted, security.md).
  - S6-alt (WSL only): Docker Desktop with WSL integration for "Ubuntu-24.04", or Docker Engine inside WSL
    (then `wsl.exe --shutdown` from PowerShell and reopen after `usermod`).
  Check: `docker run --rm hello-world` works **without** sudo; `docker compose version` prints ≥ 2.20.
- [ ] S7 GitHub CLI (official apt repo, see cli.github.com) and login over HTTPS with a **fine-grained personal access
  token** (round 12 N4.4; never `--web`, which grants the classic `repo` + `workflow` scopes on every repo of the owner,
  including the private `pruefstand-gate`). Create the public repo `dheena18/pruefstand` first if it does not exist
  (GitHub web UI), then in the **Windows browser** create the token: resource owner `dheena18`, "Only select
  repositories" = `pruefstand` (the public repo only; never `pruefstand-gate` or `pruefstand-dashboard-data`),
  permissions **Contents: read and write**, **Pull requests: read and write**, **Workflows: read and write** (required:
  T0.2/T0.4/T0.5 and later tasks push `.github/workflows/**` files, D284), read-only Metadata, Actions, Commit statuses and Checks; **no** Administration,
  no other repo; expiry ≤ 90 days (note the date in the runbook). Then on the VM:
  ```bash
  gh auth login --hostname github.com --git-protocol https   # choose "Paste an authentication token"
  gh auth setup-git
  ```
  Admin actions (the tier-2 dispatch of `gate-executor.yml`, the ruleset bypass, branch protection, anything on the
  private repo) are done only from the owner's Windows browser or the GitHub mobile app, never with the VM token
  (security.md C18). Round 13 P1.3: with this token an agent can push branches, open PRs and push workflow files, but
  none of that can produce the required `pruefstand/gate` (pinned to the App `pruefstand-bot`) or start tier 2.
  Check: `gh auth status` shows "Logged in" and "Git operations protocol: https" and a `github_pat_…` token;
  `gh api repos/dheena18/pruefstand --jq .permissions.admin` → `false`; once the private repo exists (T6.2a),
  `gh api repos/dheena18/pruefstand-gate` → HTTP 404 from the VM.
