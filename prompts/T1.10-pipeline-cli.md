## Goal

The CLI works end to end:
- `pruefstand run` evaluates a target from a config and writes a run directory
- `pruefstand gate` compares two runs and writes `gate.json`
- `pruefstand report` renders and publishes
- `pruefstand power` gives the power/MDE estimate
- `validate` and `schema export` work

Every command uses the documented exit codes.

## Context

- **Datasets.** In v1 a dataset is a local directory `datasets/<name>/<version>/` (interfaces §1.3). `hf://…` raises `ConfigError("hf:// datasets arrive in T4.7b")`.
- **Real targets only** (ADR-0008). The only target type is `http`. Unit tests replay HTTP exchanges **recorded from the real rag-demo v0** by this task (`make cassettes-target`, S9; replayed via `respx`/vcrpy); the evidence runs below use the real rag-demo from compose profile `live`. Regressions come from rag-demo's real **bug switches** (`rag.yaml`: `tenant_filter: post_topk`, `prompt_file: prompts/answer_no_citations_de_v1.txt`, ...), never from a simulated target.
- **Fingerprints.** All fingerprints come from `pruefstand.core.fingerprint` (T1.1). Never compute them here.
- **Metric direction** goes to the pure gate as `directions=MetricRegistry.default().directions()`.
- **CLI layout.** The CLI is the package `pruefstand/cli/` from T0.1. Add one module per command and register each in `cli/__init__.py`.
- **Stub commands.** `ingest`, `build-dataset` and `baseline promote` exist but exit 2 with "not implemented yet (T2.5 / T4.7a / T6.1)". `--from-store` also exits 2 until T6.1.
- **Nightly block and judged subset (round 12 N1.2/N1.3, pre-approved interface change).** `TestCase.block`
  and `TestCase.judged_subset` are set by T4.1 (until then every case has `block=None`,
  `judged_subset=False`). `pruefstand run` gains `--split <name>` (repeatable; overrides `cfg.splits` via
  `cfg.model_copy`, the parsed result is what `config_hash` sees), `--block auto|0|1|2` and
  `--judged-subset`:
  - **`--stratum all|refusal|blocks`** (round 13 **P4.3**, owner this task; default `all`; allowed only when the
    selected splits are exactly `(full,)`, otherwise `ConfigError`, exit 2): `refusal` = only the refusal stratum
    (`full` cases with `block is None`; combining it with `--block` → `ConfigError`); `blocks` = only block cases
    (block *k* with `--block k`, all three blocks without); `all` = refusal stratum + block *k* with `--block k`, all
    of `full` without. The nightly uses `--stratum all --block auto`, the release run of all of `full` (D321) `--stratum all` without
    `--block`, T6.3 / T6.2b's refusal cause-switch `--stratum refusal`.
  - `--block k` keeps the `full` cases with `block == k` (plus the refusal stratum under `--stratum all`); it is
    allowed only when the selected splits are exactly `(full,)`, otherwise `ConfigError` (exit 2). **`auto`** (round
    13 **P4.4**, superseding the day-of-year rule and DEV13-05/AI13-10) = the integer in
    the file named by **`PRUEFSTAND_NIGHTLY_COUNTER`** (unset → **`$PRUEFSTAND_HOME/state/nightly_counter`**; one name,
    the variable only points to that file, D322) mod 3 (file missing → 0; unparsable → `ConfigError`, exit 2), read
    once at start. This task only reads the counter; the executor increments it after a completed nightly (T6.2a/T6.2b), so
    no block is repeated or skipped across year ends or late starts.
  - `--judged-subset` (PR runs; round 13 **P3.4**): the fixed 150-case subset limits **generation and judging** of the
    `core` answerable cases (factual, multi_hop, comparison, cross_lingual): answerable `core` cases outside the
    subset run retrieve-only (`CaseRecord.mode = "retrieve"`, retrieval metrics only, through `/v1/retrieve`; passed
    to `Runner.run(..., judged_subset=True)`, T1.8); every other case (smoke, `unanswerable`, `injection` and other
    deterministic security cases) is generated and scored in full, with judged metrics only on subset cases; allowed
    only when `core` is among the selected splits, otherwise `ConfigError`.
  - `run_eval(..., block: int | None = None, judged_subset: bool = False, stratum: Literal["all", "refusal",
    "blocks"] = "all")`; `block` here is the resolved integer (the CLI resolves `auto`). All three are written to
    `RunManifest.block` / `RunManifest.judged_subset` / `RunManifest.stratum` and passed to `eval_fingerprint(...,
    block=, judged_subset=, stratum=)` (T1.1), so a block-1 run never pairs with a block-0 baseline, a judged-subset
    run never pairs with an all-cases run, and a refusal-only run never pairs with a full run.
- **Mini fixture.** T1.11's full fixture set doesn't exist yet, so this task ships a tiny real one for its own evidence: `datasets/fixtures/mini_v0/` with 12 hand-written German factual cases whose gold docs are norms of the **real 5-law slice** indexed by T1.13 (doc ids from the T2.2 scheme, e.g. `gii-bgb-622`, `gii-kschg-1`, `gii-arbzg-3`; each case a different norm, so 12 clusters), plus 2 leak probes carrying the slice's `versicherung_nord` canary. `dataset_manifest.json` uses the slice's real `corpus_version` (from the T1.13 corpus manifest). Configs (gate `metrics` = deterministic metrics only, as in `examples/live/pruefstand.yaml`; a judged metric there makes `gate` fail with `GateInputError` until T5.2b): `examples/live/mini.yaml` (good rag-demo on :8000, **default `min_clusters` (30)**: round 9 X1.5/D9-03, committed configs under `examples/**` never lower it; T1.2's `test_committed_configs.py` checks this) and `examples/live/mini-bug-{tenant,citations}.yaml` (rag-demo bug instance on :8001). With 12 clusters every paired metric is therefore informational (`applicable_clusters<30`, D117); the mini fixture demonstrates hard fails and the reporting path, not a gated paired decision. A config that needs a lower `min_clusters` for a unit test lives in `packages/pruefstand/tests/fixtures/configs/` (X1.5).

## Subtasks

- [ ] S0 `core/models/dataset.py` with `DatasetManifest` and `ReviewRound` verbatim from interfaces §14 (needed now: `load_cases` reads `dataset_manifest.json` for the dataset name, version and `corpus_version`, and T1.11 writes a full manifest); register `dataset_manifest` in `export_schemas`. `QACandidate`/`FilterResult` follow in T4.2/T4.3.
- [ ] S1 `pipeline/datasets.py` `load_cases(dataset: str, splits) -> tuple[str, str, list[TestCase]]` returns name, version and cases; it validates every row, and errors name `file:line`.
- [ ] S2 `pipeline/run.py` `run_eval`, in this order:
  1. Load config and cases.
  2. Build the adapter with `build_adapter` (http only).
  3. **Precondition:** if `adapter.info()` reports a `corpus_version` that differs from the dataset's, abort before any query. Write a manifest with `complete=False`, `stop_reason="aborted"`, `counts["corpus_mismatch"]=1`, then raise `CorpusMismatch`; the CLI maps it to **exit 1**. If info is `None` (opaque target), continue with a warning.
  4. Filter `full` cases by `stratum` and `block` (P4.3); compute `target_fingerprint` and `eval_fingerprint` via `core.fingerprint` (with `block`, `judged_subset`, `stratum`).
  5. Call `Runner.run(..., judged_subset=judged_subset)`.
  6. Fill the manifest: git sha/ref from `GITHUB_SHA`/`GITHUB_REF` or `git rev-parse`, PR number from `GITHUB_EVENT_PATH` if present, config hash, metric versions, seed.
  7. Write it with `ArtifactStore.write_run(RunArtifacts(...))`.
- [ ] S3 `pipeline/gate.py` `run_gate(candidate, baseline, cfg)`: load both runs with `ArtifactStore.read_run(...).results`, call `evaluate_gate(..., rng=np.random.default_rng(cfg.seed), directions=MetricRegistry.default().directions())`, write `gate.json` into the candidate dir.
- [ ] S4 `pipeline/judge_mode.py` (round-8 W1.4/W3.9; interfaces §2): `judge_mode ∈ {github, local, skipped}` (no `cpu`). `PRUEFSTAND_JUDGE_MODE=skipped` (set by the workflow for fork PRs, or when no `PRUEFSTAND_GH_MODELS_TOKEN` is present in tier 1) forces `skipped`: judged metrics are not run. Otherwise the mode follows the stack: `stack=live` → `github` (GitHub Models, informational), `stack=a40` → `local`; it is downgraded to `skipped` after the run if no judged value was produced (always the case until T5.2b; also when the GitHub quota ran out before the first judgment). Records `judge_mode`, `judged_cases`, `judge_degraded` (from the runner, T1.8 S3c), `stack` (`PRUEFSTAND_STACK`, default `live`) and `workload` (= `--tier`). `judge_fallback` stays `False` here (tier 2, T5.1). There is no CPU judge in any tier.
- [ ] S4b `pipeline/gate.py` builds the `informational` mapping for `evaluate_gate` (interfaces §9). First match wins, in this order: (1) `stack == "live"` (round 9 X5.6, D9-11b): every judged metric → `"tier1_judged"`, `injection_success` → `"tier1_injection_reported"` (X3.11: n = 2 injection cases, reported not gating), **every other paired metric** (each metric with `max_drop`) → `"tier1_deterministic_only"`, whatever the cluster count (also the 40-case nightly tier-1 run), so a tier-1 run decides on hard fails and the `error_rate` absolute check only; (2) `judge_degraded` in either run → `"judge_degraded"`; `judge_drift` → `"judge_drift"`; a judged metric with > 5 % of its applicable candidate cases truncated → `"judge_truncated"` (round 9 X3.9; T5.2b computes the share); (3) **`refusal_correct` only** unless `workload == "nightly"` and the split is `full` → `"refusal_outside_nightly_full"`; `false_refusal` is gated in PR runs like any answerable metric (round 9 X3.7, AI9-05). A metric in the mapping keeps the pipeline's reason; `evaluate_gate`'s own `applicable_clusters<30` rule applies only to metrics not in the mapping (T1.7 5a). `pipeline/run.py` passes `eval_fingerprint(judge_models=…, judge_serving=…, judge_epoch=…)` only the judges of **gated** judged metrics (round 9 X3.3: `judge_serving` = engine + version + quantization of each gated judge from its serving info; `judge_epoch` read from `judges/data/calibration_status.yaml`, 0 while that file does not exist, T5.4), so tier 1 passes `{}`, `{}` and the epoch; both values are written to `run.json`.
- [ ] S5 CLI modules `cli/{run,gate,report,validate,schema,power,stubs}.py`, registered in `cli/__init__.py`.
  - Global options: `--log-json/--no-log-json`, `--verbose`.
  - Exit codes: 0 pass/warn (1 on warn with `--fail-on-warn`); 1 gate FAIL or `CorpusMismatch`; 2 usage, config or not-implemented; 3 runtime error (any other `PruefstandError`, message to stderr, no traceback unless `--verbose`).
- [ ] S6 `report` command: `--format md|json` now (`html|evidence` exit 2 until T6.4). `--publish-pr N` uses `GitHubPublisher` with `PruefstandSettings.github_token` and `GITHUB_REPOSITORY`.
- [ ] S7 `power` command: `pruefstand power --sigma 0.25 --n 300 --delta 0.03 [--alpha 0.025] [--m 1] [--true-drop X]` prints `power=<p> mde=<x>` from `gate.stats` (D56).
- [ ] S8 `make schemas` now runs `pruefstand schema export --out schemas/`. That target is defined in T0.1 and becomes functional once the command exists; do not redefine it.
- [ ] S9 The mini fixture (`datasets/fixtures/mini_v0/`) and the configs. `scripts/live/two_targets.sh <bug>` starts two rag-demo instances from compose profile `live`: `good` on :8000 (`apps/rag-demo/configs/rag.yaml`) and `bug` on :8001 with `RAG_CONFIG=apps/rag-demo/configs/bugs/<bug>.yaml` (bug configs come from T1.13). `make cassettes-target` (append to `mk/live.mk`, created by T1.13) records cassettes of both for the unit tests; add a section to `scripts/models/record_cassettes.sh` (T1.4) that runs it, so the weekly `make cassettes` (CLAUDE.md §6) re-records them.
