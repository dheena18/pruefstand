## Goal

A reusable, hardened Python Dockerfile template; a `docker-compose.yml` whose `core` profile starts a
healthy Qdrant; and a `build-images.yml` workflow that lints, builds and scans images on every PR.

## Context

- The rag-demo image (T1.13, extended in T3.2) and the Action image (T1.12) are built later from this template.
- The **tier-2 stack is not defined here.** GPU serving is **Ollama on the cluster** (one server for both GPUs, ADR-0018, reused or started detached with `setsid nohup`, no Docker there; round 10 Z1/Z3, D228), reached from the VM through the `autossh` tunnel (T0.7); there are **no vLLM or TEI GPU services** in any compose file. The VM-side compose profile `gpu` (T3.1a: `rerank-cpu` from `infra/gpu/compose.gpu.yml` + `qdrant` with VM storage) and the trusted `llm-proxy` (T6.2a, executor only) are added by those tasks, together with `infra/gpu/models.yaml` and `infra/gpu/endpoints.yaml` (single source: `docs/engineering/gpu-cluster.md`). Leave the `qdrant` service easy to extend with `profiles: [core, live, gpu]` (T3.1a adds `gpu` in its own hunk).
- This task ships the `core` profile (Qdrant), the **`live` profile** (the real CPU stack used by tier-1 CI and local live tests: Qdrant, a real llama.cpp generator server, rag-demo placeholder; T1.13 adds the CPU embedding server). There is **no CPU judge service**: tier-1 judged metrics are informational, run only through GitHub Models, and are skipped when it is unavailable (round-8 W1.4) and the `dev` profile. Every service is real (ADR-0008).
- Pushing and signing images by SHA (D62) is added to `build-images.yml` by T6.2b. Here, nothing is pushed.
- **Two stacks on one VM (round 11 Y1.4, D214).** The executor stack (user `pruefstand`, `compose.executor.yml`, T6.2a) uses the **default** host ports. The owner/agent **dev** stack uses compose profile `dev` with `PORT_OFFSET=10000` in the owner's `.env` (Qdrant 16333/16334, rerank 18201, rag-demo 18000; full table in docker.md §3). Compose has no arithmetic, so every published port in `docker-compose.yml` is a variable with the default as fallback (`127.0.0.1:${QDRANT_HTTP_PORT:-6333}:6333`, `${QDRANT_GRPC_PORT:-6334}`, `${LLM_HOST_PORT:-8080}`, `${EMBED_HOST_PORT:-8090}`, `${RAG_DEMO_HOST_PORT:-8000}`; T3.1a uses `${RERANK_HOST_PORT:-18201}`), and `mk/docker.mk` exports each one as default + `PORT_OFFSET` (`PORT_OFFSET` unset or `0` → defaults, used by CI and laptops). Done-when checks against services use the dev ports or `docker compose exec`, never the executor's `localhost` ports (Y6.5).
- Executor state on the VM (`$PRUEFSTAND_HOME=/home/pruefstand/pruefstand` of the system user `pruefstand`: state, run dirs, Qdrant storage, runner; the GPU lock and `MAINTENANCE` are in `/var/lib/pruefstand/`, D211/D212) and the data root (`$PRUEFSTAND_DATA_ROOT=/mnt/pruefstand`, VM disk: baselines, backups, datasets) belong to T0.7/T3.1a/T6.2a (D145, `gpu-cluster.md` §8–§9, runbook `docs/ops/runbook.md`); this task's compose profiles never reference them, and this task adds them to neither section of `.env.example` (the VM section is T0.7's).

To smoke-test the template, build it with `PKG=pruefstand` and `ENTRYPOINT pruefstand` as image
`pruefstand-smoke`; that is the image Trivy scans now. `.env.example`, `.gitignore` and `docker-compose.yml`
are shared files: later tasks only append their own blocks.

## Subtasks

- [ ] S1 `infra/docker/python-uv.Dockerfile` template:
  - stage `builder`: pinned `ghcr.io/astral-sh/uv` + `python:3.12-slim@sha256:…`; runs `uv sync --frozen --no-dev --package ${PKG}` into `/app/.venv`
  - stage `runtime`: copies the venv only; `USER 10001`; `HEALTHCHECK` command from a build-arg (default `NONE`, with a comment); `ENTRYPOINT` from a build-arg; OCI labels `org.opencontainers.image.{source,revision,licenses}`
- [ ] S2 `docker-compose.yml`, three profiles:
  - `core`: `qdrant`, image pinned by digest, volume `qdrant_data`, healthcheck on `/readyz`, ports bound to `127.0.0.1` only, published as `127.0.0.1:${QDRANT_HTTP_PORT:-6333}:6333` and `127.0.0.1:${QDRANT_GRPC_PORT:-6334}:6334` (Y1.4)
  - `live` (CPU only, used by `live-e2e.yml` and `pytest -m live`):
    - `qdrant` (same service, `profiles: [core, live]`)
    - `llm`: llama.cpp server image `ghcr.io/ggml-org/llama.cpp:server` pinned by digest, CPU build; command `--model /models/${LIVE_LLM_GGUF} --host 0.0.0.0 --port 8080 --ctx-size 4096 --threads ${LIVE_LLM_THREADS:-4} --parallel 1 --seed 0 --jinja`; (`--parallel 1`: greedy outputs must not depend on batch composition, AI-36; `--jinja` so the chat template honours `enable_thinking=false` for Qwen3, W1.2, **verify** flag name against the pinned build) read-only volume `${LIVE_MODEL_DIR:-${HOME}/.cache/pruefstand/models}:/models:ro`; port `127.0.0.1:${LLM_HOST_PORT:-8080}:8080`; healthcheck `curl -fsS http://localhost:8080/health` (inside the container, so it never depends on the host port)
    - `rag-demo`: placeholder block commented out until T1.13 adds the Dockerfile (then `depends_on` qdrant + llm healthy, port `127.0.0.1:${RAG_DEMO_HOST_PORT:-8000}:8000`)
    - Model files are **not** downloaded by compose; `scripts/models/fetch.py` (T1.4) fills the cache with SHA-256 checks. `LIVE_LLM_GGUF` defaults to the pinned files from `infra/models/*.yaml` (T1.4 test model now; T1.13 pins the slice generator).
  - `dev`: `rag-demo` built from source with reload (build context `apps/rag-demo`, `profiles: [dev]`, commented out until T1.13 adds the Dockerfile); used together with `core`/`live`/`gpu`. On the VM the owner's `.env` sets `PORT_OFFSET=10000` and `COMPOSE_PROJECT_NAME=pruefstand-dev`, so the dev stack never shares host ports, container names or volumes with the executor stack (Y1.4).
- [ ] S3 `.env.example`: every variable the compose file uses, one documented line each, no real values (the file already exists with sections LOCAL / VM / CLUSTER; append only to LOCAL and add any new name to `docs/ops/secrets.md`; this includes `PORT_OFFSET` ("0 on laptops/CI, 10000 for the owner's dev stack on the VM") and `COMPOSE_PROJECT_NAME`; the per-service `*_HOST_PORT` variables are derived by `mk/docker.mk`, documented in one comment line, not set by hand). Also add `.dockerignore` and `.hadolint.yaml` (failure threshold `warning`).
- [ ] S4 `.github/workflows/build-images.yml` (as in ci-cd.md §1). Triggers: `pull_request` and `push: main`, **no path filters**; the jobs exit early with a message when no Dockerfile or compose file changed and it is not `main`. Top-level `permissions: {}`, SHA-pinned actions. **Every `actions/checkout` step uses `ref: ${{ github.event.pull_request.head.sha || github.sha }}`** (round 9 X2.4: images are built from the PR head SHA, never the `refs/pull/N/merge` commit, so the image label `org.opencontainers.image.revision` = the head SHA the executor later verifies; T0.2's guard asserts this expression). Jobs:
  - `hadolint`: all Dockerfiles
  - `build-image`: buildx, the `pruefstand-smoke` image, gha layer cache, no push
  - `trivy`: `HIGH,CRITICAL`, `--ignore-unfixed`, SARIF upload with `security-events: write` on this job only
  - `compose-config`: `docker compose --profile core --profile live --profile dev config -q`
  - `compose-lint`: S5
  - `images-gate`: the **aggregator** (required check `images-gate`, T0.2 pattern): `needs:` all jobs above, `if: always()`, fails unless all succeeded. Workflow `name: build-images`.
- [ ] S5 `scripts/check_compose.py` parses any compose YAML (root file and, later, `infra/**/compose*.yml`). It fails if:
  - an image is not pinned by digest (a service with `build:` and no `image:` is exempt; its base images are pinned in the Dockerfile and checked by hadolint);
  - a port binds all interfaces (no explicit `127.0.0.1:`);
  - a published host port is a literal instead of a `${<NAME>_PORT:-<default>}` variable (Y1.4; no exemption: the dev `llm-proxy` publishes `127.0.0.1:${LLM_PROXY_PORT:-11500}:11500`, D242);
  - a service has no `healthcheck`;
  - an env value looks like a secret: a `(?i)(key|token|secret|password)` name with a literal, non-`${…}` value.
- [ ] S6 `mk/docker.mk` with targets `up` (default `PROFILES=core`; variables `PROFILES="core live dev"`, `SERVICES="…"`, `COMPOSE_FILES="…"` (extra `-f` files, e.g. `infra/gpu/compose.gpu.yml infra/gpu/compose.rag-demo.yml`) and `WAIT=1` (adds `--wait`); round 13 DEV13-08: every Done-when line in the prompts starts stacks through `make up …`, never raw `docker compose … up`), **`stack-run CMD="…"`** (A13-M8: one stack session = one lock hold, `flock ~/pruefstand/stack.lock sh -c 'make up …; <CMD>; make down'`, so another agent's `up` cannot replace this agent's containers between its `up` and its checks), `down`, `logs`, `compose-lint` (S5), `image-smoke` (build `pruefstand-smoke`), `ports` (prints the effective host ports). It reads `PORT_OFFSET` (default 0, from the environment or `.env`) and exports `QDRANT_HTTP_PORT=$$((6333+PORT_OFFSET))`, `QDRANT_GRPC_PORT` (6334), `LLM_HOST_PORT` (8080), `EMBED_HOST_PORT` (8090), `RAG_DEMO_HOST_PORT` (8000), `RERANK_HOST_PORT` (8201 + offset = 18201) and `LLM_PROXY_PORT` (11500 + offset = 21500) for every compose call (one table in the file; docker.md §3 is the source). Round 12 A12-M4 (ci-cd/docker.md): Compose cannot add the offset itself, so a raw `docker compose --profile core up` would bind the default ports. Two more targets: **`make ports-env`** writes the effective per-service ports literally into `.env` (one managed block between `# >>> ports (make ports-env)` / `# <<< ports` markers, idempotent, other lines untouched), so plain `docker compose` uses them; **`make check-ports`** warns (exit 1 with `--strict`) when a container of project `pruefstand-dev` publishes a default port (6333, 6334, 8000, 8080, 8090, 8201, 11500).
